# 观测（Observation）

[返回阅读树](../../HUMAN.md) · [系统目标与基本约定](../../HUMAN.md#基本约定)

## 含义

**观测**是通过某种获取方式取得的一份信息。

温度计读数、应用报告的登录状态、来源给出的估算结果，都可以成为观测。获取方式说明这些信息怎样取得。

观测保留取得的信息，包括理解这些信息所需的已知说明。各项信息的含义、相互关联及已知局限一并保留。如果信息未知，保留未知。

例如，“房间气温为 23 °C，温度计 T 在 10:00 测得”。这份信息说明温度、单位、所描述的实体、测量工具与测量时间。

数值 `23` 可以表示温度 23 °C，也可以表示相对湿度 23%。理解结果需要知道数值描述的量及单位含义。

## 观测身份（ObservationIdentity）

**观测身份**用于区分不同观测，并认出同一份观测的重复出现。

观测也是实体。程序中，观测身份使用该观测的 `EntityId`，不另行分配第二个标识。

**例：相同结果。** 同一来源在一秒内进行两次测量，可能取得相同结果。如果时间只记录到秒，两份观测的来源、实体、内容、获取方式和时间可以相同。

一份测量结果被收录两遍，也会重复出现这些信息。两次测量产生两份观测；重复收录同一份结果，仍只有一份观测。重复收录时，观测身份保持一致。

## 参与实体及其角色

观测通过实体身份关联已识别的参与实体。[角色](roles.md)说明各实体在这份观测中的作用。

例如，采集器 C 给出应用 A 的运行状态。C 与 A 都参与这份观测，C 提供信息，A 是信息描述的实体。

来源提供的名称、标识和描述作为原始观测信息保留。[实体发现](../derivation/entity-discovery.md)根据这些信息及其他观测依据，建立实体指认。依据不足时，所指实体保持未知。

实体指认可以随新证据修正。原始观测信息保持不变。

## 获取方式（AcquisitionMethod）

**获取方式**说明一份观测中的信息怎样取得。

保留已知的获取方式及其局限。方式未知时，保留未知。

读取、测量、估算等可以作为获取方式的描述。

**例：来源与方式。** 同一个采集器给出气温信息，可以来自温度计读数，也可以来自历史数据估算。来源相同，获取方式不同，提供的依据也不同。

## 描述时间与获取时间

**描述时间（DescribedTime）**是信息描述的时刻或区间。

**获取时间（AcquisitionTime）**是来源取得信息的时间。

**例：两种时间。** 采集器在 10:00 读取一份描述 9:00 气温的报告。描述时间为 9:00，获取时间为 10:00。如果报告描述 9:00–9:30 的温度变化，描述时间为这个区间。

如果描述时间未知，保留未知。不得用获取时间替代未知的描述时间。

## 程序表示

观测实现 [`IEntity` 与 `ITimed`](../program/README.md)。`Id` 使用 `EntityId`；可空的 `StartAt` 与 `EndAt` 分别表示描述时间的已知开始边界和结束边界。

状态信息由具体观测内容或过程实体表达。时间边界是否已知不能代替状态。当前程序草案不为每份 Observation 声明通用状态字段。

## 信息表达示例

观测可以表达状态、事件、实体间关系等信息。例如，应用正在运行、应用启动、账号已登录应用。一份观测可以同时表达这些信息。

### 实体间关系（EntityRelationship）

观测可以表达实体之间的关系。观测说明参与实体、实体角色及关系对应的时间。

关系说明实体之间有什么关联。角色说明各实体在该关系中起什么作用。

**例：登录关系。** 如果已取得账号标识和登录信息，观测可以表达“账号 B 登录在应用 A 中”。A 指电脑上的具体应用。A 承担登录应用角色，B 承担登录账号角色。

后续取得账号 C 登录的观测，本身不足以证明 B 已退出。判断 B 已退出仍需观测依据。

## 操作约定

### 观测更正（ObservationCorrection 暂不实现）

观测更正保留原观测，并将新的更正信息及依据关联原观测。稳定的观测身份支持对原观测的引用。

未来可据此加入更正操作，无需改变基础概念。当前不增加占位字段、接口或组件。
