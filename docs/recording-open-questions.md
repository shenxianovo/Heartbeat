# 记录模型未决设计

状态：待讨论。本文只登记尚未确认的问题，不记录已接受决策。

## Collector 持久上传队列

当前最小 macOS Collector 使用进程内内存缓冲。采样与上传已经独立；上传失败会保留内存中的待上传 Record 并重试；旧回执只确认发送时的快照。

待确认问题：

- 队列是否是所有可靠 Collector 的统一要求，还是按 Collector 能力声明。
- 本地持久格式、位置、加密和清理策略。
- 成功回执如何只确认已发送快照，避免清除发送后产生的新进度。
- 进程退出、崩溃、长期离线和批量部分失败后的恢复语义。
- 是否需要限制离线期间不同 Record 的积压数量，以及达到限制后的处理方式。

约束：

- 不新增后端表。
- 不改变 `Timeline -> Collector -> Track -> Record` 四层模型。
- 不用持久队列提前引入设备表、安装身份或分轨字段。

## 断采与采样空白

当前 macOS Collector 在无法读取可靠前台应用时断开连续性。进程暂停、系统休眠和采样调度延迟造成的空白尚未识别，可能被接入旧区间。

待确认问题：

- 是否根据采样间隔设置断采阈值。
- 阈值是否按固定倍数、配置值或平台事件决定。
- 系统休眠、App Nap、进程暂停、CPU 忙导致的延迟是否统一处理。
- 恢复后如果前台应用相同，是否必须创建新 Record。
- 断采判断是否只属于 Collector 本地逻辑，不进入 Record 存储字段。

约束：

- 不修改已存 Record 来表示空白。
- 不把未知状态写成 `application: null`。
- 不凭计时器推断状态持续，只有实际观测才能延长区间。

## TTL 与实时状态

ADR-0002 已确认 TTL 只用于判断是否缺少及时确认，不修改 `ended_at`，不阻止后续补传。

待确认问题：

- TTL 配置放在 Collector、协议注册还是读取侧。
- TTL 是否只影响实时展示，不影响历史重放查询。
- 迟到补传到达后，实时状态和历史区间如何各自解释。

## `range + next_record`

当前没有实际协议使用 `range + next_record`，Track 级重放查询也不计算派生结束时间。

待确认问题：

- 哪类协议适合使用下一条 Record 推导结束时间。
- 乱序、迟到和断采时如何确定后继。
- 动态结束时间是在读取 adapter 中计算，还是由更高层重放用例计算。

## 历史纠错与删除

普通 Record 创建后不可修改；持续状态只允许延长已确认区间。历史纠错和删除尚未设计。

待确认问题：

- 删除后如何防止旧重传恢复已删除 Record。
- 是否需要修正链或单独的纠错记录。
- 纠错是否按 Track、Record ID 或更高层语义组织。

## 设备关联

ADR-0003 已确认 Device Identity 跨系统重装保留，重装后允许用户手动选择已有设备。该决定尚未实现。

待确认问题：

- 设备身份的存储位置。
- 桌面 Collector 与浏览器 Collector 如何共享和恢复协议中的设备标识。
- Target、协议 `device_id` 与未来 Device Identity 的关系。
- 错误关联如何修正。

约束：

- 当前不新增设备表。
- 当前不把 Target 解释为安装身份。
- 设备身份延续不表示观测连续。
