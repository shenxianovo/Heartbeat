# ADR-0008：窗口标题要站稳才承认

## 状态：已接受

## 日期：2026-09-16

## 背景

[ADR-0007](ADR-0007-foreground-window-is-its-own-observation.md) 把前台窗口拆成独立的观测对象之后，同一个应用的碎块问题解决了，但窗口 Track 自己带来一类新的碎块：有些窗口的标题本身在动。终端里的 spinner、下载进度、滚动字幕，还有浏览器导航时「地址先出现、页面标题随后覆盖」的中间态——只要标题字符串变了就切 Record，这些都会各自成为一条不到一秒的 Record，而它们不表达任何观测对象的变化。

先考虑过按文本相似度判等（编辑距离小于阈值就算同一个标题），否掉了：

- 距离小不等于语义相同。`Report.txt` 与 `Repost.txt` 距离 2 却是两个文件；滚动字幕的两帧距离很大却是同一个标题。判据和要判的东西不是一回事。
- 相似不可传递。A≈B、B≈C 而 A 与 C 相差很远，于是一条 Record 的观测值会顺着比较链慢慢漂移，这和「Range Record 的值固定、只延长区间」（[ADR-0002](ADR-0002-monotonic-record-extension.md)）直接冲突。
- 它把「读数是否变化」这件确定的事，换成一个要调参、且每个应用都不一样的模糊判断。

于是改用变化的**时间形态**：真实的标题变更之后标题会停下来，噪声不会。参数不能靠猜，所以先量。

## 决策

窗口标题的变化要先站稳 `window-title-dwell`（默认 **1.5 秒**）才承认为新的观测值：

- **站不住的候选被前一个区间吸收**，不产生 Record，也不留空洞。
- **承认时区间从候选第一次出现的那一刻算起**，不是从承认那一刻算起。静置只推迟写入，不改区间。
- **应用切换那一刻的标题立即承认**，不等静置——那是另一个窗口，没有可等的余地。
- **中断发生时（标题读不到、Away Signal、能力失败）当前候选若已站够时间就补记成 Record**，不把一段真实存在过的标题连同中断一起丢掉；确认间隔已经超限时不补记，因为那段时间根本没有观测。
- 前台应用 Track 完全不受影响：静置只作用于窗口标题。

参数可配（`--window-title-dwell-ms` / `HEARTBEAT_COLLECTOR_WINDOW_TITLE_DWELL_MS`）。设为 0 等于关掉静置，每次标题变化都承认。

## 1.5 秒是怎么来的

宿主机当时没给探针 Accessibility 权限，于是退一步用本机数据库里已经攒下的读数（约 46.6 小时、3462 条前台应用 Record，标题那时还在应用 Record 的 value 里）。这份数据答不了「原生通知有没有漏送」——它是投影之后的结果，也分不清通知与轮询；但它足够回答参数问题：

- **抖动高度集中**：1221 次同应用标题变化里，Chrome 666 次、终端 441 次，两个应用占 91%。
- **噪声和真实变更在时间上分得开**：终端 spinner 帧共 255 次，停留时长 p10 0.95 / p50 0.96 / p90 0.97 / **最长 1.05 秒**，窄得像时钟；其余变化 p10 0.00 / p50 0.84 / p90 9.26 / 最长 387 秒。
- **亚秒连续段是循环，不是信息**：相邻间隔都不到 1.05 秒的连续段共 257 段，吃掉 714 次变化（58%）；最长一段 37.56 秒里 42 个读数只有 3 个不同标题。

阈值必须高过实测最慢的那一帧（1.05 秒）才压得住 spinner，又要远低于真实变更那条长尾，所以取 1.5 秒。按这份数据模拟：4370 个观测值收成 3620 条 Record，压掉 704 次变化，标题累计陈旧 464 秒，占总时长 0.28%。

模拟报告里「最长陈旧 20.48 秒」不是代价：陈旧统计把 spinner 每一帧都当成不同的值，那 20 秒其实是 spinner 连烧期间一直显示首帧，而这些帧本来就是同一个标题。

## 代价

- **最新的标题最晚要等一个采样间隔才写出来**。承认发生在候选之后的第一条读数上，默认采样间隔 5 秒。区间时间是对的，只有写入被推迟；重放页面上表现为「刚切的标题过几秒才出现」。
- **被吸收的中间态会让前一个区间多出最多 1.5 秒**，那段时间窗口实际显示的是别的标题。按实测占总时长 0.28%。
- **一个数值对所有应用生效**。终端 spinner 与 Chrome 导航恰好都在这个阈值以下，但这是本机两天量出来的形态，换一台机器、换一批应用可能需要重新量。应用特定的归一化（按规则改写标题）留作后手，本 ADR 不采用。
- **中断之后的第一个标题立即承认**，所以每次能力失败或标题不可读之后，都可能记下一个恰好正在抖动的标题。代价是偶尔一条噪声 Record，换来的是不在恢复处留 1.5 秒的空洞。
- 参数来自数据库读数，不是探针读数。探针拿到 Accessibility 权限后应当复核，尤其是「通知漏送」这一路。
