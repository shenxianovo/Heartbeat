# ADR-0010：Web 性能基准归前端脚本

## 状态：已接受

## 日期：2026-09-18

## 背景

活动泳道拖动基准需要在浏览器中运行，并在开发构建与生产构建之间比较。原有 `heartbeat-dev` 的 `verify`、`quality` 和 `scenario` 会保存统一的验证证据，但没有适合性能读数的稳定阈值。把基准放进 `quality` 会把机器和构建环境带来的波动当成代码腐化；新增顶层 CLI 命令则会扩大工具职责。

## 决策

Web 前端的 `test:perf` 脚本拥有活动泳道基准的运行与报告。报告保存在前端 `.artifacts/perf/`，每次运行打印路径。验证指引要求性能变更运行生产模式基准，并报告读数与限制。`heartbeat-dev quality` 继续约束结构质量；性能报告不进入 CLI manifest，也不设置通过阈值。

## 后果

- 开发者可直接从 Web 工作区测量同一浏览器场景，并保留每轮报告。
- CLI 的验证证据与性能报告位于两个目录；任务报告需要分别引用。
- 基准退出码只表示测量过程成功，不表示性能达标。跨机器读数需要结合环境解释。
