# ADR-0024：收发曲线由 Hub 的短期时间桶驱动

状态：已接受。日期：2026-09-26。

用户确认用最近 60 秒的收发曲线表达真实活动。Hub 是事件时间与数量的权威：SQLite 接管事务提交后计入 received，开始 Record HTTP 上传时计入 sent，核对成功回执并应用本地结果后计入 confirmed。计数单位是 Record 快照，重试和续期可重复；发送不表示成功，确认可晚于发送落在另一秒。

Hub 在固定大小内存环中按秒聚合，提供本次运行 epoch、Unix 毫秒 capturedAt 和最多 60 个连续秒桶。当前秒持续更新，已知无事件的秒为零，运行前与快照之后未知，不填零。Hub 时钟回拨时钳制到最后观测时间，保证已有桶不倒序。窗口过期与进程重启不影响持久交付队列。采用事件时间而非页面轮询差值，避免网络抖动产生虚假的流量尖峰。

Desktop 直接读取；Web 消费 API 的 Owner/管理会话隔离内存副本，独立一秒上报与一秒轮询。API 四秒未收到活动即不返回该 Hub，不写数据库、不刷新 Hub 在线时间。恢复时用 Hub 当前窗口重建曲线，超过窗口的数据不补存。活动通道故障不阻塞接管、上传或管理；可靠交付继续遵守 ADR-0009。

Web 用已有 uPlot，原生平台用自身绘图 API；三端显示接收、发送、确认三条曲线。横轴滚动 60 秒，纵轴是每秒快照数，缺少数据留空；减少动态时每秒更新、不连续滚动。历史持久化、消息代理和事件重放队列不在本功能范围内。
