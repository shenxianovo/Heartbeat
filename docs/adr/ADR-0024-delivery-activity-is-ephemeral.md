# ADR-0024：收发图由 Hub 的临时累计计数驱动

状态：已接受。日期：2026-09-26。

用户确认只看 Hub 接受和成功交付的数量，界面显示相邻更新之间的增量。此前按秒保留活动窗口的设计扩大了需求；本次改为两个本次进程运行的累计计数，不建设投递历史或批次跟踪。

Hub 是计数权威。SQLite 接管事务提交后增加 accepted；核对后端成功回执并应用本地结果后增加 delivered。计数对象是处理的 Record 快照，同一 ID 的续期或再次提交可以再次计数；发送失败和未能核对的回执不增加 delivered。它们不是独立 Record 数量，也不能相减推导队列大小，队列数量仍读取 SQLite。

Hub 只保留运行 epoch、采样时间 capturedAt 和两个累计计数。通过现有独立活动通道每秒上报，API 只保留当前 Owner/活跃管理会话的最新值，不保存历史、不写 PostgreSQL、不刷新 Hub 在线时间。同 epoch 的时间与计数不可倒退。活动通道故障不影响 Record 接管与交付。

Web 和原生视图各自在内存中保留显示点，以相邻快照差值画「已接受 / 已上传」两条数量曲线。第一份快照只建立基线，不把打开界面之前的累计工作量画成峰值。重复或旧快照不产生新的显示点；断连后重新建立基线并保留缺口，epoch 改变则清空显示点。页面刷新后重新开始。不换算速率、不做滑动平均、不记录逐批对应关系。

图形只是当前观察期间的数量展示，不承诺恢复离开页面或断连期间的投递历史。历史 Record 回放仍使用现有记录链路。Web 用 uPlot，原生平台用自身绘图 API；平滑滚动与曲线连接不改变计数。
