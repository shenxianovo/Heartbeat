# ADR-0023：质量分类统一，收口组合现有检查

## 状态：已接受

## 日期：2026-09-24

用户确认改进质量检查口径、补充明确的漏错检查并减少收口漏跑。jscpd 原先把整个 `src/` 当成生产代码，与 LOC 和复杂度对前端测试的分类不同。

源码角色由 Developer CLI 的 `SourceCorpus` 统一定义，LOC、复杂度和重复检测共同使用。重复扫描按角色选择基线与工作树的路径并集，使删除或重命名文件后仍能识别已有重复；生成代码及其他角色不进入生产/测试重复闸门。保留既有阈值和 C#、TypeScript 生产函数合计预算。

`verify closeout --base REF` 负责组合变更验证和结构质量检查，先把基点解析为同一提交，再直接调用现有实现。各检查继续生成自己的日志和报告，共享一次证据会话，由收口报告汇总结果。普通检查失败继续执行下一项，取消或执行异常立即停止。场景验收和前端性能基准仍按相关变更另行选择，遵循 ADR-0010、ADR-0013 和 ADR-0018。

具体命令、分类边界和失败语义见[工程验证](../verification.md)。

2026-09-26：用户要求把死码检查纳入现有质检。`quality` 使用 Knip 的前端入口分析和同次 C# 构建的 Roslyn IDE0051 诊断，按固定 Git 基点比较，阻止新增诊断并报告存量；扫描失败不能视为通过。报告只表达静态可达性，业务用途仍由人工确认，不根据诊断自动删代码。
