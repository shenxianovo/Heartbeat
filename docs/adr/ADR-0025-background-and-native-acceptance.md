# ADR-0025：后台业务回归与原生 UI 验收分开

状态：已接受。日期：2026-09-26。

用户确认日常回归不能反复激活 Desktop、填写配置或抢占工作桌面。`runtime-replay` 默认在后台运行正常回放及离线崩溃恢复；`desktop-replay --foreground` 保留本地打包、首次使用和真实原生采集，只有显式选择时才占用桌面。这细化 ADR-0013 的按行为组合验收，不改变 ADR-0017 的宿主职责。

两个入口共用接管、恢复、Record 对账和生产 Web 回放步骤。原生会话由 UI 驱动；后台会话在独立 CLI 子进程中组合真实 `DesktopRuntime`、Collector 投影、Hub、Auth、API 与 PostgreSQL，仅 OS 观测源和临时凭据适配受控。控制走父子进程标准输入/输出，不给产品增加测试 HTTP 接口。端口仍由隔离环境自动分配，经生产配置方法传入；后台不启动原生窗口或系统采集，不接受交互式登录选项。

恢复必须强杀独立子进程，并在重启时只传临时 profile 和连接位置，不再次传入 API key；验证真实配置重读、Hub 身份、已接管 Record 的完整内容和最终回放。临时凭据不进入产物，失败及取消清理子进程/profile，隔离 Compose 遵循现有清理约定。

后台通过只证明受控观测之后的业务链路，不能替代原生配置界面、系统前台/键鼠采集、权限、Keychain 或打包验收。操作真实桌面的场景按改动单独安排；要与人的日常工作完全隔离，应使用专门的 macOS 桌面环境。
