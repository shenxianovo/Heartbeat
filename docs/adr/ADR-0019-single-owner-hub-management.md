# ADR-0019：单 Owner Hub 的管理范围与状态分离

## 状态：已接受

## 日期：2026-09-20；2026-09-21 收简

## 背景

服务器采集需要在 Desktop 离线时继续运行，并通过 Web 配置和启停；前端还需展示各处 Hub 的连接情况。设计访谈确认采用每个 Hub 只服务一个 Owner 的边界，避免在同一 Hub 内引入跨 Owner 的配置、凭据与队列隔离。

将“在线”用作整体健康结论会隐藏故障：Hub 可以正常联系后端，同时某个 Collector 因第三方认证失效而停止采集；没有新 Record 也可能只是没有新的观测结果。

## 决策

- 每个 Hub 只属于一个 Owner，可以承接该 Owner 的多个 Collector。API 可以服务多个 Owner；前端按 Owner 展示其 Hub。
- Web 提供服务器 Collector 的配置与启停操作，Desktop 的远程管理一起设计。仅通过服务器本地配置并在 Web 查看状态，不满足本次产品目标。
- Hub 身份随持久数据目录保存。重启或保留数据卷的容器重建沿用身份，全新安装创建新身份；旧 Hub 可以保持离线并由用户退役。迁移数据目录保留身份，但不允许新旧副本同时作为同一 Hub 运行；同目录用进程锁防止重复启动；API 拒绝在线身份的另一会话覆盖状态。
- Web 从目标 Hub 已安装的 Collector 类型中选择并配置；增加新类型通过更新程序或部署完成，本轮不建设动态插件安装与升级。
- 每个服务器 Collector 当前由使用者保证只配置在一处；API 不保存执行位置绑定，不阻止不同 Hub 配置相同 Collector。迁移由使用者先停止旧采集再配置新节点，不做自动接管或分布式排他。退役只阻止 Hub 管理重连，不停止远端进程。
- 分别展示 Hub 在线状态、Collector 运行状态和 Record 交付状态。Hub 在线只表达后端近期收到该 Hub 的有效联络，不以是否产生 Record 判断在线。
- 保留 ADR-0014 的数据流：Desktop 和服务器上的 Hub 各自向后端交付 Record，不通过另一处 Hub 转发。

## 后果

- 同一 Owner 可以拥有多个 Hub；不同 Owner 使用不同的 Hub。
- Web 需要分别表达联络、采集与交付的情况，不能用一个在线标记代表三者均正常。
- 沿用 ADR-0016 的约束：先完成具体功能，不引入严格、复杂的通用生命周期框架，不在通用层写死具名 Collector 的采集协议。管理能力不应要求 Hub 或 API 解释某类 Record 的内容。
- 服务器应用在同一进程组合通用 Hub 和编译时安装的 Collector。具体应用入口引用 VRChat，Hub、API 不引用具名可选 Collector；以后需要隔离时可使用既有 HTTP 接管边界，不预建进程调度框架。
- 用户随后明确接受最小方案：配置与凭据以执行 Hub 本地为权威，API 只持久化 Hub 登记和离线展示需要的最近状态（Collector 标识/名称/运行状态/错误、交付积压/失败）。已安装类型表单和公开配置仅来自在线 Hub，短暂保存在 API 内存，不写入数据库；API 不保存登录凭据或操作队列。
- Web 在线操作经 API 转交 Hub，执行后应答。离线不接收修改，API 重启不补放，超时表示结果未知，需刷新实际状态。当前管理中继面向单 API 实例；多副本路由不在本轮建设。
- Desktop 本地与远程启停复用同一运行对象和串行操作入口。暂停采集不暂停 Hub 交付；Desktop 重新打开自动开始，沿用现有客户端行为。服务器则保存启停选择并在下次启动恢复。
- 服务器第三方会话用本地受限权限密钥加密保存；用户名、密码与验证码不写入公开配置、报告或 Record。加密不隔离同一 OS 账号。Desktop API key 继续保存在系统凭据库。

- 每个 Hub 自己指定一个持久数据目录，由共享 `HubLocalStorage` 统一管理身份、配置文档、队列路径和本地加密会话。服务器使用 `Hub:DataDirectory`，Desktop 使用客户端的数据目录；不同 Hub 的目录彼此独立。运行模块不再自行拼接身份/配置文件路径或实现文件读写。
- 这是组件本地存储入口，不是配置中心，不增加 Auth 之外的集中配置基础设施。服务器启动连接参数仍通过已有环境配置传入；Desktop 的系统凭据库边界不变。

接口和故障边界见 [Hub 管理契约](../hub-management.md)，运行入口见 [服务器 README](../../src/Server/README.md)。本决策不承诺网络分区下严格执行唯一性，不引入租约选主、配置同步或自动接管。
