# ADR-0026：VRChat 服务器事件观测与可见同场

## 状态：已接受

## 日期：2026-09-27

用户确认先实现服务器 Hub 能提供的事件采集；PC/Quest 本地日志及跨来源去重互补暂缓。

## 决策

VRChat Collector 在服务器内持有会话并订阅 Pipeline，处理自己的位置和好友的可见位置/在线状态。连接后及每五分钟通过 REST 核对自己与在线好友的快照，避免依赖只有变化才到达的事件。事件接收与快照读取并行，快照请求期间收到的账号事件优先，旧快照不能覆盖新事件。REST 请求串行节流，429 尊重 Retry-After；连接故障指数退避并加入抖动。资料缓存不改变观测身份。

Collector 规范化并形成 `vrchat.location` 和 `vrchat.encounter` 的显式 Range Record，Hub 只负责持久接管与交付，后端只保存通用 Record。位置身份是完整的世界和实例；好友只有在双方可见位置完全相同时才计入 encounter。private、traveling、offline 和未知位置均不提供同场依据。只保留同场结果，不持久记录好友在其他实例的行踪。

时间是服务器接收/读取响应的观测时间，不是 VRChat 保证的真实发生时间。事件边界用于结束上一个可见状态，定期快照确认其持续；断开、核对失败或超过连续性窗口后重新开始，不用连接存活推断游戏位置。此规则延续 ADR-0002 的显式区间和空白处理，不引入任意值更新。API 可见同场属于有限的服务读数，不证明现实互动或完整同场名单；Web 必须明确这个限制。

Web 在独立 VRChat 视图中从上述 Record 计算世界气泡、访问明细、可见同场及活动热力图，不把协议解释放入通用后端，也不改变通用时间轴的绘制责任。不累加多个 Collector 对同一账号的重叠来源，首版按单个 Collector 查看。

## 后果

事件改善进出响应速度；核对和资料查询仍可能 429。启动时已存在的状态从首次看到时计时，隐藏位置、断线和服务缺失不会被日志自动补齐。原始日志与 API 的去重、互补、冲突和权威来源独立跟踪，尚未决定。

真实事件和字段覆盖只通过用户在 PCVR/Quest 的人工 E2E 验收。构建检查和现有基础回归不证明 VRChat 现场行为，不增加模拟事件单元测试作为真实性证据。
