# ADR-0011：Web 时间轴统一绘制，协议注册表提供展示内容

## 状态：已接受

## 日期：2026-09-18

## 背景

一个 Collector 可以产生多条不同协议的 Track。随着协议增加，如果每个协议自行实现时间轴布局、拖动和命中，交互与性能成本会重复出现。已有 Web 按 Track 时间模式绘制区间和点密度，但协议摘要与缓存散落在注册表和时间轴包装层。

## 决策

Web 时间轴负责视窗、拖动、裁剪、重叠布局、Range 区间条、Point 密度、命中和选择。连续指针移动只在浏览器下一帧提交最新范围，结束拖动时提交最后位置。展示模式由 Track 的 `timeMode` 选择；协议展示代码不负责时间几何。

前端注册表以 Track 的 `(type, version)` 选择协议展示声明。声明只解释该协议的 `value`，返回标签、可选分组身份、颜色语气和 hover 文案；需要专用详情时才提供详情组件。没有声明或值不合法时使用通用标签与安全 JSON 详情。注册表缓存同一 Record 的描述，避免拖动时重复解析。Collector 不发送可执行界面代码，也不决定 Web 的布局算法。

通用时间模式先保留现有 Range 区间条与 Point 密度。出现确实不适合这两种模式的协议后，再根据实际展示需求增加模式；不预设每个 Collector 专属的绘制接口。

## 后果

- 新 Track 使用现有模式时即有时间位置与安全详情；专用内容只需增加前端协议展示声明。
- 展示声明按协议类型注册，而不是按 Collector 实现注册；同一 Collector 的不同 Track 可使用不同展示。
- 运行时安装 Collector 后无需发布前端就能获得通用展示；新的专用 hover 或详情仍需发布前端代码。若未来要求动态下发声明，需要另行决定其协议与信任边界。
- 绘制介质可在通用时间轴内部演进，不影响协议展示声明。
