# Engineering Friction

Agent 在任何开发任务结束前执行一次 **friction closeout**，检查本次实际触达的路径是否暴露了
以下具体问题：

- 文档、issue 状态或验收勾选与当前实现不一致；
- 启动、测试或排障依赖隐含步骤，现有入口无法给出可判定的成功/失败；
- 新实现继续依赖已退役模型、兼容 adapter 或迁移分支，但没有移除条件；
- 同一契约、配置或领域事实存在多个可漂移的权威来源；
- 人工 smoke、发布门禁或跨平台验证无人承接，导致“代码完成”被误报为“需求完成”。

## 处理方式

1. 会影响当前任务正确性的 friction：发现时立即向用户说明证据和影响，并在当前范围内修复或
   明确阻塞条件。
2. 与当前任务紧邻、低风险的陈旧文档或 issue 状态：随实现一起修正。
3. 具体但超出范围的问题：在最终答复中给出证据、影响和下一步；如果用户要求持续跟踪，按
   `issue-tracker.md` 建 issue，并先搜索 `.scratch/` 避免重复。
4. 兼容债务必须写出兼容对象、仍服务的版本/数据、移除门槛和验证方式；只有“legacy”注释而
   没有退出条件，不算已记录。
5. 仓库明确声明的外部 skill、插件或 context pointer 不因当前会话未暴露对应能力而失效；保留
   入口，只有在其权威来源明确退役后才更新或删除。

完成标准：Agent 能明确区分“实现完成”“自动验证完成”“人工验收完成”，并同步所触达 issue
的状态与勾选项。没有发现具体 friction 时无需制造或报告假设性问题。
