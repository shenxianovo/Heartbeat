# 收口检查

每次结束前只检查本次涉及的路径：

| 检查 | 通过条件 |
| --- | --- |
| 兼容分支 | 重写期原则上不新增；确有需要时写清服务对象、删除条件和验收责任 |
| 契约权威 | 同一事实只有一处权威；其他副本由共享定义或失败测试对账 |
| 易腐快照 | 不固化测试数、行数和耗时；验收快照必须带日期、命令和证据路径 |
| 完成状态 | 区分代码完成、自动验证和人工验收；实测声明必须有证据 |
| 通用层边界 | 后端与 Hub 不认识具名的可选 Collector |
| ADR | 组件责任、协议语义或数据权威的决策已有 ADR |

## 发现了怎么办

- 影响本次正确性：说明证据和影响，在范围内修复或明确阻塞。
- 紧邻且低风险：随本次修改一起修复。
- 明确但超范围：收尾时给出证据和下一步；需要跟踪时先搜索 `.scratch/`，再按 [本地 issue](issue-tracker.md) 建立记录。
