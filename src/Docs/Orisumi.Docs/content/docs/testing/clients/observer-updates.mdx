export const caseId = 'observer-updates';

## 为什么验证 [#why]

更新不能让用户丢掉正在进行的采集，也不能换掉程序实例的身份。约定见 [Overview · 更新](../../clients/index.mdx#updates) 和 [Packages · 更新](../../clients/packages.mdx#update)。

## 前置条件 [#setup]

Runtime 使用独立的数据目录，已安装一个测试包的 `0.1.0`，官方目录提供 `0.2.0`。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 下载 `0.2.0` 时失败 | `0.1.0` 的进程一直在运行，登记仍是 `0.1.0` |
| 更新到 `0.2.0` | 准备完成后旧进程收到 `stop`，新进程的 `init` 带着原来的 EntityId 和设置 |
| 停用后更新 | 登记切换到 `0.2.0`，Observer 保持停用 |
| `0.2.0` 启动后不回复 `ready` | 按[重启](../../clients/runtime.mdx#restart)失败后报告故障，登记仍是 `0.2.0`，不切回 `0.1.0` |
| 切换登记之前结束 Runtime，再启动 | 运行的是 `0.1.0`，`0.2.0` 的目录没有被启动 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`，对应本页的预期范围：

- 停用状态下更新：身份、设置和停用状态保持，登记切换到新版本：`RuntimeHostingTests.PreparedUpdateKeepsIdentitySettingsAndDisabledIntent`。
- 未覆盖：下载失败时旧版本继续运行；运行中更新的停止与启动；新版本不回复 `ready`；切换登记前退出。
