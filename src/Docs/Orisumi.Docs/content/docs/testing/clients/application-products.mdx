## 为什么验证 [#why]

Web 控制台按[归属](../../observers/application-identity/index.mdx#membership)把各设备上的本机应用合并为应用产品。线索来自线索归属，判错时用户删除线索归属。约定见 [Web · 应用](../../clients/web.mdx#applications)。

## 前置条件 [#setup]

纯函数用构造的版本运行。页面测试用路由拦截在内存中模拟后端的读取。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 两个本机应用的线索属于同一个产品 | 名称和时长按一个产品显示，时长是两者之和 |
| 本机应用的线索没有线索归属 | 按本机应用单独显示为未归属 |
| 产品没有线索归属 | 应用页不列出它 |
| 线索归属指向的产品已删除 | 线索未归属 |
| 线索归属引用产品的旧版本 | 按实体归到这个产品 |
| 打开产品的面板 | 判断记录一条线索归属一行 |
| 点一条线索 | 打开它的线索归属 |
| 没有本机应用 | 显示空状态 |

## 测试实现 [#implementation]

- 按产品合并、时长相加、彼此之间不算切换：`src/lib/day.test.ts` 的 `groupThings`。
- 线索匹配、产品的线索、未归属和只有本机线索的安装：`src/lib/applications.test.ts` 的“归属”。
- 应用页、判断记录和空状态：`tests/e2e/applications.spec.ts`，后端由路由拦截在内存中模拟。

这些是 Vitest 和 Playwright 的测试，结果不进入 TUnit 报告。
