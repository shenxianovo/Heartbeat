export const caseId = 'storage-transactions';

## 为什么验证 [#why]

版本与派生引用需要在同一个事务里保存。一次提交被拒绝后，查询不能读到这次提交的任何版本或引用。约定见 [Storage · 事务](../../storage/index.mdx#transactions)。

## 前置条件 [#setup]

使用独立的测试数据库，API 由 WebApplicationFactory 启动。并发用例在同一个数据库上创建两个服务实例。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 一次提交形成目标和引用，后面的版本被拒绝 | 整次回滚，没有留下引用；改正后重新提交，只出现这次保存的引用 |
| 两个服务同时提交同一个实体的首版，VersionId 不同 | 只有一个保存，另一个因 `VERSION-6` 被拒绝 |
| 删除过程中注入失败 | 权威表、投影和管理登记一起回滚 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`：

- 拒绝后的引用回滚与改正后保存：`ReferrerApiTests.RejectedSubmissionLeavesNoReferencesAndTheCorrectedOneSavesItsOwn`。
- 并发首版冲突：`EntityApiTests.ConcurrentFirstVersionsFromTwoServicesConflict`。

未覆盖：删除过程中注入失败；拒绝后逐一检查所有投影表。
