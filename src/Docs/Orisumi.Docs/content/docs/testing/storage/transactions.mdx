export const caseId = 'storage-transactions';

## 为什么验证 [#why]

一次请求使用一个事务，每次写入使用保存点。约定见 [写入](../../api/writing.mdx#requests) 和 [存储事务](../../storage/index.mdx#transactions)。

## 前置条件 [#setup]

HTTP 用例经真实 API 和独立的 PostgreSQL 数据库运行。Runtime 使用临时数据目录；Observer 的读数、日志和模型回答由测试控制。实际运行的补充证据单独说明，见 [测试分工](../index.mdx#kinds)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 一条写入保存内容后在 Observation 校验时失败 | 回到这条写入前，内容、识别依据、InputSet 和缓存项都撤销 |
| 同一请求另有有效写入 | 有效写入保存 |
| Schema 声明失败后重发同一序号 | 整次请求回滚，序号没有前移 |
| 多个请求同时使用同一识别依据写相同内容 | 只有一个实体和一个版本 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- 保存点和缓存回滚：`WriteApiTests.RejectionRollsBackOnlyItsWriteIncludingKeysInputsAndContent`。
- Schema、序号与写入的原子性：`WriteApiTests.InputsShareOneSetAndContentAndSchemaFailuresHaveDifferentBoundaries`。
- 并发识别：`WriteApiTests.ConcurrentRecognitionPreservesOneChainAndHttpBoundariesRemainExplicit`。

未覆盖：删除中途注入存储失败；逐一核对全部投影表的回滚。
