export const caseId = 'api-submission';

## 为什么验证 [#why]

写入方需要知道一次提交是否已保存，以及拒绝来自哪个版本。约定见 [API · 提交](../../api/writing.mdx#submission)、[VERSION-9](../../core/model/version.mdx#version-9) 和 [VERSION-13](../../core/model/version.mdx#version-13)。

## 前置条件 [#setup]

通过 `WebApplicationFactory` 启动 API，连接独立的测试数据库，见 [Database](../database.mdx)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 按依赖顺序提交 EntitySchema、业务版本及其下一版 | 返回 `200`，结果顺序与提交相同，带有保存时间 |
| 提交已保存的 VersionId，内容相同或不同 | 返回 `409`，规则为 `VERSION-9` |
| 实体已有下一版，再提交基于首版的新版本 | 返回 `409`，规则为 `VERSION-6` |
| 第二个版本违反 Core 规则 | 错误带 `index: 1`、VersionId 和规则；这次提交的版本全部没有保存 |
| 第二个版本带有 `recordedAt` | 返回 `400`，不带 `index`；整次提交没有保存 |
| 请求体超过 10 MiB | 返回 `413` |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/EntityApiTests.cs`：

- 顺序、保存时间、VersionId 重复和旧前驱冲突：`SubmissionConfirmsInOrderAndRejectsReusedOrStaleVersions`。
- 规则拒绝与格式错误整体不保存：`ContractErrorsAndRuleRejectionsSaveNothing`。
- 请求大小：`RequestLargerThanTenMiBIsRejected`。
