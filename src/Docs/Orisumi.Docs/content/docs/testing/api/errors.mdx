## 为什么验证 [#why]

整次请求的错误使用 Problem Details，单次写入的拒绝放在结果中。约定见 [错误](../../api/errors.mdx)。

## 前置条件 [#setup]

HTTP 用例经真实 API 和独立的 PostgreSQL 数据库运行。Runtime 使用临时数据目录；Observer 的读数、日志和模型回答由测试控制。实际运行的补充证据单独说明，见 [测试分工](../index.mdx#kinds)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 请求结构错误、读取未知身份、删除仍使用的 Schema | 分别为 400、404、409；application/problem+json，带 status、title 和 detail |
| 合法请求中一条内容不满足 Schema | HTTP 200，结果带 error.status、rule 和 detail，其他写入继续 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- HTTP 错误格式：`WriteApiTests.ConcurrentRecognitionPreservesOneChainAndHttpBoundariesRemainExplicit`。
- 单次写入错误：`WriteApiTests.RejectionRollsBackOnlyItsWriteIncludingKeysInputsAndContent`。
