export const caseId = 'api-observation-drafts';

## 为什么验证 [#why]

读取方靠观测草稿看到进行中的观测。草稿必须是最新的一份，最终版本保存后必须消失，迟到的旧写入也不能让结束的时段重新显示为进行中。约定见 [API · 观测草稿](../../api/index.mdx#drafts) 和 [OBSERVATION-13](../../core/model/observation.mdx#observation-13)。

## 前置条件 [#setup]

通过 `WebApplicationFactory` 启动 API，连接一个独立的测试数据库，见 [Database](../database.mdx)。已保存一个 Observer 版本和一个观测内容。时间由可控的 `TimeProvider` 提供。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 为一份还没有版本的 Observation 写入草稿，`previousVersionId` 为 `null` | `200`，返回草稿和 `updatedAt`；`GET /observation-drafts/{entityId}` 读到它；`GET /entities/{entityId}` 返回 `404` |
| 用更大的 `sequence` 写入延长后的草稿 | `200`，读到新的 `endAt` |
| 用较小的 `sequence` 写入较早的内容 | `200`，返回已暂存的草稿，内容不变 |
| 草稿的 `contentVersionId` 指向未保存的版本 | 被拒绝，`rule` 为 `ENTITY-6`，没有暂存草稿 |
| 提交这份 Observation 的首版 | 草稿被移除，读取草稿返回 `404` |
| 首版保存后，再以 `previousVersionId` 为 `null` 写入草稿 | `409`，`rule` 为 `VERSION-6`，读取草稿仍返回 `404` |
| 重发首版 | `200`，`recordedAt` 与首次保存时相同，版本链只有一个版本 |
| 以首版为 `previousVersionId` 写入草稿 | `200` |
| 时间前进超过 2 分钟，期间没有写入 | 读取草稿返回 `404` |
| 删除实体后写入草稿 | `409`，`rule` 为 `HISTORY-7` |
| 两种业务类型各有一份草稿，按其中一个 `resourceName` 列出 | 只返回观测内容属于这种业务类型的草稿 |
