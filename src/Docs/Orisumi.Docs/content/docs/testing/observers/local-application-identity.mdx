## 为什么验证 [#why]

本机应用按设备标识和原始安装线索识别，依据由后端保存。约定见 [身份](../../observers/foreground-state/local-application.mdx#identity)。

## 前置条件 [#setup]

HTTP 用例经真实 API 和独立的 PostgreSQL 数据库运行。Runtime 使用临时数据目录；Observer 的读数、日志和模型回答由测试控制。实际运行的补充证据单独说明，见 [测试分工](../index.mdx#kinds)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 同一设备上的两个 Observer 写同一安装 | 共用设备和本机应用，各有观测 |
| 设备改名或应用名称变化 | 本机应用身份不变，设备新版本不使应用内容形成下一版 |
| 另一台设备写相同路径 | 形成另一个设备和另一个本机应用 |
| 包标识或路径变化 | 识别依据变化 |
| 没有路径 | 仅在本次运行中按进程线索复用；重启或无进程线索时重新生成临时依据 |
| 删除本机应用后再采集 | 形成新实体 |
| 读不到运行设备 | 报告诊断并等待，不采集 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- 跨 Observer、设备、改名和删除：`LocalApplicationIdentityTests.TwoObserversShareInstallationButAnotherDeviceAndDeletionCreateNewEntities`。
- 原始线索与临时依据：`LocalApplicationIdentityTests.InstallationKeysUseRawPathsAndMissingPathsUseOnlyTheProcessLifetime`。

未覆盖：两个真实托管方进程同时采集同一安装；缺少设备时等待的进程级自动测试。
