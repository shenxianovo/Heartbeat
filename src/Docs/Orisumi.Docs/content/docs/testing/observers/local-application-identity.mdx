export const caseId = 'foreground-local-application-identity';

## 为什么验证 [#why]

[本机应用](../../observers/foreground-state/local-application.mdx)的身份要在程序重启后保持不变，同时不同路径或不同设备上的安装要分开。

## 前置条件 [#setup]

为测试创建独立的登记文件，用户自己的登记文件保持不动。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 首次遇到带包标识和路径的应用 | 生成并保存一个身份 |
| 重启前台状态 Observer 后读到相同的线索 | 复用原来的身份 |
| 只修改应用名称 | 复用原来的身份 |
| 修改路径或包标识 | 新建身份 |
| 用另一台设备的登记文件读到相同的线索 | 新建身份 |
| 缺少路径，同一次运行中再次读到相同的进程和启动时间 | 复用临时身份 |
| 缺少路径，进程或前台状态 Observer 重启 | 新建身份 |
| 多个程序实例同时登记三个不同的安装 | 每个安装恰好一个身份，三个都保留 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`，对应本页的预期范围：

- 首次登记、重启与改名复用，以及路径、包标识或设备不同则新建：`LocalApplicationIdentityTests.RestartAndRenameReuseInstallationButAnotherPathOrDeviceDoesNot`。
- 缺少路径时按本次运行的进程线索复用，重启后新建：`LocalApplicationIdentityTests.MissingPathUsesOnlyThisProcessLifetimeAndNeverMatchesByName`。
- 并发登记三个安装，各有一个身份且全部保留：`LocalApplicationIdentityTests.ConcurrentRegistrationsPreserveEveryApplicationAndPublishOneIdentityPerInstallation`。

登记文件损坏时的保留由 `LocalApplicationIdentityTests.CorruptRegistryIsNotReplaced` 检查，该方法未关联本 Case，页末报告不包含它。
