## 为什么验证 [#why]

并行的工具调用、回退后的分支和子 Agent 会让时间上相邻的记录属于不同的关系。[助手交互](../../observers/assistant-sessions/assistant-interaction.mdx#references)按来源的标识关联它们，时间顺序只用来排序。

## 前置条件 [#setup]

使用合成的会话日志，包含并行调用、回退和子 Agent 的会话文件。

## 操作与预期结果 [#steps]

| 输入 | 预期结果 |
| --- | --- |
| 一次响应中有两个并行的工具调用，结果按相反的顺序返回 | 每个结果的 `toolCallVersionId` 指向 `callId` 相同的调用 |
| 调用在这一轮读到，结果在下一轮才写入 | 结果形成时引用已形成的调用，调用的交互没有新版本 |
| 调用之后没有结果 | 只有调用的交互 |
| 工具结果的 `is_error` 为 `true`，或 Codex 的 `status` 为 `failed` | 形成 `isError` 为 `true` 的 `tool-result` |
| Claude Code 中回到第二句话重新提问，形成两条分支 | 两条分支的交互都保留，各自的 `sourceParentId` 与来源相同 |
| Claude Code 的子 Agent 文件，`meta.json` 带 `toolUseId` | 形成子 Agent 的会话，`parentSessionVersionId` 指向父会话，`spawnCallId` 等于父会话中调用的 `callId` |
| Codex 的子 Agent rollout，`source.subagent` 带父会话的标识 | 同上；子 Agent 会话中的 `UserMessage` 的 `actor` 为 `agent` |
| 子 Agent 的文件先于父会话的文件被读到 | 父会话先形成，子 Agent 的会话再引用它 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`，使用合成的日志：

- 并行调用的结果按相反顺序、在下一轮读到，以及分支的 `sourceParentId`：`AssistantMappingTests.ParallelCallsAndLateResultsUseCallIdsAndKeepBranches`。
- Claude Code 的工具失败：`AssistantMappingTests.ClaudeSeparatesRolesAndPreservesMixedContentAndResponseBlocks`。
- Codex 的工具项形成调用和结果，结果引用调用、两者共用原始记录，`status` 为 `failed` 时 `isError` 为 `true`，参数为 CommandExecution、McpToolCall、FileChange、Extension 和 ImageView：`AssistantMappingTests.CodexToolItemsBecomeTwoLinkedOccurrences`。
- 两种来源的子 Agent 先于父会话读到、`spawnCallId`、子 Agent 会话中消息的发出方：`AssistantMappingTests.ChildFilesBeforeParentsKeepParentIdentityAndSpawnCall`。

未覆盖：调用之后没有结果。
