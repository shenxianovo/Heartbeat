## 为什么验证 [#why]

每次应用识别判断是一份 Observation，产品是由 Name 命名的事物。依据见 [当前理解](../../core/rules/understanding.mdx)。

## 前置条件 [#setup]

通过真实 API 和独立 PostgreSQL 数据库运行；模型回答由测试替身提供。实际运行的补充证据单独说明。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 两个应用拥有相同线索；新增平台线索归入已有产品 | 相同线索只判断一次；新线索形成新的归属 Observation |
| 模型回答新产品 | 同一个请求写 Name 和线索归属；产品通过依据认出 |
| 形成判断 | InputSet 包含实际使用的应用描述、名称时段、目录归属和用户否定 |
| 用户否定归属，模型重复被否定的产品或名字 | 线索回到未归属；否定传给模型，重复结论跳过 |
| 重新判断并保存 | 新建 Observation，再写 supersede；旧判断保留但不在 current 中 |
| 未知线索的应用和名称不变 | 本进程跳过；新证据或重启后重新判断 |
| 模型失败、非法回答或请求失败 | 不形成判断，后续轮次可以再处理 |
| 缺少 API Key；改变模型型号 | 缺少 Key 只写描述和诊断，不调用模型；型号变化形成描述新版本 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- 共享线索、新产品单请求、已有产品和输入：`ApplicationIdentityTests.SharedCluesHaveOneJudgmentAndNewProductAndNameShareOneRequest`。
- 否定后的选择与新判断：`ApplicationIdentityTests.DenialReturnsClueToUnassignedAndRepeatedConclusionIsSkipped`。
- 重新判断的保存语义：`ApplicationIdentityTests.RejudgmentSavesANewObservationAndSupersedesThePreviousJudgment`；测试直接调用保存步骤，不定义触发入口。
- 未知缓存：`ApplicationIdentityTests.UnknownWaitsForNewEvidenceAndRestartClearsItsMemory`。
- 失败、缺少 Key 和描述变化：`ApplicationIdentityTests.FailuresAndMissingKeyDoNotCreateJudgmentsAndKeepDescription`。
- 模型请求与结构化回答：`ApplicationModelTests.SendsStructuredInputWithoutToolsAndReadsTheDecision`。

重新判断的触发时机仍由 [Application Identity · 待定](../../observers/application-identity/index.mdx#open) 决定；本次没有增加入口。

未覆盖：真实 OpenAI 调用、轮次间隔的进程级测量、包含所有证据种类的单个 InputSet 组合。
