export const caseId = 'foreground-application-period-boundaries';

## 为什么验证 [#why]

[前台应用时段](../../observers/foreground-state/foreground-application-period.mdx)只记下已确认的前台事实。读取失败或采集停顿造成的空白没有确认，必须留在时段之外；其他时间线的状态也不能切开前台时段。

## 前置条件 [#setup]

使用可以控制时间和应用读数的采集时间线。定时间隔为 1 秒，最大连续间隔为 3 秒。

## 操作与预期结果 [#steps]

| 输入 | 预期结果 |
| --- | --- |
| 第 0 秒、第 1 秒连续确认应用 A | 同一份观测从第 0 秒延长到第 1 秒 |
| 第 2 秒确认应用 B | A 结束于第 2 秒，B 从第 2 秒开始 |
| 应用不变，名称或时区变化 | 开始新的时段，旧的观测内容保持不变 |
| 第 1 秒后读取失败，第 2 秒恢复 | 原时段结束于第 1 秒，恢复时开始新的时段 |
| 第 1 秒后直到第 10 秒才恢复采样 | 中间的空白不计入任何时段 |
| 应用和确认间隔不变，另一条时间线记下锁屏、休眠或无输入 | 前台时段照常延续 |
| 两次定时确认之间收到 A → B → C 的激活事件 | 三个时段都保留 |
| 读数中断超过连续确认的阈值后恢复 | 原时段结束于最后一次确认，恢复后新建；不需要判断中断是否由休眠造成 |
| 系统时间倒退，或增量跳变超过 100 毫秒 | 时段断开，原观测不再延长 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`，对应本页的预期范围：

- 连续确认延长同一时段，以及应用切换时前后相接：`ForegroundTimelineTests.ContinuousConfirmationExtendsSamePeriodAndSwitchClosesAtNewConfirmation`。
- 名称或时区变化时分段，旧内容保留：`ForegroundTimelineTests.RenameAndTimeZoneChangeSplitContentWithoutReplacingApplicationIdentity`。
- 读取失败、长间隔、休眠计时差、时钟倒退与向前跳变；参数分别为 read-failure、long-gap、sleep、clock-backward、clock-forward：`ForegroundTimelineTests.InterruptionsStartNewPeriodWithoutFillingTheGap`。
- 两次轮询之间的事件，以及休眠通知结束于最后确认：`ForegroundSubmissionTests.EventsBetweenPollsArePreservedAndSleepClosesWithoutExtending`。

未覆盖：另一条设备时间线记下锁屏、休眠或无输入，而前台读数和确认间隔保持不变时，前台时段继续延长。上面的休眠参数检查的是采集自身的计时证据，不覆盖这项跨时间线要求。
