export const caseId = 'foreground-submission';

## 为什么验证 [#why]

前台状态 Observer 在时段结束时形成 Observation。需要确认连续读数只补全内存中的时段，保存后的边界来自最后的证据。约定见 [Foreground State · 提交](../../observers/foreground-state/index.mdx#submission)。

## 前置条件 [#setup]

使用合成的前台读数和内存 HTTP 后端，经 RuntimeObserverSession 处理批次，不调用 macOS 原生接口。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 连续确认同一个应用 | 尚未保存 Observation |
| 结束时段 | 本机应用、时段内容和 Observation 在一个提交中保存；Observation 只有一版 |
| 再次要求结束已经结束的时段 | 不产生新版本 |
| 切换时旧时段提交失败，随后新时段结束 | 报告采集诊断；新时段仍能正常保存 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/ForegroundSubmissionTests.cs`：

- 进行中不提交、结束只保存一版和重复结束：`OngoingPeriodIsSubmittedOnceWhenItEnds`。
- 提交失败后继续采集：`FailedSubmissionIsDiagnosedAndCollectionContinues`。

轮询之间的事件和休眠边界见 [Application Period Boundaries](./application-period-boundaries.mdx)。
