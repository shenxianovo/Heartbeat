## 为什么验证 [#why]

时段结束时交出完整内容和时间，进行中的时段只在内存。约定见 [写入](../../observers/foreground-state/index.mdx#submission)。

## 前置条件 [#setup]

HTTP 用例经真实 API 和独立的 PostgreSQL 数据库运行。Runtime 使用临时数据目录；Observer 的读数、日志和模型回答由测试控制。实际运行的补充证据单独说明，见 [测试分工](../index.mdx#kinds)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 连续确认同一应用 | 后端尚无这段 Observation |
| 时段结束或重复结束 | 先写本机应用描述再写时段；时段本身是一份 Observation，重复结束不再写 |
| 后端不可用时切换和结束时段 | 不查询后端，本地转发收下；恢复后按 localApplicationId 关联本机应用，全部送达 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- 进行中、结束和重复结束：`ForegroundSubmissionTests.OngoingPeriodIsWrittenOnceWhenItEnds`。
- 离线继续和恢复：`ForegroundSubmissionTests.OfflineCollectionContinuesAndAllPeriodsArriveAfterReconnection`。

未覆盖：进行中时段遇到进程异常退出的实际验证。
