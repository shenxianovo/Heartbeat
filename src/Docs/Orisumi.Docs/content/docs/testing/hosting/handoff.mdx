export const caseId = 'runtime-handoff';

## 为什么验证 [#why]

一个批次中的内容和 Observation 需要一起保存，后面的操作要引用前面形成的确定版本。约定见 [API · 提交](../../api/writing.mdx#requests)。

## 前置条件 [#setup]

通过 `WebApplicationFactory` 启动 API，连接独立的测试数据库。RuntimeObserverSession 在进程内处理批次；不可用后端由 HTTP 替身模拟。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 批次写入业务内容、引用 Observer，再绑定它们形成 Observation | 一次提交保存两个新版本；具名结果与后端读到的 VersionId 一致 |
| 省略前一版本，连续写入同一个实体 | 每一版接在当前版本之后；同批次先采用已形成的版本，再读取后端 |
| 对已有实体使用 `ifAbsent` | 沿用当前版本，版本链不增长 |
| 批次中后一个版本违反 Core 规则 | 返回被拒绝的规则，整个提交没有保存 |
| 后端不可用 | 请求返回错误 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/RuntimeSubmissionTests.cs`：

- 绑定引用与具名结果：`BatchIsOneSubmissionWithBoundReferencesAndNamedResults`。
- 前一版本省略与 `ifAbsent`：`OmittedPreviousVersionFollowsTheCurrentVersionAndIfAbsentKeepsIt`。
- 拒绝后整体回滚：`RejectedSubmissionSavesNothingAndReportsTheRule`。
- 后端不可用：`UnavailableBackendFailsTheCommit`。

未覆盖：超过 512 个操作；同批次连续更新同一实体；绑定结果在后续更新后保持原引用。
