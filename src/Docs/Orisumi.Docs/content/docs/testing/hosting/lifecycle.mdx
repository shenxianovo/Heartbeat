export const caseId = 'observer-lifecycle';

## 为什么验证 [#why]

自动重启能接上暂时的故障，但不能无休止地重启，也不能重启用户停用的 Observer。约定见 [Runtime · 启动与停止](../../hosting/runtime.mdx#lifecycle) 和 [重启](../../hosting/runtime.mdx#restart)。

## 前置条件 [#setup]

Runtime 使用独立的数据目录，运行一个由测试控制的 Observer：可以忽略标准输入结束、按需异常退出。重试测试使用实际短间隔。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 进程启动成功 | 立即为 running，不等待协议握手 |
| 协议版本不兼容 | 报告故障，不重启 |
| 标准输入关闭后 10 秒内不退出 | 进程被结束，`list` 中显示错误 |
| 运行中连续意外退出 | 分别等待 1、2、4 秒重启；第三次重启后仍退出，状态为 `failed`，`enabled` 仍为 `true` |
| `failed` 后调用 `retry` | 开始新一轮，最多再重启三次 |
| 启动后运行 60 秒再意外退出 | 失败计数已清零，等待 1 秒后重启 |
| 等待重启期间停用，或退出 Runtime | 等待中的重启取消，进程不再启动 |
| 正常停用 | 进程标准输入关闭后退出，不触发重启 |
| 关闭 Observer 的管道 | Observer 停止采集并退出 |
| 退出 Runtime 后，再重启 | 只运行退出前启用的 Observer |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`，对应本页的预期范围：

- 连续意外退出后重启三次、状态变为 `failed`；`retry` 后停用，等待中的重启取消：`RuntimeHostingTests.RepeatedCrashStopsAfterThreeRetriesAndDisabledStateCancelsRecovery`。
- shell Observer 读取实例、设备、地址和设置环境变量，标准输入关闭后退出：`RuntimeHostingTests.ShellObserverReceivesContextAndStopsWhenStdinCloses`。
- 未覆盖：关闭标准输入后停止的 10 秒超时；协议不兼容；60 秒后计数清零；Runtime 重启后只运行启用的 Observer。
