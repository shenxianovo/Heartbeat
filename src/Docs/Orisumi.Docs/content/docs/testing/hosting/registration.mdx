export const caseId = 'runtime-registration';

## 为什么验证 [#why]

业务版本引用程序实例和 Schema 版本，所以登记先于业务数据保存。新旧程序要能引用各自对应的 Schema 版本。约定见 [API · 使用类型](../../api/writing.mdx#types)。

## 前置条件 [#setup]

通过 `WebApplicationFactory` 启动 API，连接独立的测试数据库。进程内的 RuntimeObserverSession 直接访问 API；进程托管测试使用独立的数据目录。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| EntitySchema 已有两个版本，登记的内容与首版相同 | 返回首版的 VersionId，版本链不增长 |
| 登记与历史各版都不同的 Schema 内容 | 在当前版本之后形成新版本 |
| 沿用同一个实例身份，登记相同的信息 | 返回当前版本 |
| 登记变化后的程序实例信息 | 同一个实体形成下一版 |
| 卸载后重装或重启 Runtime | 继续使用原程序实例的 EntityId |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/`：

- Schema 历史版本复用与新增：`RuntimeSubmissionTests.SameSchemaContentReusesItsVersionAndNewContentExtendsTheChain`。
- 程序实例信息复用与更新：`RuntimeSubmissionTests.ChangedInstanceInformationFormsTheNextVersion`。
- 卸载、重装与 Runtime 重启：`RuntimeHostingTests.UninstallReinstallKeepsIdentityAndDisabledStateSurvivesRestart`。
