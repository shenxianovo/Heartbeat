export const caseId = 'runtime-binary-content';

## 为什么验证 [#why]

版本保存文件描述，字节先到后端，版本才能引用它。约定见 [API · 文件](../../api/writing.mdx#contents) 和 [BINARY-3](../../core/model/binary.mdx#binary-3)。

## 前置条件 [#setup]

业务类型包含一个可空的 `binary` 字段。参数校验使用 HTTP 替身；上传与读取连接真实 API 和独立的测试数据库。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 批次缺少文件字节，或摘要、大小不符 | 请求失败，没有上传字节或提交版本 |
| 批次带着描述与匹配的字节 | 先上传字节，再提交版本；后端可读取原字节 |
| 两个批次使用相同的文件 | 后端只保存一份字节 |
| 客户端通过 Runtime 读取文件 | 从后端返回字节；不存在时报错；后端不可用时报错 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/RuntimeBinaryContentTests.cs`：

- 客户端读取与错误：`ClientReadsContentFromTheBackend`。
