export const caseId = 'runtime-service';

## 为什么验证 [#why]

服务器上的 Runtime 没有客户端，它必须自己完成接入、启动和退出，重启后沿用程序实例的身份和配置。约定见 [Hosting · Server](../../hosting/server.mdx) 和 [Runtime · 退出](../../hosting/runtime.mdx#shutdown)。

## 前置条件 [#setup]

以 `--service` 启动 Runtime，使用独立的数据目录，附带目录中有一个测试用的安装包。后端是真实的 API 和测试数据库。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 没有 `host.json`，也没有 `--pairing-code` | Runtime 以非零的退出码退出，日志说明尚未接入 |
| 带有效的 `--pairing-code` 启动 | 接入为 `server` 类型的托管方，安装附带的包，登记实例并运行 |
| 关闭 Runtime 的标准输入 | Runtime 继续运行 |
| 发送 `SIGTERM` | Runtime 停止所有 Observer，然后退出 |
| 退出后，用同一个数据目录启动 | 未给新配对码时沿用凭证；程序实例的 EntityId 不变，启用状态和设置保持原样 |
| 管理入口停用、修改设置、更新和重试服务器上的实例 | Runtime 经长轮询收到并执行，报告新的状态 |
| Observer 的进程 | 继承 Runtime 的环境变量，例如 `OPENAI_API_KEY` |
| 设备端和服务器使用同一个安装包格式、同一个 Runtime 程序 | 安装、更新、卸载的结果相同 |

| 启动 Observer | `ORISUMI_DEVICE` 是这台机器的设备标识；容器中读不到时为空 |

## 测试实现 [#implementation]

运行上下文的进程内测试见 `RuntimeHostingTests.ShellObserverReceivesContextAndStopsWhenStdinCloses`，读取设备标识见 `RuntimeHostingTests.DeviceIdentityIsStableForThisMachine`。服务进程的完整生命周期没有自动测试。手动步骤：

1. `orisumi observers pack application-identity --target <RID> --output <目录>` 构建 Runtime 和应用识别的安装包，`orisumi env up web --temp` 启动环境。
2. 不带配对码以 `--service` 启动，确认非零退出；在 Web 的托管页签发配对码后再启动，确认出现一台服务器和它的应用识别实例。
3. 在 Web 中停用、修改设置、重试，确认状态随之变化；移除这台服务器，再用为它签发的配对码重新启动，确认 `hostId` 不变、`host.json` 的权限是 `0600`。
4. 发送 `SIGTERM`，确认退出码为 0；用同一个数据目录重启，确认程序实例的 EntityId 不变。

容器镜像的构建和缺少身份时的退出另行检查。未覆盖：本次未执行上述服务进程手动步骤；长时间运行和断网后的恢复。
