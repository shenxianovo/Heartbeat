请求被拒绝时，后端返回一个错误响应。调用方按状态码和 `rule` 判断原因，`detail` 供人阅读。

例如删除一个还有数据使用的 EntitySchema：

```json
{
  "type": "about:blank",
  "title": "Conflict",
  "status": 409,
  "detail": "Stored data still uses this EntitySchema.",
  "rule": "HISTORY-9"
}
```

一次写入被拒绝时，错误写在[这次写入的结果](./writing.mdx#requests)中，字段相同。

## 格式 [#format]

错误响应的 `Content-Type` 是 `application/problem+json`，结构遵循 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)。

| 必填字段 | 内容 |
| --- | --- |
| `type` | 固定为 `about:blank` |
| `title` | HTTP 状态的简短名称 |
| `status` | 实际的 HTTP 状态码 |
| `detail` | 这次错误的具体说明 |

| 扩展字段 | 出现的时机 | 内容 |
| --- | --- | --- |
| `rule` | 请求被某条 Core 规则拒绝 | 规则编号，例如 `HISTORY-9` |
| `code` | 认证或管理接口的错误 | 错误的种类，取值见 [Management · 错误](./management.mdx#errors) |
| `lastLocalSequence` | `code` 为 `sequence_gap` | 后端已接受的最大本机序号 |

## 状态码 [#status]

| 状态码 | 含义 |
| --- | --- |
| `400` | 请求本身有错：请求体或参数不符合契约，路径中的 ID 不是 UUID，或者内容违反 Core 规则。违反规则时带 `rule` |
| `401` | 托管方凭证缺失、无效或已撤销，带 `code` |
| `403` | 调用方不能做这项操作，带 `code` |
| `404` | 路径中的身份从未出现过，没有 EntitySchema 使用参数中的 `resourceName`，或者没有已保存的版本使用读取的内容 |
| `409` | 请求与已保存的数据冲突，带 `rule`，见[冲突](#conflicts) |
| `410` | 读取的实体或版本已被删除，读取方把它列为不可读取，见 [HISTORY-8](../core/rules/history.mdx#history-8)；或者管理的实例已删除，带 `code` |
| `413` | 请求体超过 10 MiB（10,485,760 字节）；上传的内容超过 8 MiB（8,388,608 字节） |
| `500` | 后端出现意外错误 |

`409` 的请求本身合法，换一个时机或在实体的另一个状态下可能保存成功；`400` 的请求本身需要修改。

## 冲突 [#conflicts]

| 冲突 | `rule` |
| --- | --- |
| 必须有值的引用解析不到目标 | [ENTITY-6](../core/model/entity.mdx#entity-6) |
| 另一个 Observer 用同一份依据写入了不同的内容 | [OBSERVATION-10](../core/model/observation.mdx#observation-10) |
| 同一个描述版本改变了不再变化的内容 | [SCHEMA-18](../core/model/schema.mdx#schema-18) |
| 资源名已被另一个业务类型使用 | [SCHEMA-5](../core/model/schema.mdx#schema-5) |
| 实体已被删除，或者写入的 EntityId 属于已删除的程序实例 | [HISTORY-7](../core/rules/history.mdx#history-7) |
| 内容用到的二进制内容尚未上传 | [BINARY-3](../core/model/binary.mdx#binary-3) |
| 删除仍有数据使用的 EntitySchema | [HISTORY-9](../core/rules/history.mdx#history-9) |
