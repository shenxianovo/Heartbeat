SDK 是[写入接口](./writing.mdx)的便利库。写入接口是全部契约，能发 HTTP 就能写 Observer，SDK 只帮业务代码省掉请求编码、文件上传和运行上下文的读取。本页的方法名是语言无关的写法，各语言可以换成自己的命名习惯，语义相同。

## 准备 [#setup]

```text
data = connect()
await data.use(definitions, self = (types.ForegroundStateObserver, selfContent))
```

`connect` 在受托管时从[运行上下文](../hosting/index.mdx#context)读取地址，直接运行时由调用方传入。`data.use` 声明用到的业务类型，写入程序实例自己的描述，见[业务类型](./writing.mdx#types)和[负责的 Observer](./writing.mdx#observer)。它不等后端，所以断网时也能启动。

## 写入 [#write]

每分钟读一次温度，业务代码只写这些：

```text
onEachSample(sample):
    await data.write(
        types.Temperature,
        { celsius: sample.celsius },
        time = point(sample.time, sample.timeZone)
    )
```

没有 `key`，所以每次读数是新的实体，相同的值也各成一份。事实时间由业务给出，未知时为 `null`，SDK 不用写入时刻填补，见 [TIME-1](../core/rules/time.mdx#time-1)。

`data.write` 在受托管时写给本地转发，收下就返回，不说明已经保存。

## 引用和识别依据 [#references]

前台时段引用本机应用：

```text
appKey = installationKey(device.entityId, bundleId, executablePath)

await data.writeAll([
    item(types.LocalApplication, key = appKey,
         content = { deviceVersionId: entity(device.entityId), identifiers: nativeIdentifiers }),
    item(types.ForegroundPeriod,
         content = {
             localApplicationVersionId: ref(types.LocalApplication, appKey),
             name: capturedName,
             icon: file(iconBytes, "image/png")
         },
         time = interval(startAt, endAt, timeZone))
])
```

`ref` 和 `entity` 写成[引用](./writing.mdx#references)，后端解析成当时的确定版本。先写入被引用的实体，再写入引用它的实体。`installationKey` 属于本机应用的业务规则。`writeAll` 把多次写入放进一个请求，每次写入各自保存。

助手日志按行写入，重读什么都不发生：

```text
for line in newLines:
    session, interactions = parse(line)
    items.add(item(types.Session, key = sessionKey(session), content = sessionFields(session)))
    for each interaction in interactions:
        items.add(item(types.Interaction, key = interactionKey(interaction),
                       content = interactionFields(interaction, ref(types.Session, sessionKey(session))),
                       time = sourceTime(interaction)))

await data.writeAll(items)
saveProgress(position)
```

## 结果 [#results]

需要写入结果时，程序连后端地址：`data.write` 返回实际的版本，见[两个地址](./writing.mdx#endpoints)。

```text
result = await data.direct.write(types.ApplicationMembership, key = membershipKey(identifier),
                                 content = { identifier, productVersionId: entity(product.entityId) },
                                 time = unknown(), inputs = usedVersions)
catalog.apply(result.version)
```

读取用 `data.observations`、`data.version`、`data.versions`、`data.entity`，见 [Reading](./reading.mdx)。读取需要后端可用。

## 文件 [#files]

业务代码用 `file(bytes, mediaType)` 交出字节，SDK 计算摘要和大小，先上传，再把描述写进 `binary` 字段，嵌套的对象和数组中相同。已有描述时可以直接写入。上传发生在写入之前，所以文件已上传不说明版本已保存。

## 输入 [#inputs]

`inputs` 列出处理实际用到的已保存版本，由业务代码给出，见 [Evidence](../core/rules/evidence.mdx)。

- 读到同一实体的两个版本时，两个都列出。
- 查询过但没有进入处理的版本不列出。
- Schema 版本的说明进入了模型的上下文时，列出这个 Schema 版本。

## 分工 [#division]

| 谁 | 负责 |
| --- | --- |
| 业务代码 | 对象和观测的粒度、内容、识别依据、事实时间、实际输入、写入时机、读取进度 |
| SDK | 请求编码、文件、运行上下文 |
| 本地转发 | 留住写入，按顺序交给后端，留住被拒绝的写入 |
| 后端 | 认出对象，ID、版本链、解析引用、InputSet、校验和保存 |

## 业务类型的声明 [#definitions]

一种业务类型的声明是 SchemaId 和完整的 Schema 内容，随程序发布。各语言使用同一份声明，所以同一种业务类型在每种语言中都是同一个 SchemaId 和同样的内容。

识别依据的组成属于业务规则：`scope`、`scheme` 和 `value` 怎样组成，写在业务类型页，并给出输入输出样例。

## 读取的数据 [#fidelity]

读到的版本保留实际的 Schema 版本、全部字段，以及省略和 `null` 的区别。

- 强类型只解释程序支持的结构。遇到不认识的结构时，程序保留原始内容，由业务决定怎样处理，不按最新的 Schema 转换。
- 数值、时间和 `null` 按原值保留。API 的整数范围超过很多语言的默认数字类型，SDK 用能保真的表示。

## 受托管与直接运行 [#modes]

| | 受托管的程序 | 直接运行的程序 |
| --- | --- | --- |
| 地址和凭证 | 来自[运行上下文](../hosting/index.mdx#context) | 由调用方传入 |
| 写入 | 默认写给本地转发 | 写给后端，断网时失败 |
| 负责的 Observer | 程序实例 | 调用方选定的实体，用[识别依据](./writing.mdx#observer)认出自己 |
| 配置和停止 | 来自托管方 | 由程序自己决定 |

例如一次性脚本从一个 CSV 导入健康数据：它声明业务类型，写入代表这个脚本的实体，再为每一行写入，每一行用来源的标识作 `key`，运行结束就退出。再导入一次同一份文件，什么都不发生。

## .NET [#dotnet]

.NET 的 SDK 在 `src/Observers/Orisumi.Observer.Sdk/`，前台状态 Observer、助手会话 Observer 和应用识别 Observer 都用它。
