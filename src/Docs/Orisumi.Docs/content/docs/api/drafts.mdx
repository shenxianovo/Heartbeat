---
title: "Drafts"
description: "怎样写入和读取观测草稿：一份 Observation 尚未保存的最新陈述"
---

观测草稿是一份 Observation 尚未保存的最新陈述，见 [OBSERVATION-11](../core/model/observation.mdx#observation-11)。后端在进程的内存中为每份 Observation 暂存一份草稿，重启后清空。其他接口只返回已保存的版本。写入方怎样维护草稿，见 [Hosting · Submission · 观测草稿](../hosting/submission.mdx#drafts)。

## 写入 [#writing]

VS Code 的时段从 14:00 开始，14:12 的确认用 [`PUT /observation-drafts/{entityId}`](/api/putObservationDraft) 写入草稿：

```json title="PUT /observation-drafts/01a12e31-9050-7000-8000-000000000030"
{
  "previousVersionId": null,
  "sequence": 721,
  "content": {
    "observerVersionId": "01a12e31-9050-7000-8000-0000000000a1",
    "contentVersionId": "01a12e31-9050-7000-8000-000000000120",
    "inputSetVersionId": null,
    "startAt": "2026-10-06T06:00:00Z",
    "endAt": "2026-10-06T06:12:00Z",
    "timeZone": "Asia/Shanghai"
  }
}
```

- 路径中的 EntityId 是这份 Observation 的身份，实体可以还没有版本。
- `previousVersionId` 必须是实体的当前版本，实体还没有版本时为 `null`，见 [OBSERVATION-13](../core/model/observation.mdx#observation-13)。不是当前版本时返回 `409`，`rule` 为 `VERSION-6`。
- `sequence` 是写入方为这份草稿生成的递增整数。不大于已暂存草稿的 `sequence` 时，草稿保持不变，响应返回已暂存的草稿。
- `content` 按 Observation 校验，见 [OBSERVATION-12](../core/model/observation.mdx#observation-12)。请求结构的错误和违反规则的错误，与[提交](./writing.mdx#submission)中的状态码和 `rule` 相同，不带 `index` 和 `versionId`。

写入成功返回 `200`，响应是暂存的草稿：请求的成员加上 `entityId` 和 `updatedAt`。`updatedAt` 是后端最近一次接受这份草稿的时刻。

## 移除 [#removal]

后端在两种情况下移除草稿：

| 情况 | 原因 |
| --- | --- |
| 实体保存了新版本 | 草稿已经不接在当前版本之后 |
| 超过 2 分钟没有写入 | 写入方可能已经停止，草稿不再更新 |

16:00 VS Code 的 Observation 保存后，它的草稿随即移除。草稿被移除不说明事实已经结束，事实是否结束按 [TIME-4](../core/rules/time.mdx#time-4) 判断。

## 读取 [#reading]

[`GET /observation-drafts/{entityId}`](/api/getObservationDraft) 读取一份草稿，没有草稿时返回 `404`。[`GET /observation-drafts`](/api/listObservationDrafts) 按 EntityId 升序列出全部草稿，不分页；`resourceName` 可以省略，给出时只返回观测内容属于这种业务类型的草稿。

读取方组合已保存的观测和草稿：同一个 EntityId 两者都有时，草稿接在当前版本之后，是较新的陈述。
