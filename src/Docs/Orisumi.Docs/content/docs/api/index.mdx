---

Orisumi API 提供数据能力：按 [Core](../core/index.mdx) 的事物与观测模型写入、读取和删除数据。写入时调用方说出一份 Observation 的完整内容，后端认出对象、创建事物、组织版本；读取时接口按身份寻址：版本用 VersionId，实体用 EntityId。所有类型的实体共用同一组接口，读取一个版本之前不需要知道它的类型。理由见 [ADR · 单向写入与托管的分工](../adr/data-capability.mdx) 和 [ADR · 实体 API](../adr/entity-api.mdx)。

## 例子 [#example]

[Walkthrough](../start/walkthrough.mdx) 那一天，各方这样调用 API：

| 时刻 | 调用方 | 调用 |
| --- | --- | --- |
| 16:00 | 前台状态 Observer | `PUT /contents/{digest}` 上传 VS Code 的图标，见 [Writing · 文件](./writing.mdx#contents)；再 `POST /writes` 写入 VS Code 的前台时段，见 [Writing](./writing.mdx#example) |
| 晚上 | 推断 Observer | `GET /observations` 读取当天的时段，见 [Reading · 按事实时间查询](./reading.mdx#observations)；再 `POST /writes` 写入推断，列出实际用到的输入 |
| 第二天 | Web 控制台 | `GET /contents/{digest}` 读取时段中的图标，见 [Reading · 内容](./reading.mdx#contents)；`GET /entities/{entityId}/referrers` 从 VS Code 找到相关的数据，见 [Reading · 引用方](./reading.mdx#referrers)；`DELETE /entities/{entityId}` 删除浏览器的时段，见 [Writing · 删除](./writing.mdx#deletion) |

读取收到的都是版本，版本的 JSON 表示见 [Versions](./versions.mdx)。请求被拒绝时的响应见 [Errors](./errors.mdx)。业务代码可以直接发 HTTP 请求，也可以用 [SDK](./sdk.mdx)。

## 接口 [#operations]

| 用途 | 接口 |
| --- | --- |
| 写入 | [`POST /writes`](/api/write)、[`PUT /contents/{digest}`](/api/putContent)、[`DELETE /entities/{entityId}`](/api/deleteEntity) |
| 读取 | [`GET /versions/{versionId}`](/api/getVersion)、[`POST /versions/read`](/api/readVersions)、[`GET /entities/{entityId}`](/api/getEntity)、[`GET /entities/{entityId}/versions`](/api/listEntityVersions)、[`POST /things/read`](/api/readThings)、[`GET /contents/{digest}`](/api/getContent) |
| 列出与查询 | [`GET /entities`](/api/listEntities)、[`GET /things`](/api/listThings)、[`GET /observations`](/api/listObservations)、[`GET /entities/{entityId}/referrers`](/api/listReferrers) |
| Observer 的管理 | `/pairings`、`/hosts` 和 `/observer-instances` 下的接口由管理入口调用，`/runtime/` 下的由托管方调用，见 [Management](./management.mdx) |

每个接口一页，由契约生成，给出路径、参数、请求和响应的结构。接口的语义写在本分区的主题页中：[Writing](./writing.mdx)、[Reading](./reading.mdx) 和 [Management](./management.mdx)。

## 契约 [#contract]

`content/docs/api/openapi.json` 是 HTTP 契约的权威来源，后端、客户端、测试和本分区的文档都按它同步，见 [ADR · 设计层与变更流程](../adr/documentation-authority.mdx)。文档站按契约为每个接口生成一页，地址是 `/api/<operationId>`。

## 服务地址 [#servers]

契约的 `servers` 声明相对地址 `/api`，所以契约中的 `/versions` 对外是 `/api/versions`。本地环境的入口地址由 `orisumi env status` 给出，各入口怎样转发见 `tools/Orisumi.AppHost/README.md`。接口页的 Playground 只在本地文档站中可用，公开站点的接口页只展示契约。

## 认证与授权 [#auth]

调用方有两种：托管方和管理入口。

| 调用方 | 请求怎样认证 | 可以调用 |
| --- | --- | --- |
| 托管方和它运行的程序 | `Authorization: Bearer <托管方凭证>`，凭证由配对得到，见 [Management · 配对与托管方](./management.mdx#hosts) | 全部读取接口，`DELETE /entities/{entityId}` 以外的写入接口，以及 `/runtime/` 下的接口 |
| 管理入口：Web 控制台、设备端客户端的管理和直接运行的脚本 | 尚未决定，之后接入 OAuth。在此之前，不带 `Authorization` 的请求按管理入口处理 | 全部接口，`/runtime/` 下的接口除外 |

- 带 `Authorization` 的请求，凭证无效或托管方已移除时，任何接口都返回 `401`。
- 托管方把凭证放进运行上下文交给程序，见 [Hosting · 运行上下文](../hosting/index.mdx#context)。
- 带托管方凭证写入时，`observer` 必须是这个托管方未删除的程序实例，否则返回 `403`，`code` 为 `host_mismatch`。托管方凭证不能删除实体。
- 读取不需要负责的 Observer。托管方凭证能读取全部 Core 数据，因为服务器上的 Observer 依据全部已保存的数据形成观测，设备端客户端也用它读取数据，见 [Hosting · 连接](../hosting/protocol.mdx#connection)。
- 管理入口的认证接入之前，API 只通过绑定本机的入口提供，见 [ADR · 定位与边界](../adr/positioning.mdx#costs)。本地环境照常使用 HTTP。
- 对外提供 API 时，入口必须使用 HTTPS，托管方凭证和配对码只在 HTTPS 中传输。
