Orisumi API 按 [Core](../core/index.mdx) 的实体与版本模型保存、读取和删除数据。接口按身份寻址：版本用 VersionId，实体用 EntityId。所有类型的实体共用同一组接口，读取一个版本之前不需要知道它的类型。接口这样设计的理由见 [ADR · 实体 API](../adr/entity-api.mdx)。

## 例子 [#example]

[Walkthrough](../start/walkthrough.mdx) 那一天，各方这样调用 API：

| 时刻 | 调用方 | 调用 |
| --- | --- | --- |
| 14:00 | Runtime | `PUT /contents/{digest}` 上传 VS Code 的图标，见 [Writing · 内容](./writing.mdx#contents)；再 `POST /versions` 提交 VS Code 的前台时段，见 [Writing · 提交](./writing.mdx#submission) |
| 14:00 起 | Runtime | `PUT /observation-previews/{entityId}` 写入进行中的 Observation，见 [Previews](./previews.mdx) |
| 16:00 后 | Runtime | `POST /versions` 提交这一段的 Observation |
| 晚上 | 推断 Observer | `GET /observations` 读取当天的时段，再 `POST /versions` 提交 InputSet 和推断，见 [Reading · 按事实时间查询](./reading.mdx#observations) |
| 第二天 | Web 控制台 | `GET /contents/{digest}` 读取时段中的图标，见 [Reading · 内容](./reading.mdx#contents)；`GET /entities/{entityId}/referrers` 从 VS Code 找到相关的数据，见 [Reading · 引用方](./reading.mdx#referrers)；`DELETE /entities/{entityId}` 删除浏览器的时段，见 [Writing · 删除](./writing.mdx#deletion) |

每次调用收发的都是版本，版本的 JSON 表示见 [Versions](./versions.mdx)。请求被拒绝时的响应见 [Errors](./errors.mdx)。

## 接口 [#operations]

| 用途 | 接口 |
| --- | --- |
| 写入 | [`POST /versions`](/api/submitVersions)、[`PUT /contents/{digest}`](/api/putContent)、[`DELETE /entities/{entityId}`](/api/deleteEntity) |
| 读取 | [`GET /versions/{versionId}`](/api/getVersion)、[`GET /entities/{entityId}`](/api/getEntity)、[`GET /entities/{entityId}/versions`](/api/listEntityVersions)、[`GET /contents/{digest}`](/api/getContent) |
| 列出与查询 | [`GET /entities`](/api/listEntities)、[`GET /observations`](/api/listObservations)、[`GET /entities/{entityId}/referrers`](/api/listReferrers) |
| 观测预览 | [`PUT /observation-previews/{entityId}`](/api/putObservationPreview)、[`GET /observation-previews/{entityId}`](/api/getObservationPreview)、[`GET /observation-previews`](/api/listObservationPreviews) |
| Observer 的管理 | `/pairings`、`/hosts`、`/observer-instances` 和 `/runtime/` 下的接口，见 [Management](./management.mdx) |

每个接口一页，由契约生成，给出路径、参数、请求和响应的结构。接口的语义写在本分区的主题页中：[Writing](./writing.mdx)、[Reading](./reading.mdx)、[Previews](./previews.mdx) 和 [Management](./management.mdx)。

## 契约 [#contract]

`content/docs/api/openapi.json` 是 HTTP 契约的权威来源，后端、客户端、测试和本分区的文档都按它同步，见 [ADR · 设计层与变更流程](../adr/documentation-authority.mdx)。文档站按契约为每个接口生成一页，地址是 `/api/<operationId>`。

## 服务地址 [#servers]

契约的 `servers` 声明相对地址 `/api`，所以契约中的 `/versions` 对外是 `/api/versions`。本地环境的入口地址由 `orisumi env status` 给出，各入口怎样转发见 `tools/Orisumi.AppHost/README.md`。接口页的 Playground 只在本地文档站中可用，公开站点的接口页只展示契约。

## 认证与授权 [#auth]

调用方有两种：管理入口和 Runtime。

| 调用方 | 请求怎样认证 | 可以调用 |
| --- | --- | --- |
| Runtime | `Authorization: Bearer <托管方凭证>`，凭证由配对得到，见 [Management · 配对与托管方](./management.mdx#hosts) | 全部读取接口、`POST /versions`、`PUT /contents/{digest}`、观测预览，以及 `/runtime/` 下的接口 |
| 管理入口 | 尚未决定，之后接入 OAuth。在此之前，不带 `Authorization` 的请求按管理入口处理 | 全部接口，`/runtime/` 下的接口除外 |

- 带 `Authorization` 的请求，凭证无效或托管方已移除时，任何接口都返回 `401`。
- Runtime 读取全部 Core 数据，因为服务器上的 Observer 依据全部已保存的数据形成观测，设备上的 Runtime 也为客户端读取已保存的部分。
- 管理入口的认证接入之前，API 只通过绑定本机的入口提供，见 [ADR · 定位与边界](../adr/positioning.mdx#costs)。本地环境照常使用 HTTP。
- 对外提供 API 时，入口必须使用 HTTPS，托管方凭证和配对码只在 HTTPS 中传输。
