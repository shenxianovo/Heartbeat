## 背景 [#context]

人会换设备、换应用、换 AI 助手。关于一个人的信息分散在各个软件里：屏幕使用时间在系统里，对话记忆在某个助手的账号里。软件被替换，信息也就丢了。

Orisumi 的长期背景是一个以人为持续主体的个人数字环境。终端、应用、Agent、计算和存储都可以替换，需要延续的是人的信息、关系和活动。这个环境还包括身份、授权、资源操作和活动执行，Orisumi 只负责其中一部分。边界不清，新需求会把 Orisumi 推向任务执行、外部资源同步或某个 Agent 的私有记忆。

## 决定 [#decision]

- 用户是 Orisumi 服务的持续主体。设备、应用、Observer 和 Agent 都是可以替换的参与者。
- Orisumi 保存一个人经历了什么，即观测及其必要上下文，为未来提出的问题提供依据。
- 关于外部资源的数据是观测，资源的权威状态由管理它的服务保存。
- 数据的结构和含义随数据一起保存，换掉采集和使用它的软件后仍能读懂。
- 数据属于用户。Agent 是读取方之一，用户也可以直接查看和管理。
- 任务和活动的执行、外部资源的管理，由个人数字环境中的其他组件负责。

## 理由 [#rationale]

经历过去就无法再采集。以设备和软件为中心组织数据，数据的寿命受限于它们；以人为主体，记录才能跨越更替持续积累。

浏览器历史、助手会话这类数据，说明的是 Orisumi 在某个时间观察到了什么。把它们当作权威副本，Orisumi 就要负责同步和冲突处理，而它无法确认外部状态。

软件替换后，读取方要能在没有原软件的情况下理解数据。EntitySchema 声明字段和业务含义，每个业务版本固定引用解释它的 Schema 版本；Observation 用统一的结构说明谁作出陈述、依据什么、事实何时成立。

Agent 会更替，会话会结束，所以数据存放在 Agent 之外。

放弃的方案：

- **Orisumi 作为某个 Agent 的记忆。** 更换 Agent 时数据无法延续。
- **Orisumi 同时负责任务执行和外部资源同步。** 执行、并发和外部确认需要另一套模型和保证，观测模型承担不了。

## 代价 [#costs]

- 替用户回复消息这类操作由其他组件完成。
- 读取方需要外部资源的当前状态时，回到来源确认。
- 读取方的授权尚未决定。
