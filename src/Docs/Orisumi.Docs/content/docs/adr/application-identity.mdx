## 背景 [#context]

前台状态 Observer 记下的是某台设备上的安装：两台 Mac 上的 QQ 是两个本机应用，Android 上的 QQ 以后也是另一个。用户看自己的记录时，想看到的是“QQ 用了多久”，所以需要一个跨设备、跨平台的应用身份，并且这个身份要持久保存：新设备接入时直接沿用已有的认识，认错了可以改。

同一款软件在不同平台上的标识各不相同，名称也可能不同，按规则匹配要维护大量对照。语言模型认识常见软件，判断一次的费用很低，适合承担这一步。

## 决定 [#decision]

- 应用产品是一种业务类型，表示用户认知中的一款软件，内容只有名称，写入一次。
- 线索归属是一种关系实体，表示一条跨设备线索属于一个应用产品，例如 macOS 的应用包标识。一条线索最多一条线索归属，识别依据就是线索。
- 本机应用的跨设备线索有线索归属时，它属于线索归属指向的产品。归属由线索的值决定，本机应用和线索归属之间没有引用。
- 线索归属的当前版本是归属的权威来源。本机应用和前台时段保持原样。
- 应用识别 Observer 是一个独立的安装包，在服务器上由 Runtime 运行，见 [ADR · Runtime 与进程托管](./observer-runtime.mdx)。每个部署只有一个它的程序实例。
- 应用识别 Observer 只处理还没有归入任何应用产品的线索：交给 OpenAI 的模型判断，结果直接写成线索归属，模型认出新软件时先写入新的应用产品。
- 每次写入后，它等后端保存了这一次写入再处理下一条线索。
- 每条线索归属有一份 Observation，Observation 说明谁负责，InputSet 列出判断时读到的版本。
- 用户撤销一次判断就是删除这条线索归属，线索回到未归属，模型再判断一次。

## 理由 [#rationale]

一款软件在一个平台上的跨设备线索通常是稳定的：QQ 在每台 Mac 上的应用包标识都是 `com.tencent.qq`。所以认识一次就够了，之后任何设备上出现这条线索，读取方查表即可得到产品。识别只发生在线索第一次出现时，模型的调用次数取决于用过多少种不同的应用，与使用时长无关。

用户要能看到每条线索是哪次判断认定的、依据是什么，线索归错时要能只撤销这一条。所以粒度是一条线索一个实体。周一判断 `com.tencent.qq`、周三判断 `com.tencent.mobileqq` 是两次模型调用、两份依据，陈述的是两件事实，见 [IDENTITY-4](../core/rules/identity.mdx#identity-4)。删除是这一阶段已有的操作，所以撤销不用新增功能；这条线索之外的产品和判断都不受影响。

线索只有一条归属，所以识别依据就是线索本身。归属规则不需要裁决同一条线索写在两个产品中的情况。

产品只有名称，这一阶段没有人改名：模型只判断新线索，用户的修改不做。它没有 Observation，是因为新建产品和线索归属出自同一次判断，责任和依据写在线索归属上一处就够。

应用识别 Observer 需要读取全部设备的数据，并保持一份全局一致的产品目录，所以它在服务器上运行，而且只有一个。它判断下一条线索之前必须读到上一次的结果，否则同一款软件的两条线索会各建一个产品。写入在业务代码等待时完成，所以下一次读取一定能读到。

模型的判断直接生效。逐条审核会让每个新应用都等待用户处理。用户的修改这一阶段不做。

放弃的方案：

- **线索写在产品的数组中，每条线索形成产品的新版本。** 几次独立的判断合进一份 Observation，只能看版本之间的差别；撤销一条线索要删除整个产品，全部线索重新判断；写入前要读出产品、加上线索再写回。
- **每次判断一个实体，读取方取保存时间最晚的一条。** 能直接保留换模型前后的结果，但这一阶段没有这个需求，归属规则还要多一条裁决。
- **在产品和本机应用之间加一层平台发行。** 当前的需求只按产品聚合，没有视图需要区分同一产品在各平台上的发行。平台可以从线索的 scheme 看出。
- **为每个本机应用保存一个归属的关系实体。** 每台设备的每个安装都要写一次，两台 Mac 上的同一个应用也要分别写；用户的一次改正要改很多实体。线索的值已经足以决定归属，所以关系实体按线索建立。
- **人工修改优先于模型，或者为每次判断保留候选和置信度。** 需要定义锁定、优先级和裁决规则。模型只处理没有归属的线索。
- **在设备上运行。** 设备的客户端不运行时不识别；设备离线时，写入要等很久才能保存，下一条线索也要跟着等。
- **允许模型联网查资料。** 要保存查到的外部资料作为依据，费用也更高。常见软件模型已经认识，不认识的保持未归属，由用户处理。

## 代价 [#costs]

- 本机应用的归属不在引用图中。沿引用方查不到一个产品有哪些本机应用，读取方要读出全部线索归属，再按线索匹配。
- 读取方多读一种类型，应用识别 Observer 的 InputSet 同时列出目录中的产品和线索归属。
- 撤销之后模型的输入几乎不变，可能再次答错。这时用户再删除一次，或者等更换模型；不再判断这条线索要等用户的陈述。
- 新建产品是两个请求。第一个成功、第二个失败时，留下一个没有线索的产品。
- 软件改名后，产品保持第一次判断时的名称。
- 线索归属引用产品的一个版本。以后产品改名形成新版本时，读取方要按实体合并。
- 跨设备线索相同的两个应用只能属于同一个产品，例如开发中使用同一个应用包标识的两个临时构建。
- 没有跨设备线索的本机应用不属于任何产品，例如只读到可执行文件路径的安装。
- 应用识别 Observer 依赖 OpenAI：需要 API Key 并产生费用，未配置时不识别新线索。
- 本机应用的名称、标识线索（包括可执行文件路径）和产品目录会发送给 OpenAI，发送的内容见 [Application Identity · 模型](../observers/application-identity/index.mdx#model)。
- 只能运行一个应用识别 Observer，扩展时需要另行设计。
- 服务器上要运行 Runtime，并保留它的持久目录。
