## 背景 [#context]

前台状态 Observer 记下的是某台设备上的安装：两台 Mac 上的 QQ 是两个本机应用，Android 上的 QQ 以后也是另一个。用户看自己的记录时，想看到的是“QQ 用了多久”，所以需要一个跨设备、跨平台的应用身份，并且这个身份要持久保存：新设备接入时直接沿用已有的认识，认错了可以改。

同一款软件在不同平台上的标识各不相同，名称也可能不同，按规则匹配要维护大量对照。语言模型认识常见软件，判断一次的费用很低，适合承担这一步。

## 决定 [#decision]

- 应用产品是一种业务类型，表示用户认知中的一款软件。它的 `identifiers` 列出属于它的跨设备线索，例如 macOS 的应用包标识。
- 本机应用的跨设备线索出现在哪个应用产品的当前版本中，它就属于哪个应用产品。归属由线索的值决定，产品和本机应用之间没有引用。
- 应用产品的当前版本是归属的权威来源。本机应用和前台时段保持原样。
- 应用识别 Observer 是一个独立的安装包，在服务器上由 Runtime 运行，见 [ADR · Runtime 与进程托管](./observer-runtime.mdx)。每个部署只有一个它的程序实例。
- 应用识别 Observer 只处理还没有归入任何应用产品的线索：交给 OpenAI 的模型判断，结果直接写成应用产品的新版本或新的应用产品。
- 每次写入后，它等后端保存了这一批再处理下一条线索。
- 用户在 Web 控制台中修改应用产品，这些修改的 Observer 是用户本人。修改和模型的判断一样，直接形成应用产品的新版本。
- 每个应用产品版本由一份 Observation 陈述，Observation 说明谁负责，InputSet 列出判断时读到的版本。

## 理由 [#rationale]

一款软件在一个平台上的跨设备线索通常是稳定的：QQ 在每台 Mac 上的应用包标识都是 `com.tencent.qq`。所以认识一次就够了，之后任何设备上出现这条线索，读取方查表即可得到产品。识别只发生在线索第一次出现时，模型的调用次数取决于用过多少种不同的应用，与使用时长无关。

线索写在应用产品中，一个产品的全部认识都在它自己的版本链里：读当前版本就知道它现在包含哪些线索，沿版本链看到它怎样变化，沿引用它的 Observation 看到每次变化由谁负责、依据什么。模型和用户写的是同一个实体，后保存的版本就是当前的结果。

应用识别 Observer 需要读取全部设备的数据，并保持一份全局一致的产品目录，所以它在服务器上运行，而且只有一个。它判断下一条线索之前必须读到上一次的结果，否则同一款软件的两条线索会各建一个产品。Runtime 收到后端的响应才返回提交的结果，所以下一次读取一定能读到，见 [Submission · 结果](../hosting/submission.mdx#result)。

模型的判断直接生效。错误由用户在 Web 中改正，改正的成本是一次操作。逐条审核会让每个新应用都等待用户处理。

放弃的方案：

- **在产品和本机应用之间加一层平台发行。** 当前的需求只按产品聚合，没有视图需要区分同一产品在各平台上的发行。平台可以从线索的 scheme 看出。
- **为每个本机应用保存一个归属的关系实体。** 每台设备的每个安装都要写一次，两台 Mac 上的同一个应用也要分别写；用户的一次改正要改很多实体。线索的值已经足以决定归属。
- **人工修改优先于模型，或者为每次判断保留候选和置信度。** 需要定义锁定、优先级和裁决规则。模型只处理没有归属的线索，已经归入产品的线索由用户调整，两者处理的线索互不重叠。
- **在设备上运行。** 设备的客户端不运行时不识别；设备离线时，写入要等很久才能保存，下一条线索也要跟着等。
- **允许模型联网查资料。** 要保存查到的外部资料作为依据，费用也更高。常见软件模型已经认识，不认识的保持未归属，由用户处理。

## 代价 [#costs]

- 归属不在引用图中。沿引用方查不到一个产品有哪些本机应用，读取方要读出全部产品的当前版本，再按线索匹配。
- 跨设备线索相同的两个应用只能属于同一个产品，例如开发中使用同一个应用包标识的两个临时构建。
- 没有跨设备线索的本机应用不属于任何产品，例如只读到可执行文件路径的安装。
- 应用识别 Observer 依赖 OpenAI：需要 API Key 并产生费用，未配置时不识别新线索。
- 本机应用的名称、标识线索（包括可执行文件路径）和产品目录会发送给 OpenAI，发送的内容见 [Application Identity · 模型](../observers/application-identity/index.mdx#model)。
- 只能运行一个应用识别 Observer，扩展时需要另行设计。
- 服务器上要运行 Runtime，并保留它的持久目录。
