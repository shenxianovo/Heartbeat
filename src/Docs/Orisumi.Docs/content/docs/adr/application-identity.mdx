## 背景 [#context]

前台状态 Observer 记下的是某台设备上的安装：两台 Mac 上的 QQ 是两个本机应用，Android 上的 QQ 以后也是另一个。用户看自己的记录时，想看到的是“QQ 用了多久”，所以需要一个跨设备、跨平台的应用身份，并且这个身份要持久保存：新设备接入时直接沿用已有的认识，认错了可以改。

同一款软件在不同平台上的标识各不相同，名称也可能不同，按规则匹配要维护大量对照。语言模型认识常见软件，判断一次的费用很低，适合承担这一步。

## 决定 [#decision]

- 应用产品是事物，表示用户认知中的一款软件，名称是一份 Name。
- 跨设备线索是事物，例如 macOS 的应用包标识。本机应用的描述引用它。
- 线索归属是一份 Observation，引用线索和产品，表示模型判断这条线索属于这个产品。一条线索可以有多次判断。
- 当前理解中的线索归属决定线索属于哪个产品。本机应用和前台时段保持原样。
- 应用识别 Observer 是一个独立的安装包，在服务器上由 Runtime 运行，见 [ADR · Runtime 与进程托管](./observer-runtime.mdx)。每个部署只有一个它的程序实例。
- 应用识别 Observer 处理当前理解中还没有归属的线索：交给 OpenAI 的模型判断，结果直接写成线索归属。模型认出新软件时，用自己范围内的依据新建产品。
- 重新判断时写新的线索归属，再写一份 Review 取代旧的。
- 每次写入后，它等后端保存了这一次写入再处理下一条线索。
- 每条线索归属说明谁负责，InputSet 列出判断时读到的版本，形成方式是推断。
- 用户否定一次判断，线索回到未归属。模型下一轮读到否定，跳过这个结论。

## 理由 [#rationale]

一款软件在一个平台上的跨设备线索通常是稳定的：QQ 在每台 Mac 上的应用包标识都是 `com.tencent.qq`。所以认识一次就够了，之后任何设备上出现这条线索，读取方查表即可得到产品。识别只发生在线索第一次出现时，模型的调用次数取决于用过多少种不同的应用，与使用时长无关。

用户要能看到每条线索是哪次判断认定的、依据是什么，线索归错时要能只否定这一条。所以一次判断一份 Observation。周一判断 `com.tencent.qq`、周三判断 `com.tencent.mobileqq` 是两次模型调用、两份依据，陈述的是两件事实，见 [IDENTITY-4](../core/rules/identity.mdx#identity-4)。

线索是事物，本机应用和线索归属都引用它，所以归属在引用图中，一条边就能从本机应用走到产品。

换了更强的模型时，新判断取代旧判断，新旧都保留，见 [ADR · 模型形成的理解](./understanding.mdx)。这也是当初只保留一条归属时做不到的。

应用识别 Observer 需要读取全部设备的数据，并保持一份全局一致的产品目录，所以它在服务器上运行，而且只有一个。它判断下一条线索之前必须读到上一次的结果，否则同一款软件的两条线索会各建一个产品。写入在业务代码等待时完成，所以下一次读取一定能读到。

模型的判断直接生效。逐条审核会让每个新应用都等待用户处理。

放弃的方案：

- **线索写在产品的数组中，每条线索形成产品的新版本。** 几次独立的判断合进一份 Observation，只能看版本之间的差别；否定一条线索要影响整个产品；写入前要读出产品、加上线索再写回。
- **一条线索只保留一条归属。** 换模型后旧判断没有地方保留，撤销只能删除，下一轮模型读不到否定。
- **在产品和本机应用之间加一层平台发行。** 当前的需求只按产品聚合，没有视图需要区分同一产品在各平台上的发行。平台可以从线索的 scheme 看出。
- **为每个本机应用保存一条归属。** 每台设备的每个安装都要写一次，两台 Mac 上的同一个应用也要分别写；用户的一次改正要改很多份。线索已经足以决定归属，所以归属按线索建立。
- **为每次判断保留候选和置信度。** 模型自报的概率不可比，需要时放在业务字段中。
- **在设备上运行。** 设备的客户端不运行时不识别；设备离线时，写入要等很久才能保存，下一条线索也要跟着等。
- **允许模型联网查资料。** 要保存查到的外部资料作为依据，费用也更高。常见软件模型已经认识，不认识的保持未归属，由用户处理。

## 代价 [#costs]

- 读取方要取当前理解，多一步排除被否定和被取代的判断。
- 应用识别 Observer 的 InputSet 同时列出目录中的产品、线索归属和否定。
- 跨设备线索相同的两个应用只能属于同一个产品，例如开发中使用同一个应用包标识的两个临时构建。
- 没有跨设备线索的本机应用不属于任何产品，例如只读到可执行文件路径的安装。
- 应用识别 Observer 依赖 OpenAI：需要 API Key 并产生费用，未配置时不识别新线索。
- 本机应用的名称、标识线索（包括可执行文件路径）和产品目录会发送给 OpenAI，发送的内容见 [Application Identity · 模型](../observers/application-identity/index.mdx#model)。
- 只能运行一个应用识别 Observer，扩展时需要另行设计。
- 服务器上要运行 Runtime，并保留它的持久目录。
