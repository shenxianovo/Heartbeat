title: "删除"
description: "删除以实体为单位，只移除选中实体的全部版本，删除后不可复活"
---

## 背景 [#context]

Orisumi 保留每个版本用于追溯，用户也要能删除自己的数据。需要划清删除移除什么、留下什么，以及被删的内容还被引用时怎么办。判断错了时用否定，删除只用于用户要抹掉的数据，见 [ADR · 模型形成的理解](./understanding.mdx)。

程序可能还持有已删除实体的 EntityId。删除后如果还能写入，这些请求会把删掉的数据重新建出来。

## 决定 [#decision]

- 删除以实体为单位，移除这个实体全部版本的内容和它的识别依据。
- 删除只作用于选中的实体。引用它的其他版本保留引用，读取时报告目标不可读取。
- 删除的实体不再接受新版本，重放旧版本也不能恢复它。EntityId 和 VersionId 不再分配。
- 被删除的内容不留副本。不再有版本使用的二进制内容同时移除，见 [ADR · 二进制内容](./binary-content.mdx)。
- 仍有事物或 Observation 使用某个 EntitySchema 时，不能删除这个 EntitySchema。
- 删除受管理的程序实例时，同时结束它的管理登记；还没写入过的程序实例也可以删除，它的 EntityId 之后不能再使用。

## 理由 [#rationale]

“版本不可改写”和“用户可以删除”两条要求可以同时满足：前者禁止替换内容，后者让内容不可读。用户删除数据的权利优先于追溯。

只删除一个版本，还要决定版本链断开后当前版本是谁，目前没有这样的需求。

删除后不可复活，离线补发才撤销不了删除。

其他实体中的推断、摘要或引文会保留下来，用户要删除它们时逐个选择。

Schema 还有数据依赖时不能删除，保留的数据才能按原定义解释。

程序实例的身份在它第一次写入之前就由 Runtime 分配。用户删除这样的实例，是要它以后不再以这个身份写入，所以它的 EntityId 和已删除的实体一样不能再使用。

放弃的方案：

- **删除后允许以同一个身份重建。** 离线补发的旧请求会撤销删除。
- **软删除，保留内容并标记删除。** 删除的数据仍然留在系统中。
- **删除时沿引用连带删除。** 会删掉用户没有选择的数据。
- **为追溯在别处保留副本。** 违背用户的删除。

## 代价 [#costs]

- 输入被删除后，依赖它的观测无法完整追溯。
- 删除一种类型的全部数据需要两步。
- 被删除的身份永久不能再用。删除身份的保存、查询和空间回收由存储设计决定。
