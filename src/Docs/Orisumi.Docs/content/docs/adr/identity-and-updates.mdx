title: "身份、时间与更新"
description: "业务规则决定身份和粒度，每个版本有自己的保存时间，更新形成新版本，独立的陈述形成新观测"
---

## 背景 [#context]

观测可能在事实进行中形成，随后不断延长；填错的边界或时区需要纠正。两个 Observer 可能读到同一条来源数据，来源还可能缺少时间。

没有统一规则，同一个事实会重复保存，旧值会被覆盖，读取方也分不清“同一实体的更新”和“另一份观测”。

## 决定 [#decision]

- 业务规则决定实体身份和粒度。
- 事实时间未知时保持未知。
- 后端在首次保存每个版本时赋值保存时间。
- 同一实体的更新形成新版本。新版本可以补全，也可以纠正。
- 独立的陈述形成新的 Observation，包括用另一种方法对同一份证据的独立解释。修复错误后的纠正形成原 Observation 的新版本。Observation 的后续版本由同一个 Observer 形成。
- 一份 Observation 只有一个作者，写入按到达顺序接在当前版本之后。其他作者写同一份识别依据时，内容相同什么都不做，内容不同就拒绝。
- 识别依据全局有效。各说各的内容把作者放进 `scope`。
- 来源保留历史的类型声明内容不再变化：同一个描述版本写来不同内容时拒绝，描述版本变了算纠正。

## 理由 [#rationale]

只有业务规则能说明来源的含义，例如两次读数之间应用是否一直在前台。后端按内容合并或拆分，会把巧合当成同一个事实。

保存时间回答“后端什么时候保存了这一版”。实体首次保存的时间就是首版的保存时间。

旧版本已经保留，禁止纠正不能进一步保护历史，只会逼写入方删除重建或绕开模型。所以新版本可以延长时段，也可以修正错误，只需自身合法。

纠正不改变责任归属。Observer 只更新自己的观测；别人的确认、否定和模型的独立解释都是新的 Observation。

重读和程序升级本身不决定观测的身份。例如把工具结果误记成用户发言，修复后重读，陈述的还是原来那件事，所以纠正原来的观测；换一个模型重新评价当天的活动，是一次新的判断，所以形成新的观测。

一条版本链让当前版本唯一。

识别依据全局有效，重装后的新实例重读日志时，内容相同什么都不发生，数据不会翻倍；两个作者的内容不同时会被拒绝，身份冲突也就能发现。同一个作者内部的冲突靠声明内容不再变化发现。Codex 早期的 `item-N` 只在一个会话内唯一，曾让 104 个会话的同名交互合并成一个实体，写入都成功了，没有任何提示。

修复解析错误后重读也要能纠正，所以按描述版本区分：程序没变时内容不同是身份冲突，程序变了是纠正。

放弃的方案：

- **后端按内容去重或合并。** 内容相同不说明是同一次观测，内容从 A 改成 B 再改回 A 也有独立意义。
- **用其他时刻填补未知的事实时间。** 读取方会分不清“确实在这一刻”和“不知道是什么时候”。
- **已保存的观测只能单调补全。** 历史已由版本保留，这条限制只会阻止纠正。
- **按客户端时间戳决定当前版本。** 时钟不同步时，晚到的旧写入会覆盖新内容。
- **在 Core 中定义纠正和撤回操作。** 纠正就是新版本，撤回是另一个 Observer 的否定或用户的删除。

## 代价 [#costs]

- 需要沿用的 EntityId 必须持久保存，例如程序实例和进行中的时段。
- 同一个作者写入的旧内容后到时，会成为当前版本。重发被拒绝的写入时要注意这一点。
- 当前内容可能被纠正，需要当时的内容时按版本读取。
