开头用一两段话说明这个 Observer 记下什么事实、从哪个来源读取，以及它负责的范围。本页的结构图借用 [Input Events](../../input-events/index.mdx) 的节点，实际写作时换成自己的节点。

## 实体 [#entities]

| 实体 | 资源名 | 说明 |
| --- | --- | --- |
| [Example Entity](./example-entity.mdx) | 待定 | 这种业务类型表达什么 |

每行是一种已定义的业务类型，链接到它的实体页。还没定义 EntitySchema 的实体列在“待定”中。

## 程序实例 [#instance]

写程序实例的身份怎样生成和保存、重启后怎样沿用、什么情况算独立的实例。设备身份和业务实体的身份写在对应的实体页。

## 采集 [#collection]

写读取的触发方式（事件、定时采样或启动时读取）、需要的授权，以及读取失败、暂停和恢复时怎样处理。一个 Observer 形成多种观测内容时，写清它们共用的读取流程，以及各自何时更新。

用户可以调整的设置作为本章的小节，写明默认值和作用，例如 [Input Events · 具体按键记录](../../input-events/index.mdx#key-recording)。

## 事实时间 [#fact-time]

| 观测内容 | 事实时间 |
| --- | --- |
| Example Entity | 时间点还是时段，各边界取自哪个来源字段 |

细节写在实体页。不作为观测内容的业务实体没有事实时间，这里不用列出。

## 提交 [#submission]

写接入时登记哪些 EntitySchema，选择及时提交还是结束后提交，以及业务代码何时通知更新和结束。本地保存、重试和幂等的规则链接到 [Submission](../../submission/index.mdx) 和所用平台的 SDK。

## 实现 [#implementation]

写各平台的实现状态、程序所在的目录和对应的测试 Case。启动方式写在程序目录的 README 中。

## 待定 [#open]

- 逐项列出尚未确认的身份、采集、时间或提交规则。
