## 业务类型 [#types]

| 业务类型 | 用途 | 资源名 |
| --- | --- | --- |
| [Example Entity](./example-entity.mdx) | 这种业务类型在当前观测中的作用，例如程序实例自身、被引用的实体或观测内容 | 待定 |

每行是一种已定义的业务类型，链接到它的业务类型页。还没定义 EntitySchema 的业务类型列在“待定”中。

## 程序实例 [#instance]

写程序实例怎样划分、身份怎样生成和保存、重启或升级后怎样沿用、什么情况算独立的实例。程序实例的字段和 EntitySchema 写在它的业务类型页。

## 采集 [#collection]

写读取的触发方式（事件、定时采样或启动时读取）、读取的证据，以及读取失败、停止和恢复时怎样处理。一个 Observer 形成多种观测内容时，写清它们共用的读取流程，以及各自何时更新。读取已有数据做推断的 Observer，标题改为“处理”，写处理由什么触发、读取哪些数据。

用户可以调整的设置作为本章的小节，写明默认值和作用，例如 [Input Events · 具体按键记录](../../input-events/index.mdx#key-recording)。

## 事实时间 [#fact-time]

| 观测内容 | 事实时间 |
| --- | --- |
| Example Entity | 时间点还是时段，各边界取自哪个来源字段 |

完整的边界规则写在业务类型页。不作为观测内容的业务类型没有事实时间，这里不用列出。

## 提交 [#submission]

写接入时登记哪些 EntitySchema，选择及时提交还是结束后提交，是否写入观测草稿，以及业务代码何时通知更新和结束。本地保存、发送和重试的规则链接到 [Submission](../../submission/index.mdx) 和所用平台的 SDK。

## 实现 [#implementation]

写各平台的实现状态、程序所在的目录，以及由哪个客户端托管，见 [Clients](../../../clients/index.mdx)。各平台的业务相同时共用本页，平台之间的差异写在相关章节下。启动方式写在程序目录的 README 中。最后列出对应的测试 Case。

## 待定 [#open]

- 逐项列出尚未确认的身份、业务、平台或提交规则。
