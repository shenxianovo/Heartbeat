开头用一段话说明这种业务类型表示什么实体、在当前观测中起什么作用（程序实例自身、被引用的实体或观测内容），以及由哪个 Observer 形成。程序实例自身也用这份模板。本页的结构图借用 [Input Event](../../input-events/input-event.mdx) 的节点，实际写作时换成自己的节点。

## 粒度 [#granularity]

写什么构成一个实体，何时延续同一个实体，何时新建。用一个具体例子说明边界。更新和结束由业务代码判断。

## 身份 [#identity]

写怎样判断是同一个实体：依据哪些来源标识，标识在什么范围内有效，重启或重放时怎样处理。业务实体的身份与程序实例的身份分开写。

## 引用 [#references]

| 字段 | 目标 |
| --- | --- |
| `<角色>VersionId` | 引用的目标及其业务含义 |

字段名以 `VersionId` 结尾，见 [SCHEMA-8](../../../core/model/schema.mdx#schema-8)。没有引用时省略本节。

## 事实时间 [#fact-time]

写对应的 Observation 是时间点还是时段、边界取自哪里、未知的边界怎样表示、补全时怎样更新。不作为观测内容的业务类型省略本节，它的时间由引用它的 Observation 表达，见 [OBSERVATION-4](../../../core/model/observation.mdx#observation-4)。

## EntitySchema [#schema]

| 项目 | 值 |
| --- | --- |
| SchemaId | 稳定的 UUIDv7，未确定时写“待定” |
| 显示名称 | `displayName` |
| 说明 | `description`：业务事实、粒度和事实时间的取值，必须填写 |
| 资源名 | `resourceName`，未确定时写“待定” |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| 字段名 | `string` 等 | 是或否 | 是或否 | 含义、来源和省略的条件 |

引用和普通字段写在同一张表中，用类型 `reference` 区分。对象成员和数组元素逐项列出，数组元素的“必填”写“不适用”。每行的 `description` 都要随字段定义保存，说明业务含义，以及适用的单位、取值、来源、引用目标和空值含义，见 [SCHEMA-10](../../../core/model/schema.mdx#schema-10)。声明格式见 [EntitySchema · 字段约束](../../../core/model/schema.mdx#constraints)。
