本机应用表示某台设备上的一个应用安装，例如这台 Mac 上的 VS Code。它有自己的 EntityId，可以在任何观测之前就存在。[前台应用时段](./foreground-application-period.mdx)通过 `localApplicationVersionId` 引用它。

<ObserverStructure node="LOCAL_APPLICATION" />

## 粒度 [#granularity]

一个实体对应某台设备上的一个安装。识别安装靠平台提供的标识线索；同名的应用、不同设备上的同一款软件，都是不同的实体。

## 身份 [#identity]

在 macOS 上，前台状态 Observer 按应用包标识和可执行文件路径的原始值识别安装：两者都相同，就复用原来的身份。比较区分大小写，名称、路径别名和软件品牌都不参与判断。

| 变化 | 身份 |
| --- | --- |
| 应用名称变化 | 复用；新名称保存在观测内容中 |
| 应用退出后重新启动 | 复用 |
| 前台状态 Observer 重启或升级 | 复用，身份来自登记文件 |
| 应用原地升级 | 复用 |
| 在原路径卸载后重装，包标识相同 | 复用 |
| 应用移动，或可执行文件路径变化 | 新建 |
| 同一路径出现不同的包标识 | 新建 |
| 先只读到路径，之后读到包标识 | 新建 |
| 另一台设备上的相同安装 | 新建 |

读不到可执行文件路径时，只在前台状态 Observer 本次运行期间，按进程号、进程启动时间和包标识复用一个临时身份；进程或前台状态 Observer 重启后新建。连进程线索也读不到时，每次读数都新建身份。这些进程线索只用于识别，不写入业务实体。

识别时宁可多建身份。名称会随语言和版本变化，两个不同的安装也可能同名；多出来的身份按跨设备线索归到同一个[应用产品](../application-identity/application-product.mdx)，错误合并的身份却无法拆开。

### 登记文件 [#registry]

本机应用的登记文件保存原生线索到 EntityId 的映射，是这一映射的权威来源。它是 Runtime 共用数据目录中的 `local-applications.json`，见 [Runtime · 数据目录](../../hosting/runtime.mdx#data)；同一个 Runtime 中的多个程序实例共用它，与程序实例的身份分开保存。

- 登记文件只属于创建它的设备。
- 文件损坏时，前台状态 Observer 报告错误并保留原文件。
- 删除文件后，下次采集重新分配身份。
- 创建和更新文件时使用互斥锁和原子替换。

运行方式见 `src/Observers/Orisumi.Observer.ForegroundState/README.md`。

## 引用 [#references]

本机应用没有引用。两台 Mac 上的 VS Code 是两个本机应用，它们的应用包标识相同，所以属于同一个应用产品，见 [Application Identity · 归属](../application-identity/index.mdx#membership)。

## EntitySchema [#schema]

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-000000000002` |
| 显示名称 | 本机应用 |
| 说明 | 表示某台设备上的一个应用安装，保存用于识别安装的平台标识线索。 |
| 资源名 | `local-applications` |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| `identifiers` | `array` | 是 | 否 | 平台标识线索，顺序无意义；没有线索时为 `[]` |
| `identifiers[]` | `object` | 不适用 | 否 | 一项平台标识线索，由 scheme 和 value 共同解释 |
| `identifiers[].scheme` | `string` | 是 | 否 | 线索的种类：macos.bundle-id 是应用包标识，macos.executable-path 是可执行文件路径，android.package-name 是 Android 应用的包名 |
| `identifiers[].value` | `string` | 是 | 否 | 线索的原始值 |

应用的名称和图标随每段时段读取，保存在[前台应用时段](./foreground-application-period.mdx)中。

### 标识线索 [#identifiers]

每项线索由 `scheme` 和 `value` 共同解释。跨设备线索在任何设备上都指同一款软件的同一类安装，应用产品按它们归属；本机线索只在所在的设备上有意义。

| `scheme` | `value` | 作用范围 |
| --- | --- | --- |
| `macos.bundle-id` | 应用包标识，例如 `com.tencent.qq` | 跨设备 |
| `macos.executable-path` | 可执行文件路径 | 本机 |
| `android.package-name` | Android 应用的包名，例如 `com.tencent.mobileqq` | 跨设备 |

Android 上的前台状态 Observer 尚未实现，`android.package-name` 目前只出现在测试数据中。

## 示例 [#example]

首次读到 VS Code 时，`POST /versions` 中的本机应用首版。`schemaVersionId` 是本机应用 EntitySchema 的一个 Schema 版本：

```json title="POST /versions"
{
  "versions": [
    {
      "entityId": "01a12e31-9050-7000-8000-000000000001",
      "versionId": "01a12e31-9050-7000-8000-000000000101",
      "previousVersionId": null,
      "category": "business",
      "schemaVersionId": "019e1bbb-ec00-7000-8000-000000000102",
      "content": {
        "identifiers": [
          { "scheme": "macos.bundle-id", "value": "com.microsoft.VSCode" },
          {
            "scheme": "macos.executable-path",
            "value": "/Applications/Visual Studio Code.app/Contents/MacOS/Electron"
          }
        ]
      }
    }
  ]
}
```
