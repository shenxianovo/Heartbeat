Observer 把来源中发生的事变成观测。本分区按 Observer 组织：每个 Observer 一页，说明它负责什么、形成哪些业务类型、事实时间怎样取值；它下面的每一页说明一种业务类型。Observer 的身份和责任规则见 [Observer](../core/model/observer.mdx)。

程序实例通常由 Runtime 运行：设备上的 Runtime 由设备端客户端启动，服务器上的以服务方式运行，见 [Hosting](../hosting/index.mdx)。程序也可以直接运行，读写用的是同一组操作，见 [API · SDK](../api/sdk.mdx)。

## 前台、输入与设备的时间线 [#timelines]

前台状态、输入事件和设备状态三个 Observer 各有自己的程序实例身份，可以运行在同一个程序中。它们各有一条时间线，每条只依据自己的证据形成和补全。所以锁屏时，前台应用的时段照样延续，和锁屏的时段在时间上重叠。

这三条时间线记下的都是系统确认的状态。“用户是否活跃”是读取时的推断：例如要算“没锁屏时 VS Code 在前台多久”，读取方把前台时段和锁屏时段叠在一起计算。活跃的定义和无输入的阈值尚未确定。

读取失败、采集停止，或两次读数的间隔超过业务允许的范围时，各 Observer 按自己的规则在最后一次确认处结束当前的时段，具体边界见各自的业务类型页。没有读数的空白保持空白。
