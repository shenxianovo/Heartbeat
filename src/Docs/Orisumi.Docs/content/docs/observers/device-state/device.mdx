设备表示用户的一台设备，例如这台 Mac。它是一个普通的业务实体，可以在任何观测之前就存在：[本机应用](../foreground-state/local-application.mdx)引用它，表示应用安装在哪台设备上；[助手交互](../assistant-sessions/assistant-interaction.mdx)引用它，表示交互发生在哪台设备上。

这种业务类型由使用它的 Observer 共用，写在设备状态 Observer 下，是因为被观测的正是它。设备状态 Observer 尚未实现，其他 Observer 照样使用它。

## 粒度 [#granularity]

一个实体对应一台设备。同一台设备上的多个托管方共用这个实体：Mac 上的客户端 Runtime 和同一台 Mac 上的开发 Runtime，形成的本机应用引用同一个设备。

## 身份 [#identity]

设备的身份来自平台给出的稳定标识。Runtime 启动时读取它，放进[运行上下文](../../hosting/index.mdx#context)；用到设备的 Observer 启动时写入设备，后端按识别依据认出它。所以这台 Mac 第一次运行时设备就出现了，同一台 Mac 上的多个托管方得到同一个实体。

| 平台 | `scheme` | `value` |
| --- | --- | --- |
| macOS | `macos.hardware-uuid` | 硬件 UUID |
| Linux | `linux.machine-id` | `/etc/machine-id` 的内容 |

`scope` 为 `null`。托管方身份 `hostId` 和主机名都会变：重装客户端得到新的托管方，改名得到新的主机名，所以它们不代表设备。

| 变化 | 身份 |
| --- | --- |
| 设备改名 | 沿用，形成新版本 |
| 同一台设备上新接入一个托管方 | 沿用 |
| 重装客户端 | 沿用 |
| 重装 macOS | 沿用 |
| 重装 Linux | 新建，`/etc/machine-id` 重新生成 |
| 另一台设备 | 新建 |

设备的新版本不改变引用它的实体的身份，旧的引用仍指向当时的版本，见 [ENTITY-4](../../core/model/entity.mdx#entity-4)。

## 写入 [#writing]

设备不是观测内容，写入时不带 `time`。`name` 在 macOS 上取计算机名，在 Linux 上取主机名。同一台设备上的程序读到的内容相同，所以多个程序写入同一个实体时什么都不发生，改名后第一个启动的程序形成新版本。

## EntitySchema [#schema]

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-00000000000d` |
| 显示名称 | 设备 |
| 说明 | 表示用户的一台设备；设备改名时形成新版本。 |
| 资源名 | `devices` |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| `name` | `string` | 是 | 是 | 设备的名称，读不到时为 `null` |
| `platform` | `string` | 是 | 否 | 设备的平台：`macos`、`windows`、`android` 或 `linux` |
