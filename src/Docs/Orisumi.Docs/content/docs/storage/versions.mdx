---
title: "Versions"
description: "实体、版本和墓碑三张表：版本链怎样保存，内容怎样表示，删除时留下什么"
---

`versions` 保存每个版本的完整内容，是版本内容的权威位置。`entities` 由版本推导出每个实体的类型和当前版本，并记下删除的时刻；`version_tombstones` 记住已删除的版本。

## entities [#entities]

每个实体一行，包括已删除的实体。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `entity_id` | `uuid` | 实体的 EntityId |
| `category` | `text`，可空 | 实体的类别，删除后为 `NULL` |
| `schema_id` | `uuid`，可空 | 业务实体的 SchemaId；其他类别和删除后为 `NULL` |
| `resource_name` | `text`，可空 | EntitySchema 当前版本的 `resourceName`；其他类别和删除后为 `NULL` |
| `current_version_id` | `uuid`，可空 | 当前版本，删除后为 `NULL` |
| `deleted_at` | `timestamptz`，可空 | 删除的时刻，未删除时为 `NULL` |

| 约束或索引 | 内容 | 用途 |
| --- | --- | --- |
| `pk_entities` | `entity_id` | 按身份读取 |
| `ux_entities_resource_name` | `resource_name`，只含非空值 | 资源名不重复，见 [SCHEMA-5](../core/model/schema.mdx#schema-5) |
| `ix_entities_schema_id_entity_id` | `(schema_id, entity_id)` | 按业务类型列出实体；删除 EntitySchema 前检查 [HISTORY-9](../core/rules/history.mdx#history-9) |
| `ix_entities_category_entity_id` | `(category, entity_id)` | 按类别列出实体 |
| `ck_entities_deleted_state` | 检查约束 | `deleted_at` 为 `NULL` 时，`category` 和 `current_version_id` 不为 `NULL`；删除后，除 `entity_id` 和 `deleted_at` 外的列都为 `NULL` |

当前版本从 `current_version_id` 读取。

## versions [#versions]

每个未删除的版本一行。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `version_id` | `uuid` | 版本的 VersionId |
| `entity_id` | `uuid` | 所属的实体 |
| `ordinal` | `integer` | 在版本链中的序号，首版为 1，之后每版加 1 |
| `previous_version_id` | `uuid`，可空 | 同一实体的前一版本，首版为 `NULL` |
| `schema_version_id` | `uuid`，可空 | 业务内容所用的 Schema 版本，Core 类型为 `NULL` |
| `category` | `text` | 内容的类别 |
| `recorded_at` | `timestamptz` | 保存时间 |
| `content` | `jsonb` | 版本的内容，与 API 中的 `content` 相同 |

| 约束或索引 | 内容 | 用途 |
| --- | --- | --- |
| `pk_versions` | `version_id` | 按身份读取 |
| `ux_versions_entity_id_ordinal` | `(entity_id, ordinal)` | 每个实体只有一条线性的版本链，见 [VERSION-4](../core/model/version.mdx#version-4)；按链的顺序读取 |

`entity_id`、`previous_version_id`、`schema_version_id` 都有外键：版本属于已有的实体，前一版本和 Schema 版本仍然存在。按实体读取全部版本时，按 `ordinal` 从首版到当前版返回。

### 内容的表示 [#content]

- 版本的 `content` 以 `jsonb` 保存，空白和键的顺序不保留。字符串中不能有 `\u0000` 或无效的代理对，否则 API 返回 `400`。
- 数值以 `jsonb` 的 `numeric` 保存，`integer` 没有 64 位的上限。数值必须在 `numeric` 的范围内（小数点前最多 131,072 位，小数点后最多 16,383 位），超出时 API 返回 `400`。
- Observation 的时间在 `content` 中保存为以 `Z` 结尾、精确到微秒的字符串，与 API 读回的写法相同。列中的时间见 [PostgreSQL · 时间](./postgresql.mdx#time)。

## 删除 [#deletion]

第二天用户删掉浏览器的时段。删除一个实体时，在一个事务中：

1. 把它每个版本的 `version_id` 和 `entity_id` 写入 `version_tombstones`。
2. 删除它在 `current_observations`、`version_references` 和 `versions` 中的行。
3. 把 `entities` 中这一行除 `entity_id` 外的列置为 `NULL`，`deleted_at` 设为删除的时刻。

### version_tombstones [#version-tombstones]

每个已删除的版本一行。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `version_id` | `uuid` | 已删除版本的 VersionId，主键 `pk_version_tombstones` |
| `entity_id` | `uuid` | 它所属的实体，外键指向 `entities` |

墓碑只保存身份和删除时刻，永久保留，每个已删除的版本约占 60 字节。读取时，身份在墓碑中就返回 `410`，都不存在就返回 `404`。其他版本对被删版本的引用留在它们的 `content` 和 `version_references` 中，见 [HISTORY-8](../core/rules/history.mdx#history-8)。
