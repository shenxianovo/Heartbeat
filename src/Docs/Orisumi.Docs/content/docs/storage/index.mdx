---
title: "Overview"
description: "实体和版本怎样保存在 PostgreSQL 中：哪些表是权威，哪些由版本推导，以及共用的事务和命名"
---

实体和它的全部版本保存在 PostgreSQL 中。所有类别、所有业务类型的版本都在同一张 `versions` 表里，它是版本内容的权威位置；其他表记录身份和删除，或者由版本推导出来，供查询使用。这样设计的理由见 [ADR · 实体存储](../adr/entity-storage.mdx)。

观测草稿只暂存在后端进程的内存中，不写入 PostgreSQL，见 [API · Drafts](../api/drafts.mdx)。

## 例子 [#example]

16:00 VS Code 的前台时段结束，它和它的 Observation 都已保存：

| 表 | 这一段对应的行 |
| --- | --- |
| `versions` | 时段一行，Observation 一行 |
| `entities` | 时段一行，Observation 一行，各记着自己的当前版本 |
| `current_observations` | Observation 一行，记着当前版本的事实时间和观测内容的类型 |
| `version_references` | 时段对 VS Code 的引用一行；Observation 对程序实例和时段的引用各一行 |

第二天用户删掉浏览器的时段，它的版本从 `versions` 中移除，身份留在 `version_tombstones` 中。

## 表 [#tables]

| 表 | 每行 | 来源 | 见 |
| --- | --- | --- | --- |
| `entities` | 一个实体，包括已删除的 | 权威：身份与删除 | [Versions · entities](./versions.mdx#entities) |
| `versions` | 一个未删除的版本 | 权威：版本内容 | [Versions · versions](./versions.mdx#versions) |
| `version_tombstones` | 一个已删除的版本 | 权威：删除 | [Versions · 删除](./versions.mdx#deletion) |
| `current_observations` | 一份未删除的 Observation 的当前版本 | 由版本推导 | [Queries · 事实时间](./queries.mdx#fact-time) |
| `version_references` | 一个版本中的一个引用 | 由版本推导，可以随时重建 | [Queries · 引用方](./queries.mdx#references) |

按类型的查询都从以类型开头的索引进入，只读取目标类型的行，所以数据量大的类型不影响其他类型的查询。各表的约束和索引写在表所在的页中，名字的写法见[命名](#naming)。

服务端托管另外有三张表，它们不是 Core 的实体或版本，见 [Server Hosting](./server.mdx)。

## 事务 [#transactions]

- 每个操作在一个事务中完成，事务开始时取得一个固定键的事务级 advisory lock（`pg_advisory_xact_lock`）。所以多个 API 实例之间，所有读写都串行执行。
- 一次提交在一个事务中完成，每个版本在自己的保存点中保存。某个版本被拒绝时，回滚到它的保存点，提交此前已保存的版本，再返回错误，见 [VERSION-13](../core/model/version.mdx#version-13)。出现异常或请求取消时，整个事务回滚。
- 保存一个版本时，`versions` 的新行、`entities` 的当前版本、Observation 的 `current_observations`，以及这个版本的 `version_references`，在同一个保存点中写入。

## 命名 [#naming]

同一个名字在三处使用三种写法：

| 位置 | 格式 | 示例 |
| --- | --- | --- |
| API 字段 | `camelCase` | `observerVersionId` |
| C# 属性 | `PascalCase` | `ObserverVersionId` |
| 表名、列名、约束名、索引名 | `snake_case` | `observer_version_id` |

约束和索引按下表命名：

| 约束或索引 | 规则 | 示例 |
| --- | --- | --- |
| 主键 | `pk_<表名>` | `pk_versions` |
| 外键 | `fk_<表名>_<目标表>_<列名>` | `fk_versions_entities_entity_id` |
| 检查 | `ck_<表名>_<内容>` | `ck_entities_deleted_state` |
| 唯一索引 | `ux_<表名>_<列名>` | `ux_entities_resource_name` |
| 普通索引 | `ix_<表名>_<列名>` | `ix_entities_schema_id_entity_id` |

## 数据量 [#volume]

导入约 230 万条键鼠事件和 25 万条前台时段时，按每条一个观测内容加一份 Observation 估算：

| 项目 | 估算 |
| --- | --- |
| 版本 | 约 510 万行 |
| 实体 | 约 510 万行 |
| `current_observations` | 约 255 万行 |
| `version_references` | 约 535 万行：每份 Observation 引用程序实例和观测内容，每个前台时段引用本机应用 |
| 连同索引的空间 | 约 5 GB，其中 `version_references` 约 1 GB |

单个 Observation 版本的 `content` 约 260 字节，主要是三个以字符串保存的 VersionId 和两个时间。

2026-10-25 在本机实测：API 为 Debug 构建并开启遥测，每次提交 1,000 个键鼠事件规模的版本，保存速度约 275 个版本/秒；10 万个版本连同索引约 79 MiB。按这个速度，导入上表的数据约需 5 小时，空间按同样的比例估算。
