[服务端托管](../hosting/server.mdx)为它运行的程序实例另外保存三张表。它们不是 Core 的实体或版本，API 不读取它们。

例如应用识别 Observer 在 `server_observers` 中有一行，绑定它的程序实例；它正在提交的产品版本在 `server_observer_submissions` 中，模型回答未知的线索在 `server_observer_state` 中。

## server_observers [#server-observers]

每个程序实例一行，是它的管理记录，第一次运行时创建。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `entity_id` | `uuid` | 程序实例的 EntityId，主键 |
| `observer_key` | `text` | 程序实例的稳定标识，例如 `application-identity`，唯一 |

## server_observer_submissions [#server-observer-submissions]

每个程序实例最多一行，是它的未决提交。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `entity_id` | `uuid` | 程序实例的 EntityId，主键，外键指向 `server_observers` |
| `payload` | `jsonb` | 按顺序排列的版本，每个版本的写法与 API 提交的版本相同 |

写入时已有一行就报错，旧的批次不被覆盖。批次得到明确的结果，全部保存或某个版本被拒绝，这一行随之删除；出现异常或取消时保留，下次用相同的 VersionId 和内容重发。

## server_observer_state [#server-observer-state]

每个程序实例最多一行，是它的业务状态。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `entity_id` | `uuid` | 程序实例的 EntityId，主键，外键指向 `server_observers` |
| `payload` | `jsonb` | 业务代码定义的状态，每次整体替换 |

应用识别 Observer 在这里保存未知的线索，见 [Application Identity · 识别](../observers/application-identity/index.mdx#identification)。

## 事务 [#transactions]

这三张表的读写不在实体的事务中：未决提交在保存版本之前写入，在结果确认之后删除，所以中途退出时版本可能已保存、未决提交仍在，重发时由 [VERSION-7](../core/model/version.mdx#version-7) 确认。
