`observations` 和 `version_references` 是投影，保存版本时在同一个保存点中写入，可以随时重建，见 [Overview · 重建](./index.mdx#rebuild)。前者支持 [API · 按事实时间查询](../api/reading.mdx#observations)，后者支持 [API · 引用方](../api/reading.mdx#referrers)。

## 事实时间 [#fact-time]

晚上推断 Observer 读取当天的前台时段，查询落在 `observations` 上。

### observations [#observations]

每份未删除的 Observation 一行，对应它的当前版本。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `entity_id` | `uuid` | Observation 的 EntityId，主键 `pk_observations` |
| `version_id` | `uuid` | 它的当前版本 |
| `content_schema_id` | `uuid`，可空 | 观测内容的 SchemaId；观测内容已删除时为 `NULL` |
| `fact_range` | `tstzrange`，可空 | 用于时间查询的事实时间范围 |

| 约束或索引 | 内容 | 用途 |
| --- | --- | --- |
| `fk_observations_entities_entity_id` | 外键指向 `entities` | Observation 未删除 |
| `ux_observations_version_id` | `version_id`，外键指向 `versions` | 当前版本存在 |
| `ix_observations_content_schema_id_fact_range` | GiST `(content_schema_id, fact_range)` | 按观测内容的类型和事实时间查询 |
| `ix_observations_fact_range` | GiST `(fact_range)` | 不限类型的事实时间查询 |

多列 GiST 索引需要 `btree_gist` 扩展，由 Initial migration 创建。

- `content_schema_id` 在保存版本时从观测内容所属的实体读取。
- 观测内容被删除、Observation 保留时，`content_schema_id` 置为 `NULL`。这份 Observation 仍按事实时间匹配不限类型的查询，不再匹配原内容类型的查询；重建得到同样的结果。Observation 的 `contentVersionId` 保持原样，见 [HISTORY-8](../core/rules/history.mdx#history-8)。
- Observation 自身删除时，移除这一行。

### 换算与查询 [#fact-range]

原始的 `startAt`、`endAt` 和 `timeZone` 保存在 Observation 的 `versions.content` 中，`fact_range` 只是从它们换算出的查询值：

| `startAt` | `endAt` | `fact_range` |
| --- | --- | --- |
| `t1` | `t2`，`t1 < t2` | `[t1, t2)` |
| `t` | `t` | `[t, t]` |
| `t` | `null` | `[t, t]` |
| `null` | `t` | `[t, t]` |
| `null` | `null` | `NULL` |

只知道一个边界时，把它当作时间点；两个都未知时不参与时间查询。未知的边界不表示无限延伸，原来哪个边界未知，仍从版本内容中读出。

按事实时间查询 `[from, to)` 时，条件是 `fact_range && tstzrange(from, to, '[)')`，结果与 API 的匹配规则一致。结果按 `lower(fact_range)` 和 `entity_id` 排序，分页游标记录这两个值。

## 引用方 [#references]

从 VS Code 找相关的数据时，查询落在 `version_references` 上。引用只保存在引用方的版本中（[ENTITY-8](../core/model/entity.mdx#entity-8)），权威位置是 `versions.content`；`version_references` 只记下哪个版本引用了哪个实体。

### version_references [#version-references]

一个版本的 `content` 中至少有一个引用指向某个实体时，这一对一行。同一个版本多次引用同一个实体，只有一行。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `target_entity_id` | `uuid` | 被引用的实体 |
| `version_id` | `uuid` | 保存引用的版本 |

| 约束或索引 | 内容 | 用途 |
| --- | --- | --- |
| `pk_version_references` | `(target_entity_id, version_id)` | 按目标实体列出引用方，按引用方的版本分页 |
| `ix_version_references_version_id` | `version_id`，外键指向 `versions`，级联删除 | 引用方版本删除时移除它的行 |

`target_entity_id` 没有外键。目标删除后，其他版本对它的行保留，见 [HISTORY-8](../core/rules/history.mdx#history-8)。

### 写入 [#reference-rows]

- 保存一个版本时，后端按 Core 类型的引用成员，或者按它的 Schema 版本中 `type` 为 `reference` 的位置（[SCHEMA-2](../core/model/schema.mdx#schema-2)），找出 `content` 中每个非空的引用，按目标所属的实体去重后写入。目标保存时一定未被删除（[ENTITY-6](../core/model/entity.mdx#entity-6)），所以写入时总能读到它所属的实体。
- 当前版本和历史版本的引用都写入，所以既能只看当前版本，也能看全部版本。
- 版本的 `previousVersionId` 和 `schemaVersionId` 已经是 `versions` 的列，不写入这张表。

### 读取一页 [#reference-reads]

1. 按 `target_entity_id` 取出一页引用方版本，按 `version_id` 排序，游标记录最后一个 `version_id`。只看当前版本时，再要求 `version_id` 是引用方实体在 `entities` 中的 `current_version_id`。所以引用同一实体不同版本的版本一起返回，见 [ENTITY-7](../core/model/entity.mdx#entity-7)。
2. 读出这一页版本的 `content`，按每个版本的 Core 类型或它的 Schema 版本枚举全部引用，得到每个引用的位置和目标版本。数组元素的位置按保存的数组下标，例如 `/content/members/3`。
3. 把这一页全部的目标版本一次查出所属的实体：未删除的从 `versions` 读，已删除的从 `deleted_versions` 读。
4. 每个版本只返回目标属于查询实体的位置，得到 API 中的 `path` 和 `targetVersionId`。

第 2 到 4 步按一页批量完成，查询次数与一页的版本数无关。
