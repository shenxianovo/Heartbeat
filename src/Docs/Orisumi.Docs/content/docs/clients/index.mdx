用户通过客户端使用 Orisumi。[Web 控制台](./web.mdx)在浏览器中读取和追溯全部记录；设备端客户端常驻在一台设备上，运行这台设备上的 Observer，并展示它们最近记下了什么。两者都通过 [API](../api/index.mdx) 访问后端，也都能管理任何一台设备和服务器上的 Observer，见[管理](#management)。

客户端只托管 Observer，陈述由形成它的 Observer 负责，见 [OBSERVER-6](../core/model/observer.mdx#observer-6)。所以 Observation 的 Observer 仍是各个程序实例，记录中不出现客户端。这样分工的理由见 [ADR · 设备端客户端](../adr/device-client.mdx)。

## 平台 [#platforms]

| 客户端 | 类型 | 状态 |
| --- | --- | --- |
| [Web](./web.mdx) | 浏览器 | 已实现 |
| [macOS](./macos.mdx) | 设备端 | 已实现：经 Runtime 托管，附带前台状态 Observer；官方目录尚未托管 |
| Windows | 设备端 | 规划中 |
| Android | 设备端 | 规划中 |

## 设备端客户端 [#device]

设备端客户端托管本机的 Observer：安装、更新和卸载，启用和停用，故障后重启，显示运行和发送状态，管理设置和登录时启动。每个平台的客户端用原生界面编写。

例如用户在 macOS 上装好客户端，附带的前台状态 Observer 随即开始记录 VS Code 在前台的时段。用户晚上停用它，当前时段结束于最后一次确认，还没发送的时段继续上传；第二天再启用，它以原来的身份接着记录，停用期间是空白。

客户端启动一个 [Runtime](../hosting/runtime.mdx)，Runtime 运行各 Observer 的进程，本地保存它们交来的数据并发送到后端。客户端向 Runtime 发出指令，从 Runtime 读取状态和数据：

```mermaid
flowchart LR
  C[客户端] -->|管理与读取| R[Runtime]
  R -->|启动与停止| O1[前台状态 Observer]
  R -->|启动与停止| O2[其他 Observer]
  O1 -->|本地交接| R
  O2 -->|本地交接| R
  R -->|提交| B[后端]
  R -->|读取| B
  click C "/clients/macos"
  click R "/hosting/runtime"
  click O1 "/observers/foreground-state"
  click O2 "/observers"
  click B "/api"
```

Observer 停下的原因有停用、卸载、更新、崩溃和退出客户端。每一种情况下，程序实例的身份、设置和本地数据都保留，再次运行时沿用。已经交给 Runtime 的版本由 Runtime 发送，发送只取决于 Runtime 是否在运行，见 [Hosting · 流程](../hosting/index.mdx#flow)。各种情况的区别写在下面各节中。

### 安装与卸载 [#install]

客户端列出官方目录中适用于本机的 Observer，用户选择后安装。随客户端附带的 Observer 在客户端第一次启动时安装，之后和其他 Observer 一样管理。安装包的格式和安装步骤见 [Packages](./packages.mdx)。

Observer 安装后直接开始采集。

卸载移除 Observer 的程序，后端已保存的记录不受影响。用户卸载了附带的 Observer，客户端之后启动或升级时不会把它装回来。重新安装后，Observer 直接开始采集。

### 启用与停用 [#enable]

每个 Observer 单独启用和停用，互不影响。

停用的 Observer 停止采集，程序保留。当前进行中的事实按这个 Observer 停止采集时的规则结束，例如前台时段结束于最后一次确认，见 [Foreground State · 采集](../observers/foreground-state/index.mdx#collection)。停用期间没有读数，记录中是空白。

启用状态跨客户端重启保持。本机离线时，启用和停用立即生效，联网后同步到后端，见[管理](#management)。

### 更新 [#updates]

官方目录中有新版本时，客户端提示用户，用户确认后才安装。新包下载并校验完之后，旧版本才停止，切换到新版本。准备新包失败时，旧版本继续运行。

更新保留启用状态：更新前在采集的 Observer，更新后继续采集；停用的保持停用。新版本切换后无法启动时，客户端显示错误，不自动退回旧版本，因为新版本可能已经改写了业务数据。

### 故障恢复 [#recovery]

Observer 意外退出后，Runtime 自动重启它，最多三次。仍然失败时，客户端显示错误，并提供重试的入口。只有用户启用的 Observer 会被重启。次数、间隔和计数的清零见 [Runtime · 重启](../hosting/runtime.mdx#restart)。

一个 Observer 的故障只影响它自己。Runtime 本身意外退出时，客户端重新启动它。

### 发送 [#sending]

客户端按 Observer 显示待发送的数量和被拒绝的原因，见 [Submission · 发送状态](../hosting/submission.mdx#status)。被拒绝的版本由 Observer 的业务代码在它运行时处理，见 [Submission · 被拒绝的版本](../hosting/submission.mdx#rejections)；是否启用 Observer 始终由用户决定。

### 运行与退出 [#lifecycle]

桌面客户端关闭窗口后，继续在菜单栏或系统托盘中运行，采集和发送照常进行。

退出客户端时，Runtime 先让所有 Observer 停止采集，再停止发送，见 [Runtime · 退出](../hosting/runtime.mdx#shutdown)。待发送的数据留在本地。下次启动时，客户端运行退出前启用的 Observer，并继续发送。

### 最近的数据 [#today]

客户端为每个 Observer 显示运行和发送状态，以及最近的 Observation，包括还没发送的部分。数据经 Runtime 读取，见 [Protocol · 读取](../hosting/protocol.mdx#reading)。Observer 停用或崩溃后，数据仍可读取。

Observer 的专用视图用原生界面写在客户端中，随客户端发布，例如前台状态 Observer 的今日时间线，见 [macOS · 今天的前台应用](./macos.mdx#today)。新安装的 Observer 没有专用视图时，客户端显示它的状态和最近的数据。专用视图负责这种业务的统计和展示，它出错不影响采集和发送。

API 不可用时，客户端显示本地的数据，并标明可能不完整。

更早的日期和追溯在 Web 控制台中查看，客户端提供入口。

## 管理 [#management]

每个客户端都能管理全部的 Observer，按托管方分组：每台设备和每台服务器上的 Runtime 是一组。例如用户在 Mac 的设置里能看到服务器上的应用识别 Observer，停用它；在 Web 中能看到 Mac 上的前台状态 Observer 有多少待发送的数据。

| 功能 | 行为 |
| --- | --- |
| 查看 | 每个程序实例的名称、安装的版本、启用、运行和发送状态 |
| 启用、停用、修改设置 | 本机的修改离线时立即生效；远程的托管方离线时，配置保存在后端，等它连接后执行 |
| 安装、更新、卸载、重试 | 本机随时可用；远程的托管方必须连接着，离线时入口不可用。安装和更新只列出适用于目标平台的安装包 |
| 删除实例 | 永久结束程序实例的身份，见下文 |
| 接入、移除托管方 | 用配对码接入一台设备或服务器；移除时撤销它的访问 |

同步的规则见 [Hosting · Management](../hosting/management.mdx)：只同步改动的字段，同一字段以后端最后接受的修改为准，设置整体替换。

### 显示 [#management-display]

客户端把配置、同步、运行和连接分开显示，取值见 [Hosting · 状态报告](../hosting/management.mdx#status)：

- 远程停用一个离线设备上的实例，显示“已请求停用，等待设备同步”；收到它已停止的报告后，才显示“已停止”。
- 托管方没有连接时，运行状态显示为未知，并写出最近一次报告的时刻。
- 远程的安装、更新、卸载和重试没有收到明确结果时，显示“结果未确认”，并重新读取实例的状态，不自动重发。

### 删除实例 [#removal]

卸载只移除程序，身份、设置和待发送的数据都保留，重装后沿用。删除实例永久结束程序实例：后端删除它的实体和全部版本，它以前形成的 Observation 和其他实体保留，需要删除时由用户另外选择。在实体页删除一个程序实例的实体，效果相同。

删除后，界面分别显示“已删除”和“已停止”：离线的设备在下次连接时才停止。它还没发送的版本仍会发送，不能保存的部分在发送状态中写出原因。用户之后再安装同一个 Observer，客户端说明这是一个新的程序实例，见 [Packages · 删除实例](./packages.mdx#removal)。

### 接入与移除 [#pairing]

用户在客户端中为新设备签发配对码，在新设备的客户端中输入它；服务器在启动 Runtime 时使用它，见 [Hosting · Server](../hosting/server.mdx#pairing)。配对码 10 分钟内有效，只能用一次。

移除托管方撤销它的访问，它已保存的数据和实例的登记都保留。离线的设备要等下次连接时才知道已被移除，这之前它仍在本地采集。之后要让它回来，为它签发重新接入的配对码，它沿用原来的身份和本地数据。

管理入口的认证尚未决定，见 [API · 认证与授权](../api/index.mdx#auth)。

## 待定 [#open]

- 官方目录和安装包的托管位置；各平台的签名与分发验证。
- 后端删除或修复数据后，本地的数据怎样显示。
- 系统权限的引导、用户登录、本地数据的清理。
- 设置里换了 API 地址、数据目录不变时，数据目录里待发送的版本怎样处理。
- 管理入口的认证，计划接入 OAuth。
- Android 上 Observer 怎样安装、在后台运行、与客户端通信。
