每个 Observer 以安装包发布，由 [Runtime](../hosting/runtime.mdx) 安装，设备和服务器上相同。本页写安装包里有什么、官方目录怎样列出它们，以及 Runtime 怎样安装、更新和卸载。为什么用这种方式，见 [ADR · 设备端客户端](../adr/device-client.mdx)。

## 安装包 [#package]

安装包是一个普通的 ZIP，每个操作系统和架构一个。解压后的根目录是清单、可运行的入口和可选的资源：

```text
foreground-state-0.1.0-osx-arm64.zip
  observer.json
  bin/
    Orisumi.Observer.ForegroundState
  assets/
```

包中是能直接在目标设备上运行的完整产物，包括 Observer 自己语言的运行库，例如 .NET 的自包含发布。Runtime 随客户端发布，在服务器上单独安装，安装包中不带它。安装时不执行包中的脚本，也不调用语言的包管理器。

第一版的安装包不带专用视图，专用视图写在客户端中，见 [Overview · 最近的数据](./index.mdx#today)。

## 清单 [#manifest]

`observer.json` 说明这个包是什么、在哪里运行、怎样启动：

```json
{
  "format": 1,
  "id": "foreground-state",
  "name": "Foreground State",
  "version": "0.1.0",
  "target": "osx-arm64",
  "protocol": 1,
  "entry": "bin/Orisumi.Observer.ForegroundState"
}
```

| 字段 | 含义 |
| --- | --- |
| `format` | 清单的格式版本，目前是 `1` |
| `id` | 安装包的标识，安装和更新用它找到同一个包 |
| `name` | 显示的名称 |
| `version` | 包的版本，三段数字，例如 `0.1.0` |
| `target` | 目标操作系统和架构，用 .NET 的 RID 表示，例如 `osx-arm64`、`osx-x64`、`linux-x64` |
| `protocol` | 入口使用的 [Observer 管道](../hosting/protocol.mdx#observer-pipe)协议版本，目前是 `1` |
| `entry` | 入口在包中的相对路径。Runtime 直接执行它 |
| `scope` | 可选。`deployment` 表示每个部署最多一个实例，见 [Management · 每个部署一个实例](../hosting/management.mdx#singleton)；省略时为 `host`，每个 Runtime 一个实例 |

Runtime 只安装 `format` 和 `protocol` 都是它支持的版本、`target` 是本机平台的包。

清单是安装协议的数据，不作为实体保存。安装包的 `id`、程序实例的 EntityId 和 SchemaId 是三种不同的标识：同一个安装包在两台设备上各有一个程序实例；程序实例的程序版本写在它的业务版本中，例如 [Foreground State Observer](../observers/foreground-state/foreground-state-observer.mdx)。

## 官方目录 [#catalog]

官方目录是一个通过 HTTPS 读取的静态 JSON，每个安装包的每个平台一项：

```json
{
  "packages": [
    {
      "id": "foreground-state",
      "name": "Foreground State",
      "description": "记录前台应用的时段",
      "version": "0.1.0",
      "target": "osx-arm64",
      "format": 1,
      "protocol": 1,
      "url": "https://example.invalid/foreground-state-0.1.0-osx-arm64.zip",
      "sha256": "…"
    }
  ]
}
```

- `url` 指向一个不再改变的文件：同一个版本和平台的安装包发布后不再替换。
- `sha256` 是 ZIP 的摘要，Runtime 用它确认下载的内容就是目录中列出的那一份。
- `format` 和 `protocol` 与清单中的相同，省略时为 `1`。Runtime 据此在下载前判断能否安装。

客户端只从官方目录和附带的安装包安装，用户不能输入任意的 ZIP 或下载地址。官方目录的托管位置尚未确定，见 [Overview · 待定](./index.mdx#open)。

## 安装 [#install]

1. Runtime 把 ZIP 下载到临时目录，核对 SHA-256。下载最长 5 分钟。
2. 读取清单，检查格式、协议和平台。
3. 解压到 `packages/<id>/<version>/`。ZIP 最大 256 MiB，解压后合计最大 1 GiB；符号链接和路径超出这个目录的条目让安装失败。
4. 写入安装登记。第一次安装时，为它生成程序实例的 EntityId 和实例目录。
5. 启用并启动这个 Observer。

任何一步失败，安装登记不变，这个版本不会运行。

## 更新 [#update]

1. 用户确认后，Runtime 按[安装](#install)的前三步准备新版本，这期间旧版本照常运行。准备失败时，旧版本继续运行。
2. 新版本准备好后，Runtime 停止旧版本的进程，在安装登记中切换到新版本。
3. 原来启用的，用新版本启动。

身份、设置和实例目录都不变。新版本无法启动时，Runtime 报告故障，不切回旧版本。

Runtime 在切换登记之前退出时，下次启动读到的仍是旧版本的登记；没有登记的版本目录不会启动。

## 卸载与重装 [#uninstall]

卸载时，Runtime 停止进程，删除这个包的程序文件，在登记中标记为未安装。程序实例的身份、设置和实例目录保留，见 [Clients · 设备端客户端](./index.mdx#device)。

重新安装同一个 `id` 的包时，Runtime 从登记中找回原来的程序实例，Observer 沿用身份和设置，直接开始采集。

## 删除实例 [#removal]

删除实例永久结束程序实例的身份，与卸载不同，见 [Management · 删除实例](../hosting/management.mdx#removal)。Runtime 停止它的进程，删除程序文件，在登记中标记实例已删除。之后安装同一个 `id` 的包，要显式新建实例：Runtime 生成新的 EntityId 和实例目录，从[安装](#install)的第四步开始，旧实例目录保留到它的版本发送完。

## 附带的 Observer [#bundled]

客户端附带一组安装包，放在 Runtime 的 `--bundled` 目录中。Runtime 启动时，安装其中还没有登记过的包，安装步骤与官方目录中的相同，只省略下载。

已经登记过的包，包括用户卸载了的，Runtime 不再自动安装。所以客户端重启或升级后，用户卸载的 Observer 不会回来。

## 发布 [#publishing]

发布方为每个支持的平台构建一个安装包，服务器上的 Observer 也一样，例如应用识别 Observer 的 `linux-x64` 包。.NET 的 Observer 用自包含发布，入口和它依赖的文件一起放进 `bin/`。

macOS 上，包中的可执行文件需要签名才能在其他设备上运行。各平台的签名和分发方式要在正式发布前验证。
