Web 控制台是 Orisumi 的完整读取界面，目前只在本机使用。它按时间和事物组织记录：首页是“日”，显示那一天在用什么、用了多久。点任何实体的记号，右边推出它的面板，可以沿引用一层层追溯。

控制台是读取方：它读取所有 Observer 的数据，也可以删除实体，见 [ADR · 删除](../adr/deletion.mdx)。数据由 Observer 写入；控制台还以[用户本人](../observers/user/index.mdx)的身份写入对应用产品的修改。设备端客户端只展示最近的数据，更早的日期和追溯都在这里查看。

| 页面 | 地址 | 内容 |
| --- | --- | --- |
| [日](#day) | `/` | 那一天在用什么、用了多久 |
| [实体](#entities) | `/entities` | 从一个实体织出和它有关的实体；类型之间怎样引用 |
| [Observer](#observers) | `/observers` | 每个 Observer 今天什么时候在记录，现在是否在写入 |
| [实体页](#entity-page) | `/entities/{id}` | 一个实体的全部内容、引用、版本和删除；从面板底部进入 |
| [应用](#applications) | `/applications` | 应用产品、它们的线索和本机应用，可以修改 |
| [托管](#hosts) | `/hosts` | 每台设备和服务器上的程序实例，可以管理 |

## 侧栏 [#sidebar]

页面导航在左边的侧栏，分两组：日、应用和实体看记录；Observer 和托管在“采集”下面，看采集。导航上带着状态：有 Observer 正在写入时，Observer 后面的点跳动；有机器离线时，托管后面写离线的台数。判断方法分别与 [Observer](#observers) 和[托管](#hosts)页面相同。

“查找”接受 EntityId 和 VersionId。点它或按 ⌘K、`/` 弹出输入框，先按 EntityId 读取，读不到再按 VersionId 读取。

侧栏底部是“现在”：今天当前时段的事物、从几点起、持续了多久，例如“VS Code · 17:51 起 · 13 分钟”。当前时段来自 Observer 最近 60 秒内确认过的观测预览；点事物推出它的面板。没有 Observer 正在写入时，这里写“没有 Observer 在写入”。最下面的外观按钮选择主题：跟随系统、浅色或深色。

窄屏时侧栏变成页面顶部的一栏：导航横排，查找和外观收成图标，“现在”收起。

彩色只用来区分事物和 Observer 的类别。

## 角色和记号 [#roles]

控制台按实体在记录里的角色画它的记号，同一个实体在所有页面上的记号相同。例如前台状态 Observer 记下一段 VS Code 的使用：VS Code 这个本机应用是事物，前台应用时段是经历，前台状态 Observer 是来源。

| 角色 | 哪些实体 | 记号 |
| --- | --- | --- |
| 经历 | Observation，以及被 `contentVersionId` 引用的业务实体 | 一段横条 |
| 来源 | 被 `observerVersionId` 引用的业务实体 | 带圆心的圆圈 |
| 依据 | InputSet | 叠放的几层 |
| 定义 | EntitySchema | 虚线框 |
| 事物 | 其余业务实体 | 带类型图标的色块，例如本机应用是一个窗口，应用产品是一叠方块。本机应用和应用产品有图标时，用应用自己的图标，见下文 |

角色由控制台从数据推出：每种业务类型取最近 30 天里一份以它为内容的 Observation 作样本，由它知道哪些类型是观测内容、哪些类型是 Observer。事实时间未知的陈述不在样本中，所以应用产品是事物；只写这种陈述的 Observer，例如应用识别 Observer 和用户本人，从它们的一个实体的引用方认出。

应用的图标来自前台时段的 `icon`，见 [Foreground Application Period · 图标](../observers/foreground-state/foreground-application-period.mdx#icon)。本机应用用引用它的最近 20 段前台时段中，最新一段带图标的图标，控制台用 `order=desc` 读取它的引用方找到这一段，见 [API · 引用方](../api/reading.mdx#referrers)；应用产品用属于它的本机应用中图标最新的那个。字节按摘要读取并缓存，见 [API · 内容](../api/reading.mdx#contents)。

来源的名字是它的类型名，例如“前台状态 Observer”。事物的颜色按名字稳定地取，所以同名的事物颜色相同。

悬停一个记号时，页面上同一实体的记号一起亮起。点击一个记号，右边推出它的面板；在面板里再点，下一层接在后面。超过两层时，前面的收成窄条，点窄条回到那一层。Esc 关掉最后一层。打开的面板写在地址的 `stack` 参数里，刷新页面后它们还在。

面板的内容按角色：

| 角色 | 面板内容 |
| --- | --- |
| 事物 | 这一天的用量、叫过的名字、被引用、同名的其他实体（写出它们内容里不同的那一段）、内容、谁看到过它 |
| 经历 | 事实时间、内容和它关于的事物、由哪个 Observer 记下、依据、对它的陈述 |
| 来源 | 内容和这一天的写入 |
| 定义 | 字段和类型之间的引用 |
| 依据 | 输入，以及用到它的 Observation |

每个面板底部有原始数据，以及“从这里织”和进入实体页的入口。“从这里织”以这个实体为起点打开[织图](#weave)。

进行中的经历来自[观测预览](../core/model/observation.mdx#previews)。例如 VS Code 从 17:51 起在前台，这一段还没有保存，它的面板写着“17:51 – 18:04”和“13 分钟 · 进行中”，“由谁记下”是前台状态 Observer 和观测预览最近一次更新的时刻。同一份 Observation 已经保存过版本时，面板的事实时间取观测预览。来源面板的“最近一次”也算上观测预览的更新；它的 Observation 数只数已保存的。

## 日 [#day]

日页面读出这一天的全部 Observation，按形状分三种处理：

- 有时段、内容引用了事物的，按事物分行。例如前台应用时段引用本机应用，本机应用再按[应用产品](#applications)合并，每个产品一行；未归属的本机应用单独一行。
- 有时段、内容不引用事物的，按内容类型分行。
- 只有时间点的，按 Observer 汇成一行密度。

页头是日期、总时长和切换次数，例如“3 小时 41 分 · 在 21 个本机应用之间切换了 447 次”。同一个 Observer 相邻两段指向不同的事物，算一次切换。

下面是排行和时间线合成的一张表，每个事物一行：左边是名次、记号和时长，底色的长度是它和用时最多的事物之比；右边是它这一天的段。默认列出前 12 个事物，其余收在“还有 N 个”里。不引用事物的经历和只有时间点的 Observation 排在最下面。

全天的缩略条可以拖动，也可以拉两端选范围；在时间线上捏合或按住 ⌘ 滚动滚轮缩放，拖动平移。预设范围有全天、有记录的时段和最近 1 小时，最近 1 小时只在今天出现；当前所在的范围高亮，切换时有 220ms 的过渡。悬停一行或一段，同一事物的段一起亮起。

今天的数据每 5 秒刷新一次，观测预览每 2 秒刷新一次。进行中的时段来自观测预览，画到观测预览的结束边界，也就是 Observer 最近一次确认的时刻。同一份 Observation 已经保存过版本时，观测预览是较新的陈述，取代那个版本的时段。现在在记录什么写在[侧栏](#sidebar)。

← 和 → 翻日期，地址参数是 `date=YYYY-MM-DD`，今天省略这个参数。

## Observer [#observers]

Observer 页面每个 Observer 一行，显示它今天什么时候在记录、现在是否在写入。例如前台状态 Observer 从 10:13 记到 17:36，之后它那一行是空的，右边写着“29 分钟前”；切到 VS Code 后，它的草稿每秒更新，这一行末尾开始跳动，写着“VS Code，从 17:51 起”。

开头是一句话，例如“3 个 Observer，1 个正在写入”，后面是今天的 Observation 数，以及最后一次写入的时刻和 Observer。

Observer 来自[角色和记号](#roles)中认出的 Observer 类型：每种类型的全部实体都列出，今天没有写入的也在。Observation 指向的 Observer 版本读不到时，这些 Observation 单独成一行“不可读取”。名称取类型的 `displayName`，同名的加 EntityId 末 4 位。

每一行的时间轴分两段，所有行对齐：

| 段 | 范围 | 内容 |
| --- | --- | --- |
| 今天 | 当天 0:00 到 24:00，占 4/5 | 今天的 Observation |
| 现在 | 最近 10 分钟，占 1/5 | 同样的内容放大，观测预览也画在这里 |

一行按哪种时间画，看这个 Observer 写的陈述：

- 写有事实时间的 Observation 的，例如前台状态 Observer，按事实时间画：时段是一段横条，只知道一个边界的是一道刻度。观测预览按它的事实时间接在后面。
- 只写事实时间未知的陈述的，例如应用识别 Observer 和用户本人，按保存时间画，每份 Observation 一道刻度。这些 Observation 从 Observer 的引用方读出。

最近 60 秒内保存过 Observation 或更新过观测预览的 Observer 算正在写入。它的一行高亮，末尾的点跳动，右边写观测预览的观测内容和开始时刻；其余的行右边写最近一次写入距现在多久，以及今天的 Observation 数。正在写入的排在前面，其余按最近一次写入排列。

点一行，右边推出这个 Observer 的面板，地址参数同样是 `stack`。

今天的 Observation 每 5 秒刷新一次，观测预览每 2 秒刷新一次，引用方每分钟刷新一次。事实时间远离今天的补发不在按事实时间画的行中出现。系统开启“减少动态效果”时，末尾的点不跳动。

## 实体 [#entities]

实体页面从一个实体出发，织出和它有关的实体。例如从 VS Code 开始：点它，左边长出它的前台应用时段，每段写着“14:00–16:00 · 前台状态 Observer”；点其中一段，左边长出前台状态 Observer。停在 Observer 上，整条路亮起：前台状态 Observer —来源— 14:00–16:00 —`localApplication`— VS Code。

地址参数 `root` 是起点的 EntityId。没有起点时，页面是[类型图](#type-map)，在那里选起点。

### 织图 [#weave]

实体是线，Observation 是把线系在一起的结：谁依据什么说了什么。织图按这个意思画节点：

- 观测内容是经历的 Observation 并进经历的节点。节点写经历的名字，下面写事实时间和记下它的 Observer。
- 其余的 Observation 画成结，写着 Observer、“陈述”、事实时间和依据了几个输入，它的 InputSet 并进结。例如应用识别 Observer 认定本机应用 QQ 属于应用产品 QQ：这份 Observation 是一个结，左边连着本机应用 QQ 和其他输入，右边连着应用产品 QQ。
  结上另写一行这次改了什么。观测内容有上一版时，和上一版比较：数组字段写加入和移出的元素，元素是对象时按键名的顺序写出它的值，其他字段写新的值，去掉的字段写“去掉”，几处变化用分号隔开。例如应用识别 Observer 把一条线索加进 Apple Preview，结上写“加入 macos.bundle-id com.apple.Preview”；改了名字的写“name 改为 Apple Preview”。内容是首版时写“新建”，后面是数组字段里的元素，例如“新建；加入 macos.bundle-id com.tencent.qq”；和上一版相同时写“内容相同”。
  结上的 Observer 名字可以单独点：点一次，Observer 长在结的左边，线上写“来源”；再点一次收起。展开结时只长出依据和其他邻居，谁说的已经写在结上。
- 其余业务实体各是一个节点。EntitySchema 只出现在类型图和面板里。

位置按来龙去脉从左往右排。点一个节点，它的邻居长在它左边或右边的一栏，连线上写着关系：

| 邻居 | 在哪边 | 线上写 |
| --- | --- | --- |
| 记下它的 Observer。结的 Observer 由点结上的名字长出 | 左 | 来源 |
| 它依据的输入，即 InputSet 的成员 | 左 | 依据 |
| 引用它的业务实体 | 左 | 引用所在的字段，例如 `localApplication` |
| 以它为观测内容的其他陈述 | 左 | 内容 |
| 它的业务字段引用的实体 | 右 | 字段名 |
| 结的观测内容 | 右 | 内容 |
| 以它为输入的陈述 | 右 | 依据 |
| 它作为 Observer 写下的 Observation | 右 | 来源 |

邻居来自 Core 的结构：Observation 和 InputSet 的固定字段、EntitySchema 声明为 `reference` 的字段，以及后端给出的引用方。所以接入新的 Observer 和类型后，织图照样能用。

已经在图上的邻居只连一条虚线。再点一次节点，收起从它长出来的整枝。

同一边、同一个标签、同一类型的邻居超过 6 个时，先长出最近的 3 个，其余收成一束，写着“还有 N 个”；点一次线束再放出 8 个。例如 VS Code 一天有几十段前台应用时段，它们收在一束里。

依据按类型分组：一种类型只有一个输入时直接长出，同一类型有两个以上时全部收成一叠，写着“6 个”和类型名，点一次同样放出 8 个。例如应用识别 Observer 认定 com.apple.Preview 属于 Apple Preview，依据是这个本机应用、读到名字的前台应用时段和目录里的每个产品：本机应用和时段直接长出，产品收成一叠。

一个节点和从它长出来的整枝占一段高度，同一个节点长出来的各枝上下排开，互不交错。例如展开结左边的 com.apple.Preview，它左边长出的时段排在它的那一段里，同一栏的其他依据上下让开。

停在一个节点上，它从起点长出来的那条路亮起，其余的变淡。选中的节点下面有“详情”和“从这里开始”：前者推出它的面板，后者把它设为新的起点。

每次生长后，画面对准新长出来的节点，最小缩到 60%。拖动背景平移，捏合或按住 ⌘ 滚动滚轮缩放；右下角是缩小、放大和“适应画面”。

### 类型图 [#type-map]

类型图分四列：来源、观测（Observation 和 InputSet）、经历、事物。一条线表示一种类型的实体经由某个字段引用另一种类型，线上写字段名，末尾的 `VersionId` 省略。例如前台应用时段指向本机应用的线上写着 `localApplication`。

引用关系来自样本：每种业务类型取一个实体，读出它引用的类型；Observation 的引用取自[角色和记号](#roles)中的那份样本 Observation。

点一个类型，下面列出它的实体：

- 事物、来源和依据按名字排列，同名的写出不同的那一段。
- 经历列出最近 24 小时的，按时间倒序。

点一个实体，从它开始织。今天有正在记录的事物时，页头有“从现在的 X 开始”。地址参数 `type` 是业务类型的 `resourceName`，或者 `observation`、`input_set`。

## 实体页 [#entity-page]

实体页显示一个实体的一个版本。例如 VS Code 这个本机应用的实体页，标题是“VS Code”，上方写“事物 · 本机应用”，左边是它的记号。标题与面板标题的取法相同，记号按[角色和记号](#roles)画。标题下面是 EntityId、所选的版本和它的保存时间。

页面从上到下是引用图、内容、版本和删除。地址参数 `version` 选择版本，不写时显示当前版本。内容中的 `binary` 字段写出媒体类型和大小，媒体类型是图片时显示图片。

引用图的中间是这个版本，左边是它引用的版本，右边是引用这个实体的版本。每个节点写名字、类型和引用所在的字段，字段名省略末尾的 `VersionId`，与[类型图](#type-map)的连线写法相同。经历的节点在右侧写出事实时间，所以 VS Code 的实体页列出的多个前台应用时段可以区分，例如“14:00–16:00”。点击节点进入它所属的实体，并选中被引用的那一版。

鼠标在节点上停留片刻，或者用键盘聚焦节点，旁边浮出它的预览：

- 名字、角色和类型。
- 经历的日期、时段和时长。
- 内容的前几个字段；Observation 写出观测内容和来源。
- 引用所在的字段和保存时间。

预览只用来看，点击仍然进入节点所属的实体。

## 应用 [#applications]

各设备上的本机应用按[应用产品](../observers/application-identity/application-product.mdx)合并显示。例如两台 Mac 和一部 Android 手机上的 QQ，在控制台中是一个 QQ。

### 读取 [#application-reading]

控制台读出全部应用产品和本机应用的当前版本，按 [Application Identity · 归属](../observers/application-identity/index.mdx#membership) 匹配：

- 显示前台应用名称和时长的地方按产品合并，名称取产品的 `name`。产品的时长是它的各本机应用时长之和。本机应用的记号也用产品的名字。
- 未归属的本机应用按本机应用单独显示。

### 应用页 [#application-page]

应用页是一张产品表，每个产品一行。从左到右是：名字，下面写当前版本由谁写下、什么时候，例如“应用识别 Observer · 18 分钟前”；今天 0 点到 24 点的用量条；今天的用时；线索，每条线索后面是拥有它的本机应用；操作菜单。表头标出 0、6、12、18、24 点，用量条上 6、12、18 点各有一道细线，现在的位置是一道竖线。产品按名字排列，顶部的输入框按名字或线索筛选。窄屏时用量条和线索换到名字下面。

还没归入产品的线索列在最后的“未归属”中；只有本机线索的安装也列在这里，它们归不进产品。

点产品的名字，右边推出它的面板：今天的用量、各平台的线索与安装，以及修改记录。修改记录列出产品的每个版本改了什么、由哪个 Observer 写下，以及它的依据。本机应用的面板写出它属于哪个产品、凭哪条线索。

### 修改 [#application-edits]

用户在应用页修改产品。线索可以拖到另一个产品的那一行上；拖动时顶部出现两个落点，“新建产品”和“移出，重新识别”。点一条线索，同样可以选择去处，或者输入名字新建产品。改名、合并和删除在每行末尾的菜单中。

每次修改是一次提交，修改成功后控制台重新读取产品并重新合并，底部提示做了什么。

| 操作 | 形成的版本 |
| --- | --- |
| 产品改名 | 产品的新版本 |
| 把线索加入另一个产品，包括未归属的本机应用的线索 | 目标产品的新版本；线索原来所在的产品移出它，形成新版本 |
| 把线索加入一个新产品 | 新产品的首版；原来所在的产品形成新版本 |
| 把线索移出产品 | 产品的新版本。应用识别 Observer 在下一轮重新判断这条线索 |
| 合并两个产品 | 保留的产品形成新版本，加入另一个的全部线索；再删除另一个 |
| 删除产品 | 删除这个实体。它的线索由应用识别 Observer 重新判断 |

一次提交按顺序包含：

1. 还没保存时，应用产品和 User 的 EntitySchema，以及用户本人，见 [User Statements · 用户本人的身份](../observers/user/index.mdx#identity)。
2. 一个 InputSet，列出这次修改涉及的产品在修改前的当前版本，以及线索所属的本机应用版本。
3. 产品的版本。线索移动时，先写加入线索的产品，再写移出线索的产品。
4. 每个产品版本一份 Observation：Observer 是用户本人的当前版本，观测内容是这个产品版本，`inputSetVersionId` 指向上面的 InputSet，`startAt`、`endAt` 和 `timeZone` 都是 `null`。

产品的版本因 [VERSION-6](../core/model/version.mdx#version-6) 被拒绝时，说明产品在这期间被修改过。控制台提示用户，重新读取产品，由用户重新修改。

## 托管 [#hosts]

托管页按机器列出程序实例，规则见 [Management](./management.mdx)。顶部是一句话，例如“2 台机器，1 台离线”，下面写有几个 Observer 在运行、几个等待设备同步；右边是“接入”，签发配对码。

每台机器一张卡片：名字、设备或服务器、连接状态，例如“离线 · 18 分钟前联系过”；右边是“安装”和更多操作（改名、移除，已移除的是重新接入）。机器离线时“安装”不可用。卡片里每个程序实例一行：

- 名字和版本，下面是运行状态的点和文字、待发送的数量和错误。机器离线时运行状态是“状态未知”。
- 后端接受的配置还没被设备执行时，写着“等待同步”。
- 右边是启用开关，离线时也能改，设备连接后执行。
- 已删除的实例收在卡片底部，写出它是否已经停止。

点一个实例，右边推出它的面板，样式与实体的面板相同：

| 部分 | 内容 |
| --- | --- |
| 状态 | 配置（带启用开关）、同步、运行、连接、版本和发送，错误和采集提示写在下面 |
| 设置 | 设置的 JSON。写成对象时才能保存，整个对象一起保存，可以还原 |
| 维护 | 更新、重试、卸载。机器离线时不可用；操作进行中和结束后，下面一行写出进度和结果，没有收到结果时写“没有收到结果，上面是设备现在的状态” |
| 删除实例 | 在面板中确认后永久删除 |

面板底部链到这个程序实例的实体页。Esc 关闭面板。

“接入”的对话框显示 8 个字符的配对码、剩余的有效时间和拷贝。“安装”的对话框先读取那台机器可以安装的包，每个包一行，原来的实例已删除的写明会新建实例。

托管方和实例每 5 秒刷新一次，进行中的在线操作每秒读取一次状态。
