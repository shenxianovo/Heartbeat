Runtime 是设备端客户端中的公共组件。它安装和运行 Observer 的进程，接收它们交来的数据，本地保存并发送到后端，再把状态和数据提供给客户端的界面。本页写 Runtime 的启动参数、数据目录、进程的生命周期和两条管道的协议。为什么这样分工，见 [ADR · Runtime 与进程托管](../adr/observer-runtime.mdx)。

Runtime 是一个 .NET 程序，代码在 `src/Observers/Orisumi.Observer.Runtime/`。本地保存和发送的实现见 [.NET](../observers/submission/dotnet.mdx)。

## 启动 [#startup]

客户端启动 Runtime 进程，并通过它的标准输入和标准输出通信：

```sh
Orisumi.Observer.Runtime --data-dir <目录> --backend <API 地址> --bundled <目录> [--catalog <URL>]
```

| 参数 | 作用 |
| --- | --- |
| `--data-dir` | 数据目录，见[数据目录](#data) |
| `--backend` | API 的根地址，包括 `/api/` |
| `--bundled` | 随客户端附带的安装包所在的目录，见 [Packages · 附带的 Observer](./packages.mdx#bundled) |
| `--catalog` | 官方目录的 HTTPS 地址。省略时只列出附带的安装包 |

启动后，Runtime 安装尚未登记过的附带安装包，再运行所有启用的 Observer。

Runtime 对 API 的每个请求最多等待 5 秒，超时按网络失败处理：发送稍后原样重发，见 [Submission · 确认](../observers/submission/index.mdx#confirmation)；读取报告后端不可用，见[读取](#reading)。客户端管道一次只有一个请求未完成，所以后端没有响应时，界面最多等 5 秒就能继续。

## 数据目录 [#data]

一个数据目录同时只能由一个 Runtime 使用，Runtime 启动时锁定它。

```text
<data-dir>/
  registry.json                 安装登记
  packages/<package-id>/<version>/   解压后的安装包，安装后不再改动
  instances/<entity-id>/
    store.sqlite                Runtime 为这个实例本地保存的数据
    data/                       业务代码自己的持久数据
  shared/                       这个 Runtime 中各程序实例共用的业务数据
  staging/                      下载和解压中的安装包
```

- 安装登记记录每个安装包当前的版本、对应的程序实例、是否已安装、是否启用，以及设置。Runtime 写入新的登记文件后整个替换旧文件，所以登记总是完整的。
- 实例目录的名字是程序实例的 EntityId，不含包版本。更新、卸载和重装都使用同一个实例目录。
- `store.sqlite` 只有 Runtime 打开。客户端和各语言的 SDK 都通过管道读取。
- `data/` 和 `shared/` 中的内容由 Observer 的业务代码解释。`shared/` 供同一设备上的多个程序实例共用，例如前台状态 Observer 的[本机应用登记文件](../observers/foreground-state/local-application.mdx#registry)。
- 设置是一个 JSON 对象，含义由各 Observer 定义。

## 进程 [#process]

### 状态 [#states]

Runtime 为每个 Observer 报告托管方的三项状态，见 [Submission · 流程](../observers/submission/index.mdx#flow)：

| 状态 | 含义 | 取值 |
| --- | --- | --- |
| 启用 | 用户是否要它采集，持久保存 | `enabled` 为 `true` 或 `false` |
| 进程 | 进程现在怎样 | `starting`、`running`、`stopping`、`waiting`（等待重启）、`stopped`、`failed`；故障的原因在 `error` |
| 发送 | 本地数据的发送 | 草稿、待发送、已保存的数量，发送错误和被拒绝的版本 |

来源读取失败作为采集诊断处理，见 [OBSERVER-8](../core/model/observer.mdx#observer-8)：Observer 把诊断写入标准错误，Runtime 在 `diagnostic` 中报告最近的一条，最长 2048 个字符，进程状态不变。

### 启动与停止 [#lifecycle]

1. Runtime 启动 Observer 的进程，在管道中发送 `init`：协议版本、程序实例的 EntityId、安装包的版本、业务数据目录、共用数据目录和设置。
2. Observer 完成本地初始化和恢复后回复 `ready`，然后开始采集。初始化可以登记、读取本地状态和提交批次；`ready` 不等待后端可用，也不等待数据发送完。
3. 启动后 10 秒内没有 `ready`，视为启动失败，Runtime 结束进程。协议版本不兼容时，Runtime 直接报告故障，不重启。
4. 停用、卸载、更新或退出时，Runtime 发送 `stop`。Observer 停止读取新的证据，按自己的业务规则结束进行中的事实，等收到本地回执后退出。Runtime 以进程退出确认停止。
5. 发出 `stop` 后 10 秒内进程没有退出，Runtime 结束它，并显示异常。这时进行中的草稿保留在本地，下次启动时由业务代码按自己的规则恢复。
6. 管道关闭时，Observer 停止采集并退出。所以 Runtime 退出后，不会留下仍在采集的进程。

### 重启 [#restart]

用户启用的 Observer 意外退出后，Runtime 依次等待 1、2、4 秒重启它，最多三次。第三次重启后仍然失败，进程状态变为 `failed`，启用状态不变，等用户重试。

- 进程在 `ready` 之后连续运行 60 秒，失败计数清零。
- 用户重试时，开始新一轮的三次。
- 用户停用、卸载或退出客户端时，取消等待中的重启。正常退出不触发重启。

Runtime 不用心跳判断 Observer 是否卡住，因为事件型的 Observer 可以很久没有新数据。

### 退出 [#shutdown]

客户端发送 `shutdown` 或关闭 Runtime 的标准输入时，Runtime 先停止所有 Observer，再停止发送，然后退出。退出不等网络恢复，也不等待发送的数据全部发完。

## 客户端管道 [#client-pipe]

管道中每行是一个 UTF-8 编码的 JSON，标准输出只写协议消息，日志写入标准错误。字段名用 camelCase，UUID 写成字符串。一行最多 16 MiB，超过时 Runtime 断开连接。

客户端发出请求，一次只有一个请求未完成：

```json
{ "id": "7", "method": "setEnabled", "params": { "packageId": "foreground-state", "enabled": false } }
```

Runtime 用同一个 `id` 返回结果或错误：

```json
{ "id": "7", "result": {} }
```

```json
{ "id": "7", "error": { "code": "not_found", "message": "foreground-state is not installed" } }
```

| `code` | 含义 |
| --- | --- |
| `invalid_request` | 请求不符合协议 |
| `not_found` | 安装包、程序实例或版本不存在 |
| `conflict` | 与当前状态冲突，例如读取的游标已过期 |
| `unavailable` | 暂时无法完成，例如官方目录读取失败 |
| `internal` | Runtime 的错误 |

客户端在等待响应时继续读取标准输出，直到 Runtime 退出。

### 管理 [#management]

| 方法 | 参数 | 结果 |
| --- | --- | --- |
| `list` | 无 | 已登记的 Observer 及其状态 |
| `catalog` | 无 | 可安装的安装包 |
| `install` | `packageId` | 安装完成后返回 |
| `update` | `packageId` | 更新完成后返回 |
| `setEnabled` | `packageId`、`enabled` | 启用时进程开始启动即返回，不等 `ready`；停用时进程实际退出后返回 |
| `retry` | `packageId` | 启用并开始新一轮重启 |
| `uninstall` | `packageId` | 进程停止、程序移除后返回 |
| `shutdown` | 无 | 返回后 Runtime 退出 |

`list` 的结果中，每个 Observer 一项：

```json
{
  "observers": [
    {
      "packageId": "foreground-state",
      "name": "Foreground State",
      "version": "0.1.0",
      "instanceId": "0196f3a2-7c1e-7d40-9b1a-2f6c8e4d5a01",
      "installed": true,
      "enabled": true,
      "state": "running",
      "error": null,
      "diagnostic": null,
      "delivery": { "pending": 0, "drafts": 1, "saved": 42, "error": null, "rejection": null }
    }
  ]
}
```

- 已卸载、但还有待发送数据的程序实例也在列表中，`installed` 为 `false`。
- `rejection` 不为空时是 `{ "rule": "VERSION-6", "detail": "…" }`，说明这个实例的发送因被拒绝的版本暂停，见 [Submission · 被拒绝的版本](../observers/submission/index.mdx#rejections)。

`catalog` 合并附带的安装包和官方目录，列出本机可用的每个包：

```json
{
  "packages": [
    {
      "id": "foreground-state",
      "name": "Foreground State",
      "description": "记录前台应用的时段",
      "version": "0.1.0",
      "target": "osx-arm64",
      "format": 1,
      "protocol": 1,
      "installedVersion": null,
      "compatible": true
    }
  ]
}
```

`compatible` 说明本机的 Runtime 能否安装这个包：`target` 是本机平台，`format` 和 `protocol` 是 Runtime 支持的版本。官方目录中省略 `format` 或 `protocol` 时按 `1` 处理。官方目录读取失败时，`catalog` 返回错误，`list` 不受影响。下载地址和摘要只在 Runtime 中使用。

`install` 和 `update` 选择本机平台可用的最高版本。同一个安装包的安装和更新依次进行。安装和重装后 Observer 是启用的；更新保持原来的启用状态。停用的 `setEnabled` 和 `uninstall` 等进程实际退出后返回，最多等 10 秒，见[启动与停止](#lifecycle)。

### 读取 [#reading]

客户端经 Runtime 读取一个程序实例的 Observation。Runtime 从 API 读取已保存的部分，补上本地还没发送的版本，合并后返回。合并结果中每份 Observation 只出现一次，所以本地版本发送之后，界面不会把同一个时段显示两次。

`read` 按事实时间读取一个程序实例的 Observation：

| 参数 | 含义 |
| --- | --- |
| `instanceId` | 程序实例的 EntityId |
| `from`、`to` | 带时区的 ISO 8601 时间。事实时间与这个范围相交的 Observation |
| `resourceName` | 可选。只返回观测内容是这种业务类型的 |
| `limit` | 每页的数量，1 到 1000 |
| `cursor` | 可选。上一页返回的 `next` |

```json
{
  "observations": [
    { "version": { "versionId": "…", "entityId": "…" }, "state": "draft" }
  ],
  "next": null,
  "complete": true,
  "error": null
}
```

- `version` 是 Observation 的版本，结构和 [API](../api/index.mdx) 中提交的版本相同。
- `state` 是这份 Observation 在本机的状态：`draft`（草稿）、`pending`（待发送）、`saved`（已保存）或 `rejected`（被拒绝）。
- 结果按事实时间的起点从晚到早排列，起点相同的按 EntityId 排列。
- 第一页时，Runtime 生成一份合并的快照，之后的页都从这份快照中读取，翻页时不重复也不遗漏。快照保留 2 分钟，Runtime 最多同时保留 32 份，超出时移除最早的一份。快照过期后，`cursor` 返回 `conflict`，客户端从第一页重新读取。
- 同一份 Observation 按 EntityId 合并。本地版本与后端的版本相同时，显示为 `saved`；本地版本接在后端当前版本之后时，显示本地版本；两者分叉时显示后端的版本。
- 后端返回 `410` 的实体，Runtime 在本地记下，之后断网或重启也不再显示它的本地副本。
- `complete` 为 `false` 时，后端的部分没有读到，`error` 说明原因。结果由本地的数据和 Runtime 这次运行中最近读取的结果组成，不能作为完整的统计。

`versions` 按 VersionId 读取被引用的版本，一次最多 256 个：

```json
{ "versions": [], "missing": [], "error": null }
```

- 还没发送的版本从本地读取，已保存的从 API 读取。
- 返回的是指定的那个版本，不用实体的当前版本代替，见 [ENTITY-4](../core/model/entity.mdx#entity-4)。
- 版本已被删除时，它出现在 `missing` 中，Runtime 不用旧的缓存代替。
- 断网时返回本地有的版本，`error` 说明原因。

后端不可用时，Runtime 用最近 32 次读取的结果补充本地数据，这些结果只在 Runtime 运行期间保留。

### 刷新 [#refresh]

界面打开时立即读取，可见期间每 2 秒读取一次，隐藏后停止。

## Observer 管道 [#observer-pipe]

Observer 的进程与 Runtime 之间使用同样的逐行 JSON。管道绑定启动它的程序实例，消息中不能指定另一个实例。各语言的 SDK 封装这些消息，业务代码通过 SDK 调用。

Runtime 启动进程后先发送：

```json
{
  "event": "init",
  "protocol": 1,
  "instanceId": "0196f3a2-7c1e-7d40-9b1a-2f6c8e4d5a01",
  "packageVersion": "0.1.0",
  "dataDirectory": "/…/instances/0196f3a2-7c1e-7d40-9b1a-2f6c8e4d5a01/data",
  "sharedDataDirectory": "/…/shared",
  "settings": {}
}
```

程序实例的程序版本用 `packageVersion`，所以后端记录的版本与安装包一致。

停止时发送 `{ "event": "stop" }`，Observer 不回复它，收尾并收到回执后退出。

Observer 发出的请求和客户端管道的格式相同。批次的语义见 [Submission · 本地交接](../observers/submission/index.mdx#handoff)。

| 请求 | 参数 | 结果 |
| --- | --- | --- |
| `ready` | 无 | 初始化和恢复完成，每次启动一次 |
| `registerSchema` | `entityId`、`content` | `versionId`。只在本地登记，发送前再与后端对齐，见 [Submission · 登记](../observers/submission/index.mdx#registration) |
| `registerInstance` | `schemaVersionId`、`content` | `versionId`。登记的是管道绑定的程序实例 |
| `commit` | `operations` | `results`：每个具名操作得到的 VersionId |
| `local` | 可选的 `entityId`、`versionId`、`draftsOnly`、`category` | 本地的版本及其状态，供恢复和修复使用 |
| `status` | 无 | 发送状态：`pending`、`drafts`、`saved`、`error`、`rejection` |
| `readCurrent` | `entityId` | 后端的当前版本，带 `recordedAt`；没有时为 `null` |
| `entityStatus` | `entityId` | 后端对这个实体返回的 HTTP 状态码，例如 `410` 说明已删除 |
| `repair` | `rejectedVersionId`、`action` 及其字段 | 处理被拒绝的版本 |

### 批次的操作 [#operations]

`commit` 请求的 `id` 就是批次的标识，重发时沿用原来序列化好的整行。一个批次有 1 到 512 个操作：

```json
{
  "id": "0196f3a3-1b20-7e11-8c4d-5a7b9e2f6c13",
  "method": "commit",
  "params": {
    "operations": [
      { "op": "complete", "entityId": "0196f3a2-9d10-7a52-b3c4-1e2f3a4b5c6d" },
      { "op": "reference", "entityId": "0196f3a2-8e21-7b63-a4d5-2f3e4a5b6c7d", "as": "app" },
      {
        "op": "draft",
        "entityId": "0196f3a3-0a32-7c74-95e6-3a4f5b6c7d8e",
        "category": "business",
        "schemaVersionId": "0196f3a1-ff43-7d85-86f7-4b5a6c7d8e9f",
        "content": { "name": "Safari", "localApplicationVersionId": null },
        "bindings": { "/localApplicationVersionId": "app" },
        "as": "period"
      }
    ]
  }
}
```

| 操作 | 字段 |
| --- | --- |
| `draft` | `entityId`、`category`、`content`，可选 `schemaVersionId`、`strategy`（`Immediate` 或 `OnCompletion`）、`publishDraft`、`ifAbsent`、`bindings`、`as` |
| `reference` | `entityId`、`as` |
| `complete` | `entityId`，可选 `as` |

- `op` 写明操作的种类，`category` 是版本的类别，与 [API](../api/index.mdx) 中的相同。
- `as` 给操作的结果起名，后面的 `bindings` 和回执中的 `results` 用这个名字。
- `bindings` 把内容中的一个引用位置（JSON Pointer）绑定到前面 `reference` 的结果，结果是一个确定的版本。
- `ifAbsent` 为 `true` 时，实体在本地已有版本就沿用当前版本，不写入。
- `content` 是完整的版本内容，Observation 的可空字段也要写出。

### 修复 [#repair]

`repair` 的 `rejectedVersionId` 必须是当前被拒绝的版本，请求的 `id` 和批次一样持久去重。`action` 对应 [Submission · 被拒绝的版本](../observers/submission/index.mdx#rejections) 中的处理：

| `action` | 附带的字段 | 作用 |
| --- | --- | --- |
| `adoptSaved` | `saved`：`readCurrent` 得到的版本 | 采用后端已保存的版本 |
| `replaceRejected` | `entityId`、`schemaVersionId`、`content` | 改写被拒绝的版本 |
| `replaceReference` | 同上，再加 `oldVersionId` | 在同一个事务中形成替代的实体，并把引用改到它 |
| `discard` | 无 | 丢弃被拒绝的版本和依赖它的版本 |

## 开发运行 [#development]

开发时不启动客户端，用 `--run` 在命令行中运行一个已安装的 Observer：

```sh
dotnet run --project src/Observers/Orisumi.Observer.Runtime -- --data-dir <目录> --backend <API 地址> --bundled <目录> --run foreground-state
```

这时 Runtime 不读取标准输入，按 Ctrl+C 退出。它启动同样的 Observer 进程，用同样的方式保存和发送。为不同的测试指定不同的数据目录，它们就是不同的程序实例，`shared/` 也互不影响。
