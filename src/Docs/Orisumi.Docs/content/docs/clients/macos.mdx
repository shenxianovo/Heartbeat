macOS 客户端常驻在菜单栏，通过 [Runtime](../hosting/runtime.mdx) 托管这台 Mac 上的 Observer。它遵循[设备端客户端](./device.mdx)的托管规则；本页写它附带哪些 Observer、怎样展示数据，以及实现的进度。

## 菜单栏 [#menu-bar]

客户端平时只在菜单栏显示图标：有 Observer 在采集时是彩色，否则变灰；Runtime 或某个 Observer 故障、发送被暂停时，图标上有红点。

菜单显示 Runtime 的状态、每个已安装的 Observer、等待发送的总数，以及发送被暂停的 Observer：

| 菜单项 | 作用 |
| --- | --- |
| Observer 名称 | 勾选即启用，再点一次停用。停用时进行中的事实按它的规则结束 |
| 重新启动 Runtime | Runtime 连续意外退出、客户端停止重启后出现 |
| 打开 Orisumi | 打开窗口 |
| 打开 Web 控制台 | 用浏览器打开设置中的 Web 控制台地址 |
| 设置… | 打开设置窗口 |
| 退出 Orisumi | Runtime 先停止所有 Observer，再停止发送，然后客户端退出 |

窗口或设置可见时，客户端每 2 秒刷新一次数据；都关闭后，每 15 秒读取一次 Observer 的状态，用于菜单栏图标。

## 窗口 [#window]

窗口是使用和管理 Orisumi 的地方，设置窗口只放默认的行为。侧栏分两组：

| 分组 | 每一项 | 打开后 |
| --- | --- | --- |
| 记录 | 本机每个已安装的 Observer 的视图。有专用视图的按记录的内容命名，例如前台状态 Observer 的视图叫“前台应用” | 它的数据，见[今天的前台应用](#today)和[最近的数据](#recent) |
| 设备 | “这台 Mac”，以及接入的其他设备和服务器 | 那台机器上的 Observer，见[管理](#management) |

Observer 停用或出了问题时，侧栏中它的视图旁有标记；其他机器离线或已移除时，名字后面写着。侧栏底部是“接入设备”和设置。

视图顶部在需要时显示一条横幅：

- 视图的 Observer 已停用：说明它不在记录，并提供启用。
- 视图的 Observer 故障、发送被暂停或发送出错：说明原因，并提供重试或打开它的详情。
- Runtime 故障：所有视图都显示，并提供重新启动 Runtime。

窗口打开时客户端出现在 Dock 中，关闭后只留在菜单栏。数据视图的工具栏有“Web 控制台”，其他日期和追溯在那里看。

## 管理 [#management]

“这台 Mac”列出本机的 Observer，经 Runtime 管理，所以离线时启用、停用和修改设置立即生效。其他机器列出它们的 Observer，经后端管理。功能和显示规则见 [Management](./management.mdx)。

每个 Observer 一行：名称、版本、运行和发送状态，还没同步时写着“等待同步”，右边是启用开关。选中一行，右侧的检查器显示它的详情：

| 部分 | 内容 |
| --- | --- |
| 状态 | 运行、发送和同步；其他机器上的再加配置和最近报告的时刻。错误和采集提示写在下面 |
| 设置 | 设置的 JSON，写成对象时才能保存，整个对象一起保存 |
| 维护 | 更新、重试、卸载，以及在窗口中查看。已卸载的提供重新安装，已删除的提供新建实例 |
| 删除实例 | 永久结束程序实例的身份，需要确认 |

“这台 Mac”的工具栏是“添加 Observer”；其他机器的工具栏是“安装”和更多操作（改名、移除，已移除的是重新接入）。机器离线时，“安装”和维护不可用，页面顶部说明启用和设置会在它连接后执行。“这台 Mac”还没接入或已被移除时，页面顶部提供接入。

“添加 Observer”列出官方目录和附带的安装包中本机可以安装的 Observer，每一项说明它记录什么，并只给一个操作：安装、重新安装、新建实例、更新到新版本，或在窗口中打开已安装的那一个。不适用于这台 Mac 的排在最后。给其他机器安装时，列表从那台机器的 Runtime 读取。

“接入设备”签发配对码，显示 8 个字符、剩余的有效时间和拷贝。

## 设置 [#settings]

设置是单独的窗口，从窗口侧栏底部、菜单或 ⌘, 打开，放 Orisumi 默认怎样运行：

| 分组 | 内容 |
| --- | --- |
| 通用 | 外观、登录时启动、本机数据目录 |
| 连接 | 这台 Mac 的接入状态，没接入或已被移除时输入配对码和名称；API 地址、Web 控制台地址 |

外观可以选跟随系统、浅色或深色，只改变 Orisumi 自己的窗口、弹窗和菜单，默认跟随系统。

## 最近的数据 [#recent]

没有专用视图的 Observer，视图中列出最近 7 天的 Observation，最多 50 份：事实时间、本机状态（进行中、待发送、已保存、被拒绝）和观测内容的 JSON。数据经 Runtime 的 `read` 读取，见 [Protocol · 读取](../hosting/protocol.mdx#reading)。

## 今天的前台应用 [#today]

前台状态 Observer 的专用视图。客户端用 `read` 读取今天的前台应用时段，再用 `versions` 读取时段的内容、它引用的本机应用版本和应用的标识。应用的图标是时段中的 `icon`，用 [`content`](../hosting/protocol.mdx#reading) 读取；应用列表用这个应用今天最晚一段带图标的时段。时段没有图标时用通用的应用图标。

视图顶部是今天的前台总时长。下面左边是 24 个小时的柱状图，每小时的前台时长按应用堆叠；右边是应用列表，列出每个应用的时长和占今天总时长的比例。选中一个应用后，图表突出它，下方只列出它的时段；不选时列出全部时段，按时间倒序。

- 只有草稿状态的时段显示为进行中。
- 时长按已确认的结束边界计算，不随客户端的时钟延长。
- 被引用的内容和本机应用每次刷新都用 `versions` 读取。后端已删除的不再显示；暂时读不到时沿用上一次的内容，并标明可能不完整。
- `read` 或 `versions` 报告后端不可用时，视图标明“可能不完整”。
