客户端通过标准输入和标准输出与 [Runtime](./runtime.mdx) 通信，用于管理 Observer。Observer 的进程不用这条管道，它遵守几条普通的进程约定。本页写管道的消息格式和这些约定；语义见 [Runtime](./runtime.mdx)。

## 格式 [#format]

管道中每行是一个 UTF-8 编码的 JSON，标准输出只写协议消息，日志写入标准错误。字段名用 camelCase，UUID 写成字符串。一行最多 16 MiB，超过时 Runtime 断开连接。

请求带 `id`、`method` 和 `params`：

```json
{ "id": "7", "method": "setEnabled", "params": { "instanceId": "0196f3a2-7c1e-7d40-9b1a-2f6c8e4d5a01", "enabled": false } }
```

Runtime 用同一个 `id` 返回结果或错误：

```json
{ "id": "7", "result": {} }
```

```json
{ "id": "7", "error": { "code": "not_found", "message": "no such instance" } }
```

| `code` | 含义 |
| --- | --- |
| `invalid_request` | 请求不符合协议 |
| `not_found` | 安装包或程序实例不存在 |
| `conflict` | 与当前状态冲突，例如安装的包的实例都已删除 |
| `unavailable` | 暂时无法完成，例如后端不可用或官方目录读取失败 |
| `internal` | Runtime 的错误 |

## 客户端管道 [#client-pipe]

客户端一次只有一个请求未完成，等待响应时继续读取标准输出，直到 Runtime 退出。

### 管理 [#management]

| 方法 | 参数 | 结果 |
| --- | --- | --- |
| `list` | 无 | 已登记的 Observer 及其状态 |
| `catalog` | 无 | 可安装的安装包 |
| `install` | `packageId`，或者安装包的地址 `url` 和可选的 `sha256` | 安装完成后返回 `packageId` 和 `instanceId` |
| `update` | `packageId` | 实例切换后返回 `packageId` 和 `instanceId` |
| `setEnabled` | `instanceId`、`enabled` | 启用时进程开始启动即返回；停用时进程实际退出后返回 |
| `setSettings` | `instanceId`、`settings` | 设置写入安装登记后返回；进程在运行时，Runtime 停止它，再用新的设置启动 |
| `pair` | `code`、`name` | 接入后端后返回 `hostId`，见 [Management · 接入](./management.mdx#pairing) |
| `retry` | `instanceId` | 启用并开始新一轮重启 |
| `resendRejected` | `instanceId` | 被拒绝的写入重新排队后返回重发的数量，见[本地转发](./runtime.mdx#forwarding) |
| `uninstall` | `packageId` | 进程停止、程序移除后返回 `packageId` 和 `instanceId` |
| `connection` | 无 | 当前的数据连接，见[连接](#connection) |
| `shutdown` | 无 | 返回后 Runtime 退出 |

`list` 的结果中，每个程序实例一项：

```json
{
  "host": { "hostId": "0196f3a0-2b11-7c30-8a1b-1c2d3e4f5a60", "connection": "connected" },
  "observers": [
    {
      "packageId": "foreground-state",
      "name": "Foreground State",
      "version": "0.1.0",
      "instanceId": "0196f3a2-7c1e-7d40-9b1a-2f6c8e4d5a01",
      "installed": true,
      "enabled": true,
      "state": "running",
      "error": null,
      "diagnostic": null,
      "writes": { "pending": 0, "rejected": 0, "lastRejection": null },
      "removed": false,
      "settings": {},
      "sync": { "revision": 7, "pendingChanges": 0, "error": null }
    }
  ]
}
```

- `host.connection` 是这个 Runtime 与后端的连接：`unpaired`（还没有接入，`hostId` 为 `null`）、`connected`、`offline` 或 `revoked`（托管方已移除）。
- 已卸载的程序实例也在列表中，`installed` 为 `false`。已删除的程序实例也在列表中，`removed` 为 `true`。
- `writes.pending` 是本地转发中等待交给后端的请求数，`writes.rejected` 是被拒绝的写入数，`writes.lastRejection` 是最近一次被拒绝的原因。
- `enabled` 和 `settings` 是生效的配置。`sync.revision` 是已合并的后端配置的修订号，还没有登记时为 `0`；`sync.pendingChanges` 是待同步的修改数；`sync.error` 说明同步停止的原因，见 [Management · 同步](./management.mdx#sync)。

`catalog` 合并附带的安装包和官方目录，列出本机可用的每个包：

```json
{
  "packages": [
    {
      "id": "foreground-state",
      "name": "Foreground State",
      "description": "记录前台应用的时段",
      "version": "0.1.0",
      "target": "osx-arm64",
      "format": 1,
      "protocol": 1,
      "installedVersion": null,
      "compatible": true
    }
  ]
}
```

`compatible` 说明本机的 Runtime 能否安装这个包：`target` 是本机平台，`format` 和 `protocol` 是 Runtime 支持的版本。官方目录中省略 `format` 或 `protocol` 时按 `1` 处理。官方目录读取失败时，`catalog` 返回错误，`list` 不受影响。下载地址和摘要只在 Runtime 中使用。

`install` 和 `update` 选择本机平台可用的最高版本。同一个安装包的安装和更新依次进行。安装和重装后 Observer 是启用的；更新保持原来的启用状态。`setEnabled`、`setSettings` 和安装形成的启用都是本机修改，见 [Management · 本机修改](./management.mdx#local-changes)。停用的 `setEnabled` 和 `uninstall` 等进程实际退出后返回，最多等 10 秒，见 [Runtime · 启动与停止](./runtime.mdx#lifecycle)。

### 连接 [#connection]

客户端的业务读取都走 [API](../api/reading.mdx)，Runtime 只告诉它怎样连接。`connection` 没有参数：

```json
{
  "hostId": "0196f3a0-2b11-7c30-8a1b-1c2d3e4f5a60",
  "api": { "url": "https://…/api/", "credential": "…" },
  "connection": "connected"
}
```

- `connection` 的取值与 `list` 的 `host.connection` 相同。还没有接入时，`hostId` 和 `credential` 为 `null`，客户端这时不读取数据。
- 客户端在 `pair` 之后，以及 `list` 的 `host` 变化时重新取得它。

## Observer 进程 [#observer-process]

Observer 是一个普通进程，这几条约定是它和 Runtime 之间的全部协议：

| 约定 | 内容 |
| --- | --- |
| 运行上下文 | 启动时从环境变量读取，见 [Overview · 运行上下文](./index.mdx#context) |
| 写入 | 发给 `ORISUMI_WRITE_URL`，见 [Runtime · 本地转发](./runtime.mdx#forwarding) |
| 停止 | 标准输入关闭时结束进行中的事实，然后退出。退出码为 `0` 表示正常退出 |
| 诊断 | 写入标准错误，每行一条，见 [Runtime · 状态](./runtime.mdx#states) |

配置变化时，Runtime 重启进程，所以程序不需要监听配置。
