服务器上的 Observer 依据全部已保存的数据形成观测，例如[应用识别 Observer](../observers/application-identity/index.mdx)。它们和设备上的 Observer 一样是安装包，由 [Runtime](./runtime.mdx) 运行。服务器上的 Runtime 以服务方式启动：没有客户端，由服务管理器或容器启停，只经后端接受管理，见 [Management](./management.mdx)。为什么这样托管，见 [ADR · Runtime 与进程托管](../adr/observer-runtime.mdx)。

例如部署时在服务器上用 systemd 运行 Runtime，数据目录放在 `/var/lib/orisumi/runtime`。第一次启动时带上在 Web 中签发的配对码，Runtime 接入后端，安装附带的应用识别安装包，开始识别。之后用户在 Web 中停用它、修改识别间隔或更新到新版本，都经后端交给这个 Runtime。

## 启动 [#startup]

```sh
Orisumi.Observer.Runtime --service --data-dir <目录> --backend <API 地址> [--bundled <目录>] [--catalog <URL>] [--pairing-code <配对码>] [--name <名称>]
```

| 参数 | 作用 |
| --- | --- |
| `--service` | 以服务方式运行：不读取标准输入，收到 `SIGTERM` 或 `SIGINT` 时按 [Runtime · 退出](./runtime.mdx#shutdown) 退出 |
| `--data-dir`、`--backend`、`--bundled`、`--catalog` | 与[设备上的启动](./runtime.mdx#startup)相同 |
| `--pairing-code` | 数据目录中还没有 `host.json` 时，用它接入后端 |
| `--name` | 接入时的托管方名称，省略时用主机名 |

启动后，Runtime 安装尚未登记过的附带安装包，接入、登记实例，再运行所有启用的 Observer。日志写入标准错误，由服务管理器收集。

## 接入 [#pairing]

服务方式的 Runtime 必须接入后端才能运行：

| 数据目录 | `--pairing-code` | Runtime 怎样做 |
| --- | --- | --- |
| 有 `host.json` | 省略 | 用其中的身份和凭证 |
| 有 `host.json` | 给出 | 带着原来的 `hostId` 重新接入，换成新的凭证。配对码必须是为这个托管方签发的 |
| 没有 `host.json` | 给出 | 作为新的托管方接入，类型为 `server` |
| 没有 `host.json` | 省略 | 以非零的退出码退出 |

接入失败时，Runtime 同样以非零的退出码退出，错误写入日志。配对码 10 分钟内有效，所以签发后即启动服务；接入成功后，之后的启动省略它。

## 持久目录 [#data]

数据目录必须持久保存，并且只由一个 Runtime 使用，结构见 [Runtime · 数据目录](./runtime.mdx#data)。它保存托管方凭证、程序实例的身份和 Observer 的业务状态，后端无法重建它们。容器部署时把它挂载为卷；目录丢失后，用新的配对码接入，得到的是一个新的托管方，原来的实例要在管理入口中删除。

## 运行环境 [#environment]

Observer 的进程继承 Runtime 的环境变量。外部服务的凭证由服务器的运行环境提供，例如应用识别 Observer 的 `OPENAI_API_KEY`，不写进同步的设置。

API 不在本机时，地址必须是 HTTPS，见 [API · 认证与授权](../api/index.mdx#auth)。安装包按服务器的平台选择，例如 `linux-x64`，见 [Packages · 清单](./packages.mdx#manifest)。

## 实现 [#implementation]

Runtime 和安装包由 `orisumi observers pack` 按平台构建，容器镜像由 `src/Observers/Orisumi.Observer.Runtime/Dockerfile` 从它的输出构建。构建和运行的步骤见 `src/Observers/Orisumi.Observer.Runtime/README.md`。
