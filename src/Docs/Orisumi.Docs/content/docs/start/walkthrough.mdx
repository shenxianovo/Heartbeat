---
title: "Walkthrough"
description: "用一天的数据串起 Core 的概念"
---

用户在 Mac 上写代码。电脑上运行着前台状态 Observer，它记下哪个应用在前台；晚上，推断 Observer 用模型整理当天的数据；第二天，用户查看结果。下面按时间顺序，看这一天的数据怎样形成、使用和删除。

## 1. 准备 [#setup]

前台状态 Observer 第一次启动时，托管方为它生成 EntityId，之后每次启动都沿用。前台状态 Observer 是一个事物，用户本人、这台 Mac 和 VS Code 这个本机应用也都是。

程序启动时写入一份描述：它是哪个版本、运行在什么平台上。之后的观测都引用这一版描述，所以能查到每份陈述出自哪个程序版本。

## 2. 采集 [#collect]

14:00，前台状态 Observer 读到 VS Code 在前台，开始这一段。这时什么都还没有保存，读取方也读不到它。

16:00 用户切到浏览器，这一段到此结束，前台状态 Observer 写入一份 Observation：内容提到 VS Code 这个本机应用，事实时间是 14:00 到 16:00，形成方式是直接读到。它直接读取系统状态，没有用到已保存的数据，所以这份 Observation 没有输入集。

VS Code 这个事物第一次被提到时由后端创建，程序不用先写入它。

## 3. 推断 [#infer]

晚上，推断 Observer 把当天的前台时段和键鼠事件交给模型，得到十份推断，其中一份是“14:00 到 16:00 在写代码”，形成方式是推断。它一次保存这十份推断，并列出这次实际读到的版本；后端用这些版本形成一个 InputSet，十份推断都引用它。

InputSet 列的是读取时的那一版。之后前台时段再改，这些推断的依据仍是当时那一版。

## 4. 否定 [#deny]

第二天，用户发现 15:00 到 16:00 其实在开视频会议，VS Code 只是留在了前台。用户保存一份 Review，引用那份推断，写明“在开会”，事实时间是 15:00 到 16:00，形成方式是亲口陈述。这份 Observation 的 Observer 是用户本人。

模型的推断保持原样。读取方看到这份 Review，就知道这条推断的后半段被否定了；下一轮模型读到它，以后不再犯同样的错。

## 5. 追溯 [#trace]

从“在写代码”出发，沿 InputSet 能读到模型当晚用过的前台时段和键鼠事件，读到的正是当晚那一版。要找和 VS Code 有关的全部数据，就列出引用 VS Code 这个事物的 Observation。

## 6. 删除 [#delete]

用户删掉 16:00 之后的浏览器时段。这份 Observation 连同全部版本一起移除。当晚读过这一段的推断仍然保留，追溯到这里时显示目标不可读取。之后如果还有程序向这份 Observation 写入，后端会拒绝，删除依然有效。
