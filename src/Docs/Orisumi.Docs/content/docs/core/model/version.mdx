---
title: "Version"
description: "实体一次保存的完整内容，保存后不可改写"
---

版本是实体一次保存的完整内容。每次修改都形成一个新版本，旧版本原样保留，所以一个实体的历史就是它的版本链。Observation、EntitySchema 和 InputSet 共用这一结构，[事物](./thing.mdx)没有版本。

<ModelRelations node="Version" />

- **身份**：`VersionId`，由后端生成的 UUIDv7，见 [VERSION-12](#version-12)
- **所属**：一个实体，由 `entityId` 指出
- **决策**：[ADR · 实体模型](../../adr/entity-model.mdx)、[ADR · 身份、时间与更新](../../adr/identity-and-updates.mdx)

## 成员 [#members]

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `entityId` | `EntityId` | 版本所属的实体 |
| `versionId` | `VersionId` | 版本的身份 |
| `previousVersionId` | 引用或 `null` | 同一实体的前一版本，首版为 `null` |
| `category` | `observation`、`entity_schema` 或 `input_set` | 实体的类别 |
| `recordedAt` | 时间，由后端赋值 | 保存时间：后端保存这个版本的时刻 |
| `content` | 由 Core 或 Schema 版本规定 | 这个版本的内容。EntitySchema 和 InputSet 的成员见各类型页，Observation 的业务字段由 Schema 版本声明 |

Observation 的版本还有说明这份陈述的成员，见 [Observation · 成员](./observation.mdx#members)。

## 内容 [#content]

### VERSION-1 完整内容 [#version-1]

执行方：写入方

一个版本保存实体在这一次的完整内容，读取它只需要这一个版本。`binary` 字段保存文件的描述，字节按摘要单独读取，见 [Binary](./binary.mdx)。

### VERSION-2 不可改写 [#version-2]

执行方：后端

已保存的版本不得改写，保存时间也包括在内。实体需要新内容时，形成新版本，见 [HISTORY-1](../rules/history.mdx#history-1)。

### VERSION-3 Observation 引用 Schema 版本 [#version-3]

执行方：后端

Observation 的版本必须引用一个 Schema 版本，内容按这一版校验和解释。

## 版本链 [#chain]

### VERSION-4 一条版本链 [#version-4]

执行方：后端

每个有版本的实体只有一条线性的版本链。首版的 `previousVersionId` 为 `null`；之后每个版本的 `previousVersionId` 必须是保存时的当前版本。

### VERSION-5 当前版本 [#version-5]

定义

实体最新保存的版本是它的当前版本。当前版本说明这份陈述的作者目前怎么说，系统目前采用哪些陈述，见 [UNDERSTANDING-4](../rules/understanding.mdx#understanding-4)。

### VERSION-6 按到达顺序 [#version-6]

执行方：后端

同一份 Observation 的写入按到达顺序形成版本：写入方给出完整内容，后端把它接在当前版本之后。一份 Observation 只有一个作者，见 [OBSERVATION-10](./observation.mdx#observation-10)。

### VERSION-8 版本按变化形成 [#version-8]

执行方：后端

写入的内容与当前版本相同时，不形成新版本。内容回到旧值是一次变化：内容从 A 改成 B 再改回 A，一共形成三个版本。

### VERSION-9 VersionId 不复用 [#version-9]

执行方：后端

VersionId 不得重新分配，实体删除后也一样。

## 保存时间 [#recorded-at]

### VERSION-10 recordedAt 由后端赋值 [#version-10]

执行方：后端

后端在保存一个版本时赋值 `recordedAt`。首版的 `recordedAt` 就是实体首次保存的时刻。

### VERSION-11 recordedAt 的含义 [#version-11]

定义

`recordedAt` 只表示后端保存这个版本的时刻。版本的先后由版本链决定，不同版本的 `recordedAt` 可以相同。

## 写入 [#writes]

写入方把一份 Observation 的完整内容、事实时间和形成方式交给后端，这是一次写入。

### VERSION-12 VersionId 由后端生成 [#version-12]

执行方：后端

VersionId 是后端在保存时生成的 UUIDv7。写入方用识别依据或 EntityId 指出引用的目标，后端解析成事物的 EntityId 或确定的版本，见 [API · Writing](../../api/writing.mdx#references)。

### VERSION-13 一次写入整体保存 [#version-13]

执行方：后端

一次写入形成的 Observation 版本和 InputSet，连同它提到的新事物，全部通过才一起保存。其中一项被拒绝时，这次写入都不保存，其他写入不受影响。
