Observer 是对一份 [Observation](./observation.mdx) 负责的[事物](./thing.mdx)，也就是 `observerId` 引用的事物。程序实例、Agent 和人都可以是 Observer：前台状态 Observer 对它采集的前台时段负责，用户对自己写下的“在开会”负责。

Observer 是一种角色，就像“作者”。同一个事物可以在一份观测中是 Observer，在另一份中被观测：用户否定一条推断时是 Observer，被记下睡眠时是被观测的对象。

一份观测有没有依据已保存的数据，由它的输入集表达，与 Observer 是人还是程序无关。同一个人可以凭亲身经历陈述，也可以读完日志再推理。

- **承担者**：事物
- **被引用**：Observation 的 `observerId`

## 责任 [#responsibility]

### OBSERVER-1 被引用者负责 [#observer-1]

定义

被 `observerId` 引用的事物是这份观测的 Observer，对其中的陈述负责。一个事物是不是 Observer，只取决于它在某份 Observation 中的位置。

## 划分 [#division]

### OBSERVER-2 按陈述划分 [#observer-2]

执行方：写入方

Observer 按负责的陈述划分。例如前台状态、输入事件和设备状态由三个 Observer 负责，三者可以运行在同一个进程中。

### OBSERVER-3 多种内容 [#observer-3]

执行方：写入方

一个 Observer 可以形成多种 Observation，多个 Observer 也可以使用同一种业务类型。不同平台的实现，只要字段、约束和事实含义相同，就必须共用同一种业务类型。

## 程序实例 [#instances]

程序实例是由程序承担的 Observer。四个词描述四件事：

| 词 | 含义 | 例子 |
| --- | --- | --- |
| 程序 | 一份代码 | 前台状态 Observer 的代码 |
| 程序实例 | 负责陈述的身份，有自己的 EntityId 和配置 | 这台 Mac 上的前台状态 Observer |
| 一次执行 | 程序实例的一次运行 | 今早开机后启动的进程 |
| 安装包 | 分发程序的文件 | `foreground-state-0.1.0-osx-arm64.zip` |

### OBSERVER-4 重启沿用身份 [#observer-4]

执行方：写入方

程序实例在下表的变化中保持身份。程序实例是[程序实例](../rules/understanding.mdx#thing-types)这种事物。受托管的程序实例由托管方预先分配并持久保存 EntityId；直接运行的程序用识别依据认出自己。实例的信息变化时，形成它的描述的新版本，见 [OBSERVER-9](#observer-9)。

| 变化 | EntityId |
| --- | --- |
| 新的一次执行，包括崩溃后重启 | 沿用 |
| 程序升级，安装包更新 | 沿用 |
| 卸载后重装 | 沿用 |
| 删除实例后再次使用 | 新建 |

推断 Observer 更换模型或提示词也属于升级；模型和提示词写在描述中，所以每份判断都知道自己出自哪个模型。

### OBSERVER-5 一个实例一个身份 [#observer-5]

执行方：写入方

每个程序实例有自己的 EntityId。一个程序可以有多个程序实例，同一个托管方可以运行它们，同一个进程也可以。同时运行的不同推断方法是不同的程序实例，例如用便宜的模型做筛选、用强模型做判断。

## 陈述 [#statements]

### OBSERVER-6 谁形成谁负责 [#observer-6]

执行方：写入方

形成观测的 Observer 对陈述负责：

| 情况 | 负责的 Observer |
| --- | --- |
| 内部模块只读取或检测证据 | 使用该模块的 Observer |
| 内部模块独立形成观测 | 该模块自己的 Observer |
| 程序只传输或组合已有观测 | 原 Observation 的 Observer |
| 程序依据已有观测形成新的观测 | 形成新观测的 Observer |
| 另一个 Observer 重新解释证据 | 重新解释证据的 Observer |
| 用户经客户端确认、否定或陈述 | 用户本人 |
| 正在和用户工作的 Agent 当场形成判断 | 这个 Agent |

不同 Observer 的陈述冲突时，读取方按 [UNDERSTANDING-4](../rules/understanding.mdx#understanding-4) 取当前理解。

### OBSERVER-7 确认与否定 [#observer-7]

执行方：写入方

确认或否定写成一份 [Review](../rules/understanding.mdx#review-type)。例如用户否定模型的推断：这份 Review 引用被否定的那一版推断，并写出用户的结论；用户参考过的日志列在输入集中。

### OBSERVER-8 失败作为诊断 [#observer-8]

执行方：写入方

读取、解析或匹配失败不形成观测，作为采集诊断处理。

## 描述 [#description]

### OBSERVER-9 描述 [#observer-9]

执行方：写入方、后端

程序实例和 Agent 用一份 Observation 描述自己：程序版本、平台、模型和提示词。这份描述的 Observer 是它自己，`observerVersionId` 为 `null`。之后它形成的每个版本都由后端填上当时描述的版本。描述变化时形成新版本，已有的陈述继续引用当时那一版。人没有描述，`observerVersionId` 为 `null`。
