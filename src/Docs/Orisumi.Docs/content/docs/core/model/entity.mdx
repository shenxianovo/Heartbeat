实体是 Orisumi 中有稳定身份的一项数据，例如这台 Mac、14:00 开始的那段前台时段，或者晚上的一份推断。实体分四类：

| 类别 | `category` | 有版本 | 内容 |
| --- | --- | --- | --- |
| [事物](./thing.mdx) | `thing` | 否 | 只有身份，例如设备、会话、QQ 号、人 |
| [Observation](./observation.mdx) | `observation` | 是 | 一份陈述 |
| [EntitySchema](./schema.mdx) | `entity_schema` | 是 | 一种业务类型 |
| [InputSet](./input-set.mdx) | `input_set` | 是 | 一次处理实际用到的版本 |

事物和 Observation 保存用户的数据，EntitySchema 和 InputSet 是支撑它们的结构。

## 身份 [#identity]

### ENTITY-1 EntityId 不变 [#entity-1]

执行方：后端

每个实体有一个 EntityId，生成后不再改变。一个 EntityId 只属于一个实体，实体删除后仍然占用。什么算同一个实体由业务规则决定，见 [Identity](../rules/identity.mdx)。

### ENTITY-2 EntityId 的生成 [#entity-2]

执行方：后端

EntityId 是 UUIDv7。新实体的 EntityId 由后端生成，直接运行的程序实例也一样。受托管的程序实例由托管方预先分配，见 [HISTORY-7](../rules/history.mdx#history-7)；SchemaId 是业务规则给定的常量。

### ENTITY-3 类型不变 [#entity-3]

执行方：后端

实体的类型在创建后不再改变：事物的 SchemaId 不变；有版本的实体，后续版本的 `category` 与首版相同；Observation 的后续版本必须引用同一个 EntitySchema 的 Schema 版本，可以是其中任何一版，比前一版更旧的也可以。每个版本都按自己引用的 Schema 版本解释，见 [SCHEMA-2](./schema.mdx#schema-2)。

## 引用 [#references]

### ENTITY-4 引用的目标 [#entity-4]

定义

引用指向事物时，值是目标的 EntityId；指向有版本的实体时，值是目标版本的 VersionId，所以沿引用读到的始终是这一版。

例如交互引用设备这个事物，设备改名不影响这份交互。推断的输入引用下午的前台时段的一个版本，这段时段后来被纠正，追溯时读到的仍是当时那一版。

引用方要跟上目标的新内容，就形成自己的新版本，改为引用目标的新版本。

### ENTITY-5 引用的位置 [#entity-5]

定义

一个版本的引用，是 Core 或它的 Schema 版本声明为引用的全部位置：

- 版本的 `previousVersionId` 和 `schemaVersionId`；
- Core 声明的引用成员，例如 Observation 的 `observerId`；
- 业务字段中 `type` 为 `reference` 的值，包括对象成员和数组元素，见 [SCHEMA-9](./schema.mdx#schema-9)。

枚举引用时，保留每个引用所在的位置：前一版本、Schema 版本、Observer 和输入是不同的关系。

### ENTITY-6 只引用存在的目标 [#entity-6]

执行方：后端

新版本引用的目标版本，都必须已保存且未被删除。写入按顺序逐个保存，所以版本不能引用自己，两个新版本也不能互相引用。引用的事物不存在时，后端按 [THING-2](./thing.mdx#thing-2) 创建它；已删除的 EntityId 不能再被引用。

Observation 之间仍然可以互相关联：A 的第二版引用 B 的第一版，B 的第一版引用 A 的第一版。

目标保存后又被删除时，已有的引用保留，见 [HISTORY-8](../rules/history.mdx#history-8)。

### ENTITY-7 按实体归集 [#entity-7]

执行方：读取方

查找与某个实体相关的数据时，按目标所属的实体归集。例如两份推断分别引用了同一段时段的第一版和第二版，它们都依据这段时段。

### ENTITY-8 引用存在引用方 [#entity-8]

定义

引用只保存在引用方的版本中。要找出引用某个实体的版本，就查询引用方的数据。

## 关系与操作 [#relations]

### ENTITY-9 关系都是引用 [#entity-9]

定义

实体之间的关系都表达为 Observation 中的引用，关系的时间、责任和形成方式就是这份 Observation 的时间、Observer 和形成方式。例如交互的 `deviceId` 说明它发生在哪台设备上，[关系](../rules/understanding.mdx#relation)说明 QQ 号 123 是本人，两者是同一种引用。

### ENTITY-10 统一的操作 [#entity-10]

执行方：后端

所有实体使用同一组读取和删除操作。有版本的实体用同一种方式形成新版本。
