Observation 是一份陈述，中文叫观测。它说明五件事：哪个 [Observer](./observer.mdx) 负责、说了什么、怎么来的、依据了哪些已保存的数据、事实在什么时间成立。前台状态 Observer 采集到的前台时段、模型的推断、用户的确认和否定，都是 Observation。

这五件事都在同一个版本中，所以读一份 Observation 就读到了全部。它提到的对象是[事物](./thing.mdx)，实体之间的关系也都写在 Observation 中，见 [ENTITY-9](./entity.mdx#entity-9)。

<ModelRelations node="Observation" />

- **类别**：`category` 为 `observation`，类型由 EntitySchema 定义
- **引用**：`schemaVersionId`、`observerId`、`observerVersionId`、`inputSetVersionId`，以及业务字段中的引用
- **决策**：[ADR · 实体模型](../../adr/entity-model.mdx)、[ADR · Observer 与输入集](../../adr/observers-and-evidence.mdx)、[ADR · 身份、时间与更新](../../adr/identity-and-updates.mdx)、[ADR · 模型形成的理解](../../adr/understanding.mdx)

## 成员 [#members]

以下成员在版本共有的[成员](./version.mdx#members)之外：

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `schemaVersionId` | 引用 | 这份陈述所用的 Schema 版本，决定它的类型和 `content` 的结构 |
| `observerId` | 引用 | 负责的 Observer，是一个事物 |
| `observerVersionId` | 引用或 `null`，必须出现 | 形成这一版时 Observer 的描述，见 [OBSERVER-9](./observer.mdx#observer-9)。没有描述时为 `null` |
| `formation` | 枚举 | [形成方式](#formation) |
| `inputSetVersionId` | 引用或 `null`，必须出现 | 这次处理实际用到的 [InputSet](./input-set.mdx)。没有用到已保存的数据时为 `null`，见 [EVIDENCE-1](../rules/evidence.mdx#evidence-1) |
| `timeZone` | 字符串或 `null`，必须出现 | 事实所属的 IANA 时区，未知时为 `null` |
| `startAt` | 时间或 `null`，必须出现 | 事实的已知开始边界，未知时为 `null` |
| `endAt` | 时间或 `null`，必须出现 | 事实的已知结束边界，未知时为 `null` |

## 示例 [#example]

VS Code 从 14:00 起在前台，前台状态 Observer 在 14:05 最后一次确认。

```json
{
	"entityId": "019e1bbb-ec00-7000-8000-0000000000e1",
	"versionId": "019e1bbb-ec00-7000-8000-000000000101",
	"previousVersionId": null,
	"category": "observation",
	"schemaVersionId": "019e1bbb-ec00-7000-8000-000000000201",
	"observerId": "019e1bbb-ec00-7000-8000-0000000000a0",
	"observerVersionId": "019e1bbb-ec00-7000-8000-0000000000a1",
	"formation": "direct",
	"inputSetVersionId": null,
	"startAt": "2026-10-06T06:00:00Z",
	"endAt": "2026-10-06T06:05:00Z",
	"timeZone": "Asia/Shanghai",
	"recordedAt": "2026-10-06T06:05:01Z",
	"content": {
		"localApplicationId": "019e1bbb-ec00-7000-8000-0000000000c1",
		"name": "Visual Studio Code"
	}
}
```

`endAt` 是最近一次确认的时刻，VS Code 此后可能仍在前台。采集直接读取系统状态，没有用到已保存的数据，所以 `inputSetVersionId` 为 `null`。

## 引用 [#references]

### OBSERVATION-1 引用的目标 [#observation-1]

执行方：后端

每份 Observation 必须引用一个 `kind` 为 `observation` 的 Schema 版本和一个作为 Observer 的事物。`observerVersionId` 不为 `null` 时，必须是这个 Observer 的描述的版本。`inputSetVersionId` 不为 `null` 时，必须指向一个 InputSet 的版本。这些目标都要存在且未被删除，见 [ENTITY-6](./entity.mdx#entity-6)。

### OBSERVATION-2 陈述的类型 [#observation-2]

定义

Observation 的类型由它所用的 Schema 版本决定。

### OBSERVATION-3 同一件事的多份观测 [#observation-3]

定义

不同的 Observer 对同一件事可以各有一份 Observation。一个 Observer 的陈述更新时形成它那一份的新版本，其他 Observer 的不受影响。每次读取都要单独成一份观测时，每次读取是一个新的 Observation，例如一次温度读数。

## 事实时间 [#fact-time]

事实时间由 `startAt` 和 `endAt` 两个边界表示，任何一个都可以未知：

| `startAt` | `endAt` | 含义 |
| --- | --- | --- |
| `null` | `null` | 开始和结束都未知 |
| `t` | `null` | 开始已知，结束未知 |
| `null` | `t` | 开始未知，结束已知 |
| `t` | `t` | 时间点 `t` |
| `t1` | `t2`，`t1 < t2` | 时段 `[t1, t2)` |
| `t1` | `t2`，`t1 > t2` | 无效 |

`endAt` 可以是最近一次确认的时刻，事实是否已经结束按 [TIME-4](../rules/time.mdx#time-4) 判断。边界怎样取值，见 [Time](../rules/time.mdx)。

### OBSERVATION-4 只有 Observation 有事实时间 [#observation-4]

执行方：写入方

只有 Observation 保存事实时间。业务字段可以保留来源的原始时间，见 [TIME-5](../rules/time.mdx#time-5)。

### OBSERVATION-5 null 即未知 [#observation-5]

定义

边界为 `null` 表示这个边界未知。暂停、取消这类业务状态由 `content` 表达。

### OBSERVATION-6 开始不晚于结束 [#observation-6]

执行方：后端

两个边界都已知时，`startAt` 不得晚于 `endAt`。

### OBSERVATION-7 时间点 [#observation-7]

定义

`startAt` 等于 `endAt` 表示一个时间点。

### OBSERVATION-8 左闭右开 [#observation-8]

定义

`startAt` 早于 `endAt` 表示时段 `[startAt, endAt)`。前后相接的两个时段，前一个的 `endAt` 等于后一个的 `startAt`。

### OBSERVATION-9 时区 [#observation-9]

执行方：后端

`timeZone` 必须出现，值是事实所属的 IANA 时区，未知时为 `null`。读取方用它把 `startAt` 和 `endAt` 换算为当地时间。

## 版本 [#versions]

### OBSERVATION-10 一个作者 [#observation-10]

执行方：后端

一份 Observation 只有一个作者：所有版本的 `observerId` 相同。其他 Observer 写入同一份识别依据时，内容相同什么都不做，内容不同就拒绝这次写入。后续版本可以补全或纠正事实时间、时区、内容和输入集。其他 Observer 的确认或否定形成新的 Observation，见 [IDENTITY-3](../rules/identity.mdx#identity-3)。

## 形成方式 [#formation]

形成方式说明这份陈述怎么来的，它说明来由，不说明真假。前台时段是程序直接读到的，VS Code 留在前台时用户可能在开会。

| `formation` | 含义 | 例子 |
| --- | --- | --- |
| `direct` | 程序记下来源给出的内容 | 前台应用、一条助手消息、一次传感器读数 |
| `stated` | 人自己说的 | “15:00 在开会”、对一条判断的否定 |
| `computed` | 同样的输入一定得到同样的结果 | QQ 今天用了多久 |
| `extracted` | 模型只转述材料中有什么 | OCR、语音转写 |
| `inferred` | 超出材料的判断 | “QQ 号 123 是本人”、“下午在写代码” |

### OBSERVATION-11 如实声明形成方式 [#observation-11]

执行方：写入方、后端

写入方如实声明每个版本的形成方式，后端只检查取值。一个 Observer 可以形成不同形成方式的陈述。读取方要知道结论的依据里有没有推断时，沿 InputSet 查，见 [EVIDENCE-7](../rules/evidence.mdx#evidence-7)。
