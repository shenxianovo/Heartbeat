## 文字 [#prose]

文档写给第一次读这一页的人：先让读者知道在讲什么，再给约束。

- 每页开头用一两句话说清这一页讲什么。
- 先举例，再概括。公共例子用 [Walkthrough](../start/walkthrough.mdx) 里的那一天：前台状态 Observer、VS Code、晚上的推断和第二天的否定。
- 句子写完整，有主语。前后句的关系用“所以”“例如”“这时”这类词接上。简洁靠删去多余的内容，单句保持完整。
- 每句话都要让读者多知道一件事。复述、预防假想的误读、交代与当前设计无关的背景，都删掉。
- 一段只讲一件事，段落按读者需要的先后排列。
- 写是什么、由谁负责。否定句只用于规则禁止的做法。
- 只写当前的设计。规则正文写条件、例外和例子，理由写在 ADR 中。
- 一项要求或一个例子只写在一处，其他地方链接过去。链接放在读者需要跳转的地方。
- 用中性的书面语。不用“即使”“悄悄”“静默”“没有例外”这类强调词。

## 用词 [#terms]

一个概念只用一个词。术语的定义见 [Glossary](./glossary.mdx)。

| 用 | 指 | 不用 |
| --- | --- | --- |
| 已保存 | 后端已保存的版本，可以被引用 | 已经成立、已成立、被接受 |
| 本地保存 | Runtime 在本机持久保存、尚未提交的内容 | 单独的“保存” |
| 成立 | 事实为真 | 用于版本 |
| 保存时间 | `recordedAt` | 记录时间 |
| 记录 | 作名词时只指 Orisumi 为用户保存的全部数据 | 用来指单个实体、版本或观测 |
| 观测 | Observation 的中文名 | 记录、观测记录 |
| 粒度 | 一个实体或一份观测覆盖的范围 | 记录粒度 |
| 来源数据 | 来源自己提供的数据，例如浏览器的历史条目 | 来源记录 |
| 程序实例 | 有自己 EntityId 的运行中程序 | 采集器、实例、采集程序 |
| 前台状态 Observer、推断 Observer | 某一个程序实例，名字与 Observers 文档一致 | 前台状态程序、推断程序 |
| Observer 的业务代码 | 程序实例中按业务规则形成观测的部分 | Observer 的实现 |
| 停用、启用 | 在客户端中让一个已安装的 Observer 停止、恢复采集 | 暂停、关闭、打开 |
| 安装包 | 一个 Observer 在一个平台上的 ZIP 发布物 | 插件、扩展 |
| Runtime | 运行 Observer 进程、完成本地保存和发送的公共组件，设备和服务器上相同 | 宿主、守护进程、服务端 Runtime |
| SDK | 各语言连接 Runtime 的库 | SDK 库、Protocol 库 |
| 托管方身份 | 后端为一个 Runtime 分配的 `hostId` | 设备 ID |
| 删除实例 | 永久结束一个程序实例的身份，并删除它的实体 | 用来指卸载 |
| 移除托管方 | 撤销一个 Runtime 的接入，保留它已保存的数据 | 删除设备 |
| 本地回执 | Runtime 提交一个批次后返回的结果 | 确认 |
| 草稿 | Runtime 本地保存、尚未冻结的版本 | 用来指后端暂存的观测预览 |
| 观测预览 | 后端暂存的一份 Observation 尚未保存的最新陈述，内容来自它的草稿 | 实时版本、临时版本 |
| 业务类型 | 一种业务数据 | 类型定义 |
| EntitySchema | 定义业务类型的 Core 类型，以及它的每个实体 | EntitySchema 实体、单独的“Schema”、单独的“定义” |
| Schema 版本 | EntitySchema 的一个版本 | EntitySchema 版本、一版定义、结构定义 |

## 标题与导航 [#navigation]

导航的分区、分组和页面标题用英文。ADR 的标题是一项决定的名称，用中文。正文用中文。
