description: "什么是事物，何时沿用 Observation、何时形成新版本、何时新建"
---

写入前要回答两个问题：这里提到的对象是哪个事物？这份陈述是不是已有的 Observation？下表是常见情况的答案。

| 情况 | 实体 | 版本 |
| --- | --- | --- |
| 提到一个新的来源对象 | 新建事物 | 没有版本 |
| 提到已有的来源对象 | 沿用事物 | 没有版本 |
| 补全或纠正同一件事实 | 沿用 Observation | 新版本 |
| 来源中的对象变了 | 沿用 Observation | 新版本 |
| 重新读到来源，内容没有变化 | 沿用 Observation | 不形成新版本 |
| 新的独立观测 | 新建 Observation | 首版 |
| 另一个 Observer 确认、否定或陈述 | 新建 Observation | 首版 |
| 用另一种方法独立解释同一份证据 | 新建 Observation | 首版 |

例如采集器把一条工具结果误记成用户发言，修复解析器后重读日志，这是纠正：原来的交互形成一个新版本，旧版本仍可追溯。用另一个模型重新评价当天的活动，这是独立解释：形成新的 Observation。

## 共同规则 [#common]

### IDENTITY-1 业务规则定身份 [#identity-1]

执行方：写入方、后端

业务规则决定什么算同一个实体。写入方认出已有实体时沿用它，否则新建。业务规则可以用已持有的引用、来源的标识或业务上的匹配认出实体；没有自然标识的类型每次新建，或者由业务选定已有的实体。后端按写入方指出的实体保存。

### IDENTITY-2 身份与 Observer 无关 [#identity-2]

执行方：写入方

事物的身份由业务规则决定，与提到它的 Observer、运行它的托管方和编写它的语言无关。例如同一台 Mac 上的两个程序实例提到 QQ 这个本机应用，得到同一个事物，各自形成观测。

## Observation [#observation]

### IDENTITY-3 独立观测，新建实体 [#identity-3]

执行方：写入方

新的独立观测使用新的 EntityId。另一个 Observer 的确认、否定或陈述，以及用另一种方法对同一份证据作出的独立解释，都形成新的 Observation，见 [UNDERSTANDING-2](./understanding.mdx#understanding-2)。

### IDENTITY-4 补全纠正，出新版本 [#identity-4]

执行方：写入方

补全或纠正同一件事实时，形成原 Observation 的新版本。例如前台时段随每次确认延长，纠正填错的时区，或者修复解析错误后纠正原来的交互；从时间点补全为时段，也是这种情况。

一次处理是新观测还是原观测的新版本，取决于它陈述的是不是同一件事实。重读、程序升级和执行的次数都不决定这一点。补全不得把几次独立的读数合并为同一份 Observation。

### IDENTITY-5 Observation 的粒度 [#identity-5]

执行方：写入方

Observation 的粒度由业务规则决定：来源中的内容变化时，是形成新版本，还是新建一份。来源的性质决定这一点：

| 来源 | 实体 | 变化 |
| --- | --- | --- |
| 保留历史，例如日志 | 一条来源数据一份 Observation，类型声明 `immutable` | 新的 Observation |
| 只给当前状态，例如日历事件 | 一个对象一份 Observation，每次写入完整内容 | 新版本，事实时间写在这一版上 |

例如 Codex 的索引文件追加每次改名，所以每次改名是一份 Name，会话本身是事物。日历事件改时间时，来源只给出新的时间，所以它形成日历事件的新版本。

对象本身是事物。一个对象的内容只能读到一部分，或者会变的部分来自不同的来源时，各写成单独的 Observation，它们引用同一个事物。

## 识别 [#recognition]

### IDENTITY-6 不补造身份 [#identity-6]

执行方：写入方

来源缺少稳定标识时，写入方按已有证据识别实体，不得补造来源身份；证据不足以确定的字段保持未知。作用范围不同的同名标识属于不同的实体，例如两台设备上同名的应用。作用范围由业务规则决定，例如设备、账号、浏览器 profile 或一个来源会话；托管方和程序实例不是来源对象的作用范围。

Observer 为自己形成的理解新建事物时，用自己范围内的依据，见 [THING-4](../model/thing.mdx#thing-4)。

### IDENTITY-7 识别依据 [#identity-7]

执行方：后端

识别依据是认出实体所用的一组值：业务类型、作用范围、标识方案和标识的值。事物和 Observation 都可以有识别依据。一份识别依据最多对应一个实体，一个实体可以有多份，也可以没有。实体的身份始终是 EntityId：识别依据随实体删除，之后读到同一个来源对象时，它是一个新实体。

### IDENTITY-8 各说各的 [#identity-8]

执行方：写入方

多个 Observer 要对同一个事物各写一份内容时，把 Observer 的 EntityId 放进识别依据的 `scope`。例如两个 Observer 都写设备的描述，改名后各自形成新版本，互不影响。识别依据是全局的，所以其他 Observer 写入同一份依据时按 [OBSERVATION-10](../model/observation.mdx#observation-10) 处理。
