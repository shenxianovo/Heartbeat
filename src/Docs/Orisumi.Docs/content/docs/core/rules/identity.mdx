---
title: "Identity"
description: "何时沿用实体、何时形成新版本、何时新建实体"
---

形成一个版本前，写入方要先回答一个问题：这是不是已有的实体？下表是常见情况的答案。

| 情况 | 实体 | 版本 |
| --- | --- | --- |
| 按业务规则认出已有实体，内容有变化 | 沿用 | 新版本 |
| 补全或纠正同一件事实 | 沿用 | 新版本 |
| 重新读到来源，内容没有变化 | 沿用 | 不形成新版本 |
| 新的独立观测 | 新实体 | 首版 |
| 另一个 Observer 确认、否定或陈述 | 新实体 | 首版 |
| 用另一种方法独立解释同一份证据 | 新实体 | 首版 |

例如采集器把一条工具结果误记成用户发言，修复解析器后重读日志，这是纠正：原来的交互和 Observation 各形成一个新版本，旧版本仍可追溯。用另一个模型重新评价当天的活动，这是独立解释：形成新的 Observation。

## 共同规则 [#common]

### IDENTITY-1 业务规则定身份 [#identity-1]

执行方：写入方、后端

业务规则决定什么算同一个实体。写入方认出已有实体时，形成它的新版本，否则新建实体。业务规则可以用已持有的引用、来源的标识或业务上的匹配认出实体；没有自然标识的类型每次新建，或者由业务选定已有的实体。后端按写入方指出的实体保存。

### IDENTITY-2 身份与 Observer 无关 [#identity-2]

执行方：写入方

业务实体的身份由业务规则决定，与形成它的 Observer、运行它的托管方和编写它的语言无关。同一个 Observer 可以形成很多业务实体，多个 Observer 也可以观测同一个业务实体。例如同一台 Mac 上的两个程序实例共用 QQ 这个本机应用，各自形成观测。

## Observation [#observation]

### IDENTITY-3 独立观测，新建实体 [#identity-3]

执行方：写入方

新的独立观测使用新的 EntityId。另一个 Observer 的确认、否定或陈述，以及用另一种方法对同一份证据作出的独立解释，都形成新的 Observation。

### IDENTITY-4 补全纠正，出新版本 [#identity-4]

执行方：写入方

补全或纠正同一件事实时，形成原 Observation 的新版本。例如前台时段随每次确认延长，纠正填错的时区，或者修复解析错误后纠正原来的交互；从时间点补全为时段，也是这种情况。

一次处理是新观测还是原观测的新版本，取决于它陈述的是不是同一件事实。重读、程序升级和执行的次数都不决定这一点。补全不得把几次独立的读数合并为同一份 Observation。

## 观测内容 [#content]

### IDENTITY-5 内容的粒度 [#identity-5]

执行方：写入方

观测内容的粒度由业务规则决定：内容变化时，是形成内容实体的新版本，还是新建一个实体。来源的性质决定这一点：

| 来源 | 实体 | 变化 |
| --- | --- | --- |
| 保留历史，例如日志 | 一条来源数据一个实体，内容不再改变 | 新的实体 |
| 只给当前状态，例如日历事件 | 一个对象一个实体，每次写入完整内容 | 新版本 |

例如 Codex 的索引文件追加每次改名，所以每次改名是一条会话标题，会话本身只有身份。日历事件改时间时，来源只给出新的时间，所以它形成日历事件的新版本。

一个实体的内容如果只能读到一部分，或者由多个写入方共用，它只放不变的内容，会变的部分定义为单独的业务类型。

## 识别 [#recognition]

### IDENTITY-6 不补造身份 [#identity-6]

执行方：写入方

来源缺少稳定标识时，写入方按已有证据识别实体，不得补造来源身份；证据不足以确定的字段保持未知。作用范围不同的同名标识属于不同的实体，例如两台设备上同名的应用。作用范围由业务规则决定，例如设备、账号或浏览器 profile；托管方和程序实例不是作用范围。

### IDENTITY-7 识别依据 [#identity-7]

执行方：后端

识别依据是认出实体所用的一组值：业务类型、作用范围、标识方案和标识的值。一份识别依据最多对应一个实体，一个实体可以有多份，也可以没有。实体的身份始终是 EntityId：识别依据随实体删除，之后读到同一个来源对象时，它是一个新实体。
