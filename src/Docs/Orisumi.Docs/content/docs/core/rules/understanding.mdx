来源只能告诉 Orisumi 发生了什么。“QQ 号 123 是本人”“这两个设备是同一台机器”这类理解，采集时拿不到，靠人录入也不现实。所以这些理解由模型读已保存的数据形成，用户只在发现错误时否定。

这一页写理解怎样形成、怎样纠正，以及三种公共的业务类型。理由见 [ADR · 模型形成的理解](../../adr/understanding.mdx)。

| 层 | 例子 | 谁产生 | 保存方式 |
| --- | --- | --- | --- |
| 证据 | QQ 号 123 发了这句话 | Observer | 永久保存，尽量保留原样 |
| 世界知识 | QQ 是腾讯的软件 | 模型自带 | 读取时现取，不保存 |
| 私有理解 | 123 是本人，某人是高中同学 | 模型推断，用户纠正 | 保存为 Observation，可以出错和重做 |

## 形成 [#forming]

### UNDERSTANDING-1 采集时不判断关系 [#understanding-1]

执行方：写入方

采集时只记下来源给出的内容，提到来源中的对象。来源没有直接给出的关系留给理解。例如 QQ 的采集只记发送者是 QQ 号 123，“123 是本人”由模型另外陈述。

### UNDERSTANDING-2 判断互不覆盖 [#understanding-2]

执行方：写入方

每次判断形成新的 Observation，新旧判断都保留，所以能看到认识怎样变化。模型变强后可以重读过去的数据，再形成一批判断。

### UNDERSTANDING-3 现取的内容不保存 [#understanding-3]

执行方：写入方

世界知识和叙事在读取时由模型现取，不保存。只有私有理解，以及软件要用来计算的结果，才保存为 Observation。

## 复核 [#review]

### UNDERSTANDING-4 当前理解 [#understanding-4]

执行方：读取方

当前理解是没有被否定、也没有被取代的陈述。用户确认过的陈述，模型的取代不生效。认识的变化是这些陈述和它们的复核按保存时间排列的结果。

### UNDERSTANDING-5 复核 [#understanding-5]

执行方：写入方

确认、否定和取代都写成一份 [Review](#review-type)，被复核的陈述保持原样。复核的事实时间说明它针对哪一段；只否定一段时，当前理解保留这条陈述，读取方按时间判断。

撤销一条判断是否定它，只有用户要抹掉数据时才删除，见 [History · 删除](./history.mdx#deletion)。

### UNDERSTANDING-6 取代由模型声明 [#understanding-6]

执行方：写入方

新判断取代旧判断时，由形成它的 Observer 写一份 `verdict` 为 `supersede` 的 Review。只有 Observer 自己知道两条判断是否在回答同一个问题。

### UNDERSTANDING-7 记得否定 [#understanding-7]

执行方：写入方

形成判断前，Observer 读取相关的否定并列入输入。类型固定的判断，Observer 在写入前跳过用户否定过的结论；模型又写出被否定的结论时，用户再否定一次。

### UNDERSTANDING-8 依据被否定 [#understanding-8]

执行方：读取方

一条陈述的 InputSet 中有被否定的陈述时，读取方把它标记为依据已被否定，并能找到被否定的那一条。是否重新处理由下一轮的 Observer 决定，见 [EVIDENCE-8](./evidence.mdx#evidence-8)。

## 公共类型 [#common-types]

这些业务类型由 Core 定义，后端内置，所有 Observer 不用声明就能使用，读取方都能理解。

### Review [#review-type]

对一条陈述的确认、否定或取代。

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-00000000000e` |
| 显示名称 | 复核 |
| 说明 | 表示对一条陈述的确认、否定或取代。事实时间是它针对的那一段，未知时针对整条陈述。 |
| 资源名 | `reviews` |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| `targetVersionId` | `reference`，目标为版本 | 是 | 否 | 被复核的陈述的版本 |
| `verdict` | `string` | 是 | 否 | `confirm` 确认、`deny` 否定或 `supersede` 取代 |
| `text` | `string` | 是 | 是 | 复核的说明，例如用户写下的“在开视频会议” |

### Relation [#relation]

模型发现的关系。关系不用预先定义类型，软件要用来计算的关系才单独定义，例如线索归属。

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-00000000000f` |
| 显示名称 | 关系 |
| 说明 | 表示两个事物之间的一种关系。事实时间是这个关系成立的时段。 |
| 资源名 | `relations` |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| `subjectId` | `reference`，目标为事物 | 是 | 否 | 关系的主语 |
| `predicate` | `string` | 是 | 否 | 关系的说法，例如“是本人”。`same-as` 表示两个事物是同一个，见 [THING-5](../model/thing.mdx#thing-5) |
| `objectId` | `reference`，目标为事物 | 是 | 否 | 关系的宾语 |
| `text` | `string` | 是 | 是 | 补充说明 |

### Name [#name]

事物的名字：设备名、产品名、会话标题和人的称呼都用它。来源、模型和用户都可以写。

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-000000000010` |
| 显示名称 | 名字 |
| 说明 | 表示一个事物的名字。事实时间是这个名字成立的时段，未知时为 null。 |
| 资源名 | `names` |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| `thingId` | `reference`，目标为事物 | 是 | 否 | 被命名的事物 |
| `name` | `string` | 是 | 否 | 名字的原文 |

### 事物的类型 [#thing-types]

| 项目 | 程序实例 | 人 |
| --- | --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-000000000012` | `019e1bbb-ec00-7000-8000-000000000006` |

### UNDERSTANDING-9 取名字 [#understanding-9]

执行方：读取方

显示事物时，在当前理解的 Name 中取用户写下的一条，其次取保存时间最晚的一条。
