本定义表达“设备处于休眠或清醒状态的时段”，由[设备状态 Observer](../device-state.mdx)形成观测。状态时间段的方向已确认，以下字段与具体边界为草案。尚未实现，固定 SchemaId 尚未分配。

## 数据结构

Data 只实现 `IEntity`，状态时间由 Observation 保存。最小草案用一个字段记录状态：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `state` | 字符串枚举 | `awake` 表示设备清醒，`asleep` 表示设备休眠 |

清醒只描述设备状态，不证明会话未锁定、存在键鼠输入或用户正在使用。没有状态证据时保留未知，不能仅凭没有采样或输入生成休眠事实。

### JSON 结构草案

以下定义描述具体数据内容，不包含 `IEntity.Id` 或 Observation 的身份、时间字段。

```json
{
  "type": "object",
  "properties": {
    "state": {
      "type": "string",
      "enum": ["awake", "asleep"]
    }
  },
  "required": ["state"],
  "additionalProperties": false
}
```

### 数据示例

```json
{
  "state": "asleep"
}
```

## 事实时间

Observation 保存状态的已知起止边界。已知起止边界的时段使用左闭右开区间 `[StartAt, EndAt)`，未知边界遵循 [ITimed](../../core/model/contracts/timed.mdx#边界语义)。`EndAt = null` 不证明设备此刻仍处于该状态。

系统休眠／唤醒证据如何确定边界、启动时如何取得状态、崩溃或停止后的空白如何处理，尚需确认。状态观测不以提交时刻补齐历史边界。

## 定义与实现状态

各平台遵循同一状态含义、字段和时间规则时，共用一份定义。当前没有设备状态采集实现；本页字段、约束与边界规则需确认后实施。锁屏和用户活跃规则另行讨论。
