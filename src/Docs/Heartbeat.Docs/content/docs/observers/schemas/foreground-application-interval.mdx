本定义表达“应用 A 处于前台的时段”。[前台状态 Observer](../foreground-state.mdx)负责形成观测。

连续采集尚未实现，固定 SchemaId 尚未分配。

## 数据结构

观测内容实现 [IEntity](../../core/model/contracts/entity.mdx)。以下示例展示两个业务字段，不包含内容实体自身的 ID：

```json
{
  "localApplicationId": "01a12e31-9050-7000-8000-000000000001",
  "name": "Visual Studio Code"
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `localApplicationId` | EntityId | 引用观测发生的设备上的[本机应用实体](../entities/local-application.mdx) |
| `name` | 字符串或 `null` | 保留当时实际读到的应用名称；未取得名称时为 `null` |

未取得名称时，观测内容仍引用本机应用实体：

```json
{
  "localApplicationId": "01a12e31-9050-7000-8000-000000000001",
  "name": null
}
```

`identifiers` 由本机应用实体保存，不放在本观测内容中。起止时间由 Observation 保存。

本机应用的身份范围、标识线索与跨平台关联见[本机应用](../entities/local-application.mdx)。

## 事实时间

“应用使用”表示前台时长。Observation 按以下边界记录时间：

- 采集器第一次确认应用在前台时，开始时段。
- 采集器确认切换应用时，结束原应用时段。
- 如果设备休眠、采集停止或读取失败，采集器在最后一次确认的位置结束时段。
- 采集恢复后，采集器新建时段。中间空白不计入前台时长。

已知起止边界的时段使用左闭右开区间 `[StartAt, EndAt)`，见 [ITimed](../../core/model/contracts/timed.mdx#边界语义)。标题变化不切开应用时段。如果标题读取失败，仍可形成应用观测。

如果采集连续且完整观测内容相同，采集器延长同一时段。如果 `localApplicationId` 或 `name` 变化，采集器新建时段。每段引用的内容必须保持一致。

是否排除锁屏或无输入时段，由后续分析规则确定。

## 定义与实现状态

本定义表达时段，单次读数表达时间点。实施时，应用时段必须使用自己的定义和固定 ID。规则见[定义更新](../../core/model/observations/schema.mdx#定义更新)。

当前程序只提交单次读数。数据仍包含 `bundleIdentifier`、`name`、`executablePath`，契约见[当前单次读数](../foreground-state.mdx#当前单次读数)。应用身份分层与新观测字段尚未加入代码，也没有对应的数据库记录。
