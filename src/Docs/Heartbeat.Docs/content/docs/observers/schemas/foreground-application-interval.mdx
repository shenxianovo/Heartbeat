本定义表达“应用 A 处于前台的时段”。[前台状态 Observer](../foreground-state.mdx)负责形成观测。

## 数据结构

观测内容实现 [IEntity](../../core/model/contracts/entity.mdx)。以下示例展示内容的业务字段，不包含内容自身的 ID：

```json
{
  "localApplicationId": "01a12e31-9050-7000-8000-000000000001",
  "name": "Visual Studio Code"
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `localApplicationId` | EntityId，必填且不可为空值 | 引用观测设备上的[本机应用](../entities/local-application.mdx) |
| `name` | 字符串或 `null`，必填 | 保留当时读到的名称；未取得时为 `null` |

应用标识线索由本机应用保存。起止时间由 Observation 保存。

## 实体定义与保存

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-000000000001` |
| 资源名 | `foreground-application-periods` |

先[登记实体定义](/api/saveEntitySchema)，再向 `PUT /entities/foreground-application-periods/{内容标识}` 提交。引用和普通属性分别放入对应对象，同一值只提交一次：

```json
{
  "references": {
    "localApplicationId": "01a12e31-9050-7000-8000-000000000001"
  },
  "properties": {
    "name": null
  }
}
```

## 事实时间

“应用使用”表示前台时长。连续确认期间，应用身份、名称和记录时区都相同时，采集器延长同一条 Observation。内容实体和起始时间保持不变，结束时间更新为最后一次确认的时刻。

| 事件 | 原时段 | 后续时段 |
| --- | --- | --- |
| 首次确认应用位于前台 | 无 | 从确认时刻开始 |
| 确认切换应用、名称变化或时区变化 | 结束于新确认时刻 | 从同一时刻开始 |
| 读取失败、停止采集或采集器退出 | 保留最后一次已保存的确认时刻 | 恢复后新建 |
| 两次确认间隔超过采样间隔的 3 倍 | 保留最后一次确认时刻 | 从恢复确认时刻开始 |
| 检测到休眠或系统时间跳变 | 保留最后一次确认时刻 | 从恢复确认时刻开始 |

已知起止时间使用左闭右开区间 `[StartAt, EndAt)`。只有一次确认时，起止相同，记录一个时间点，时长为零。时间含义见 [ITimed](../../core/model/contracts/timed.mdx#边界语义)。

应用激活事件触发确认，默认每 1 秒再读取一次作为兜底。实际确认间隔超过 3 秒时断开。兜底间隔可以调整，断开阈值始终为其 3 倍。网络发送独立运行，不占用采集等待时间。

macOS 实现比较包含休眠的计时与不含休眠的计时。两次采样间的差异超过 100 毫秒时，采集器断开时段。系统时间倒退、重复，或系统时间增量与持续计时增量相差超过 100 毫秒时，也断开。100 毫秒容差内的休眠或时间跳变不能可靠区分。

应用事件可以记录两次定时确认之间的切换。事件遗漏时，定时读取只能发现当前状态，无法补回期间短暂切换又返回的应用。时段边界使用确认时刻，可能晚于实际切换。

## 内容与历史

名称和本机应用引用发生变化时，采集器新建内容与观测，不覆盖原内容。标题变化不切开应用时段。是否排除锁屏或无输入时间，由后续分析规则决定。

进行中的时段只在本地更新已确认的结束时间。时段结束后，完整内容进入 Outbox 并发送到后端。已进入 Outbox 的时段不再延长。程序重启后，先按最后一次本地确认结束遗留时段，再另开时段，不补齐停机空白。

实现、保存和失败规则见[前台状态](../foreground-state.mdx)。
