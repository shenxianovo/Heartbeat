## 原生管道实际检查了什么

`SourcePipelineTests.NativeImportSurvivesSqliteRestartAndApiReadback` 读取 Graph、Slack、Gmail、OTLP、CloudEvents、Debezium、ICS、GPX 的合成原生材料，再执行：

1. 按来源规则生成固定 Schema、属性、引用和时间
2. SQLite 保存身份、历史证据及 Outbox，关闭并重新打开
3. 重放相同材料，核对持久 UUID 和 Observation 身份
4. 通过实际 HTTP API 写入独立 PostgreSQL 测试库
5. 在后续 GET 中逐项核对所有实体的类别、定义身份、引用、属性及 Observation 时间
6. 只有读回一致后确认 Outbox；合法 Schema 显示名修改不被回放覆盖

`LiveProcessCaptureReachesActualApi` 和 `LiveLocalCaptureReachesActualApi` 分别使用实际 Linux procfs、临时 Git 仓库和隔离二进制文件。它们不依赖私人邮箱、聊天、定位或健康数据。

专项管道通过不会自动补齐 100 项中的来源业务缺口。例如，before/after 都能读回仍不证明主键切换关联；GPX 点能存储仍不证明 Android boot/accuracy；ICS 能保留 DATE 仍不等于 Google Calendar API 接通。

## 数据库与运行环境限制

标准测试/开发环境按项目配置使用 PostgreSQL 18.6 与 Testcontainers/Docker。本次受环境限制，集成测试使用 PostgreSQL 17.11 的隔离替代启动器；API、EF/Npgsql、迁移及每测试数据库隔离逻辑仍实际执行。

因此 `251 / 251` 是 **PostgreSQL 17.11 替代环境**的结果，不是 18.6 容器或完整 Aspire 的运行结果。标准容器流程、Aspire 端到端启动、线上来源鉴权与生产部署未验证。

本轮 Linux 无法运行原生 macOS 前台读取；A01–A03 的既有 timeline/registry 模拟测试和存储测试有执行证据，实际 macOS 应用切换、休眠及安装变化没有新增实跑证据。
