这一页展示业务实体定义的写法。页首复用 Input Event 的共享图作展示，实际业务规则以 [Input Event](../../input-events/input-event.mdx) 为准。编写时先用一段话说明一条实体表达什么、是否承担观测内容角色、由哪个 Observer 形成。

## 记录粒度

说明什么构成一条记录，何时延续同一条，何时新建。用一个具体例子解释业务边界；更新或结束由业务决定，不交给 SDK 推断。

## 身份

说明同一实体的判断依据、来源标识的作用范围、重启或重放如何处理。不要将 Observer 身份与业务实体身份混为一谈。

## 引用

| 字段 | 目标与含义 |
| --- | --- |
| 待填写 | 填写引用目标及其业务含义，链接到对应定义 |

没有引用时直接说明没有引用，提交的 `references` 为 `{}`；尚未确定的引用列入“待定”。

## 事实时间

说明对应 Observation 是时间点还是时段，时间取自哪里，已知和未知边界如何表达，补全时如何处理。若它只是独立业务对象，说明时间由哪些观测表达即可。

## Schema

| 项目 | 值 |
| --- | --- |
| SchemaId | 填写该定义的稳定标识，未确定时写“待定” |
| 显示名称 | 填写显示名称 |
| 说明 | 填写业务事实、记录粒度与事实时间的取值规则；正式提交时必填，不允许 `null` 或空字符串 |
| 资源名 | 填写保存入口的资源名，未确定时写“待定” |

| 字段 | 类型 | 必填 | 可空 | 含义 |
| --- | --- | --- | --- | --- |
| 待填写 | 待填写 | 待定 | 待定 | 填写含义、来源与省略规则 |

引用与普通属性放在同一字段表中，以 `reference` 和其他类型区分。对象成员和数组元素逐项列出。具体声明格式见 [EntitySchema · 字段约束](../../../core/model/schema.mdx#constraints)。

## 示例

提供符合本页 Schema 的业务实体示例，引用放在 `references`，普通属性放在 `properties`。以下用已有 Input Event 的最小内容展示共用格式；它不是为本模板登记的新 Schema：

```json
{
  "references": {},
  "properties": {
    "kind": "keyDown"
  }
}
```

具体业务的 Schema 元信息与提交示例见 [Input Event](../../input-events/input-event.mdx#schema)。
