.NET 运行环境中的 Observer 复用 .NET 提交 SDK。SDK 使用 SQLite Outbox 保存待发送内容，并遵循[共同提交约定](./index.mdx)处理发送、确认与重试。

## SQLite Outbox

1. 将业务交来的记录与更新先写入 SQLite，按所选提交策略决定何时允许发送。
2. 后台读取待发送项并上传。失败或响应不确定时保留原内容，后续继续重试。
3. 后端完成保存并返回 `201` 或 `204` 后，移除对应待发送项。
4. 程序重启后，继续处理 SQLite 中尚未确认的待发送项。

重试保留同一份内容的实体身份、引用、属性和事实时间。已有待发送项的确认不能删除发送期间产生的新补全；同一记录尚未发送的连续补全可以合并，不同记录分别保留。具体幂等语义见[幂等重试](./index.mdx#幂等重试)。

## 运行与状态

SDK 启动时恢复 SQLite 中的待发送项，退出前完成已接收内容的本地保存。网络连接中断不要求业务停止采集，下次运行或网络恢复后继续发送。

SDK 统一处理后端地址、请求组织与响应解析，并向调用方反馈待发送数量、记录的成功确认与失败原因。共同约定见[后端连接与协议封装](./index.mdx#后端连接与协议封装)和[发送状态反馈](./index.mdx#发送状态反馈)。

## 业务接入

- 接入时提供稳定的 Observer 身份与所需 Schema，由 SDK 先登记主体和定义。
- 按业务记录类型选择及时提交或结束后提交。
- 把新形成或补全的实体与观测交给 SDK，并由业务明确通知记录何时结束。

应用切换判断、事实时间、内容身份与历史保留属于业务。SDK 不负责读取前台应用或解析来源材料，业务也不自行维护网络重试循环。
