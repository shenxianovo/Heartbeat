本内容表达“这一段前台应用活动中，当前焦点窗口显示标题 T”，由[前台状态 Observer](./index.mdx)形成观测。通过 `foregroundObservationId` 引用对应的[前台应用时段](./foreground-application-period.mdx)的 Observation，可以沿该观测的内容找到本机应用。

这里引用的是持续补全的整段前台应用观测，不是每次采样或事件回调。标题内容不重复保存本机应用引用，也不为具体窗口建立独立身份。

## 记录粒度

应用时段与标题时段分别形成 Observation。同一次读取取得应用、焦点窗口和标题，再分别判断两条时间线如何更新。

| 情况 | 应用时段 | 标题时段 |
| --- | --- | --- |
| Chrome 内从“邮箱”窗口切到“文档”窗口 | 沿用原观测 | 结束旧标题观测，开始新标题观测；两者引用同一个前台应用观测 |
| 同一窗口的标题改变 | 沿用原观测 | 结束旧标题观测，开始新标题观测 |
| 同一应用内切换窗口，但标题相同 | 沿用原观测 | 可以延续同一条标题观测 |
| 前台应用时段结束或新建 | 结束旧观测或开始新观测 | 随父时段结束；属于新父时段的标题形成新观测，即使文字相同 |

窗口切换是重新读取标题的触发条件，窗口身份本身不属于本业务记录的内容。

## 身份

标题内容通过 `foregroundObservationId` 归属整段前台应用观测，不为具体窗口建立独立身份。内容身份及标题变化后的复用规则待定。

## 引用

| 字段 | 目标 |
| --- | --- |
| `foregroundObservationId` | 对应前台应用时段的 Observation；通过其内容关联本机应用 |

## 事实时间

时间段 Observation，遵循 [Observation · 事实时间](../../core/model/observation.mdx#fact-time)。标题时间线独立更新，范围位于引用的前台应用时段之内。连续确认同一父时段中的相同标题时，可以保留原起始边界，补全到最近一次确认的时刻。

## Schema

| 项目 | 值 |
| --- | --- |
| SchemaId | 待定 |
| 显示名称 | 前台窗口标题时段 |
| 说明 | 表达一段前台应用活动中当前焦点窗口的标题；内容引用父级前台应用观测，Observation 保存标题时段。 |
| 资源名 | 待定 |

| 字段 | 类型 | 必填 | 可空 | 含义 |
| --- | --- | --- | --- | --- |
| `foregroundObservationId` | `reference` | 待定 | 待定 | 对应前台应用时段的 Observation |
| `title` | `string` | 待定 | 待定 | 前台窗口标题原文；读到空标题时为 `""` |

标题保存原文，不解析文件、项目或网页。其他主体解释标题形成的新事实使用该主体的 `ObserverId`。

## 示例

```json
{
  "references": {
    "foregroundObservationId": "01a151e3-1900-7000-8000-000000000030"
  },
  "properties": {
    "title": "Heartbeat — Codex"
  }
}
```
