`LocalApplication` 表示某台设备上的一个应用安装。前台应用观测通过 `localApplicationId` 引用本机应用。

## 实体身份

本机应用实现 [IEntity](../../core/model/contracts/entity.mdx)，具有独立的 EntityId。应用身份与 Observer 实例身份分别保存。同一台设备上的多个采集器实例共用本机应用登记文件。

两台 Mac 上的 VS Code 分别拥有本机应用实体。即使应用标识和安装路径相同，不同设备也分别生成身份。本机登记文件只属于创建它的设备，不得复制到另一台设备使用。文件路径和参数见采集程序 README。

## 识别与复用

macOS 采集器按应用包标识和可执行文件路径的原始值识别安装。两个值都相同时，采集器复用本机应用身份。比较区分大小写，不按名称、路径别名或软件品牌合并。

| 变化 | 身份处理 |
| --- | --- |
| 应用名称变化 | 复用身份，观测保留新名称 |
| 应用退出后重新启动 | 标识与路径不变时复用身份 |
| 采集器重启或升级 | 从登记文件复用身份 |
| 应用原地升级 | 标识与路径不变时复用身份 |
| 应用移动或可执行文件路径变化 | 新建身份 |
| 同一路径出现不同包标识 | 新建身份 |
| 原路径卸载后重装，包标识相同 | 复用身份；现有证据不能区分两次安装 |
| 包标识缺失，但路径存在 | 使用“缺少包标识＋路径”识别；之后读到包标识时新建身份 |

如果没有可执行文件路径，包标识不足以区分同一设备上的多个安装。采集器只在本次运行中，按进程号、进程启动时间和包标识复用临时身份。进程重新启动或采集器重启后，新建身份。如果进程号或启动时间也不可用，每次读数使用新身份。

如果登记文件损坏，采集器报告错误并保留原文件。删除登记文件后，下次采集会重新分配应用身份。创建与更新使用互斥锁和文件替换，避免并发登记产生多个身份或覆盖其他条目。

## 标识线索

`identifiers` 保存平台取得的标识线索，每项包含 `scheme` 和 `value`。线索不作为 Heartbeat EntityId。列表顺序不影响含义。

| scheme | value |
| --- | --- |
| `macos.bundle-id` | 原始应用包标识 |
| `macos.executable-path` | 原始可执行文件路径 |

缺失的线索不加入列表。全部缺失时使用 `[]`。本机应用不保存展示名称；历史名称由观测内容保存。

## 实体定义与保存

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-000000000002` |
| 资源名 | `local-applications` |
| 字段 | `identifiers`，必填且不可为空值；允许空列表 |

先[登记实体定义](/api/saveEntitySchema)，再向 `PUT /entities/local-applications/{本机应用标识}` 提交：

```json
{
  "references": {},
  "properties": {
    "identifiers": [
      { "scheme": "macos.bundle-id", "value": "com.microsoft.VSCode" },
      {
        "scheme": "macos.executable-path",
        "value": "/Applications/Visual Studio Code.app/Contents/MacOS/Electron"
      }
    ]
  }
}
```

每项的 `scheme` 和 `value` 都是必填、不可为空值的字符串。实体只保存这份定义声明的字段。

## 与观测的关系

[前台应用时段](../schemas/foreground-application-interval.mdx)保存本机应用引用和当时读到的名称。Observation 保存事实时间。名称变化会新建观测内容，不修改旧内容。

实体引用通过 Core 的[引用枚举契约](../../core/model/contracts/entity.mdx#约定)参与关系图。业务定义引用的含义。

## 跨平台关联

跨平台应用表示多台设备或多个平台上的同一个软件。确认两个本机应用属于同一软件后，业务可以建立关联。采集器保留本机证据，不判断其他平台的软件身份。

例如，Mac 甲和 Mac 乙分别生成本机应用 A、B。业务可以将 A、B 关联到同一个跨平台应用 S。没有跨平台关联时，本机应用和观测仍可独立保存。关联的维护方、依据和保存方式单独确定。

身份与持久化职责见 [ADR 0012](../../adr/0012-foreground-application-periods.mdx)。
