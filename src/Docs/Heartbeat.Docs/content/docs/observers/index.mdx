title: "概览"
description: "观测主体、平台客户端与实体定义"
---

Observer 是实际形成观测的主体。每个主体实例拥有稳定的 `ObserverId`。API、数据源、输出类型和进程不同，不直接要求拆分主体。通用定义见 [Observer](../core/model/observations/observer.mdx)。

平台客户端组合并运行 Observer。多个 Observer 可以运行在同一进程中。

如果客户端只传输已有观测，客户端必须保留原 `ObserverId`。如果主体形成新的聚合观测，新观测使用聚合主体的 `ObserverId`。

聚合数据保存具体 Observer 实例的引用。实体定义说明引用字段。如果数据结构、约束、事实含义和时间规则一致，各平台实现可以共用定义。分工决定见 [ADR 0002](../adr/0002-observer-capabilities-and-platform-clients.mdx)。

## 文档结构

侧栏按以下分区组织：

| 分区 | 内容 |
| --- | --- |
| Observers | 实例身份、使用的实体定义和事实时间 |
| Entities | 被观测的实体，例如[本机应用](./entities/local-application.mdx) |
| EntitySchemas | 业务实体定义的含义、数据示例和字段约束 |

## 目标与职责

| Observer | 目标观测 | 时间形式 |
| --- | --- | --- |
| [前台状态](./foreground-state.mdx) | [前台应用时段](./schemas/foreground-application-interval.mdx) | 时间段 |
| [前台状态](./foreground-state.mdx) | [前台窗口标题时段](./schemas/foreground-window-title.mdx) | 时间段，独立于应用时间线 |
| [输入事件](./input-events.mdx) | [键鼠输入事件](./schemas/input-event.mdx) | 事件发生的时间点 |
| [设备状态](./device-state.mdx) | [设备休眠与清醒](./schemas/device-state.mdx) | 时间段 |

三个 Observer 分别拥有实例身份。三个 Observer 可以运行在同一程序中。前台状态实例使用两份 EntitySchema，分别定义应用和标题事实。

“应用使用”表示前台时长。设备清醒、会话未锁定和近期存在输入是三种事实。阅读或观看视频时，用户可能没有键鼠输入。

“用户活跃”的判断规则和锁屏责任归属尚未确定。是否从前台时长排除锁屏或无输入时段，也需确认。

采集器可以在内存中保留当前应用和标题。采集器无需保存每次采样。

采集器必须保留历史 Observation 引用的内容，不得覆盖。结束时间未知不证明应用此刻仍在前台。

## 当前实现

| Observer | 已实现范围 | 文档 |
| --- | --- | --- |
| 前台状态 | macOS 前台应用单次读取、提交和读回核对 | [前台状态](./foreground-state.mdx) |

当前程序位于 `src/Observers/Heartbeat.Observer.ForegroundState/`。现有应用读数契约见[当前单次读数](./foreground-state.mdx#当前单次读数)。

窗口标题、Windows、连续采集、输入事件、锁屏和休眠采集尚未实现。

本机应用实体表示某台设备上的一个应用安装。不同设备上的安装分别保留实体身份，可以关联到同一个跨平台应用实体。规则见 [ADR 0002](../adr/0002-observer-capabilities-and-platform-clients.mdx#应用身份)。

应用观测保存 `localApplicationId` 与当时读到的 `name`。本机应用识别与跨平台关联规则仍需确认。标题、输入事件和设备状态的字段仍为草案。四份实体定义尚未分配固定 SchemaId。
