Heartbeat API 保存和读取实体。实体模型见 [Heartbeat Core](../core/index.mdx)。请求字段与响应结构以各接口页为准。

## 服务入口

NGINX 使用 `/api` 作为 API 服务前缀。OpenAPI 的 `servers` 声明相对地址 `/api`，请求地址由服务前缀和接口路径组成。例如，`GET /entities/{id}` 对外为 `GET /api/entities/{id}`。

8080 提供业务/API 入口。3000 提供文档入口，并转发 `/api/entities/…` 请求。接口页的 Playground 使用文档站的同源入口。

## 实体提交

| 路径 | 提交模型 | 接口参考 |
| --- | --- | --- |
| `PUT /entities/{id}` | 通用领域实体，包含[具体数据](../core/model/observations/data.mdx)和[具体关系实体](../core/model/relations/relation.mdx) | [保存通用实体](/api/saveEntity) |
| `PUT /entities/observations/{id}` | [Observation](../core/model/observations/observation.mdx) | [保存观测](/api/saveObservation) |
| `PUT /entities/observers/{id}` | [Observer](../core/model/observations/observer.mdx) | [保存观测主体](/api/saveObserver) |
| `PUT /entities/observation-schemas/{id}` | [ObservationSchema](../core/model/observations/schema.mdx) | [保存观测定义](/api/saveObservationSchema) |

### 输入

路径声明模型类别。路径中的 `id` 必须是采集程序生成的 UUIDv7。

请求体必须是 JSON 对象，包含实体除 `id` 外的全部属性。请求体不得包含根级 `id`。属性类型和必填项见各接口的 OpenAPI Schema。

请求体上限为 10 MiB（10,485,760 字节），按完整请求体的字节数计算。超过上限时，NGINX 或后端返回 `413`。

JSON 字段名与字符串值必须包含有效的 Unicode。未配对的代理码点等非法内容返回 `400`。字段名区分大小写。

Observation 的时间边界和事实时区必须出现。未知时提交 `null`。Observer 和 ObservationSchema 的 `name` 必须出现，且不得为 `null`。

### 保存行为

后端组合路径中的 `id` 与请求体属性，并校验实体：

- 实体不存在时，后端创建实体并登记统一索引。
- 实体已存在且模型类别与保存路径一致时，后端替换内容。
- 实体已存在且模型类别与保存路径不一致时，后端返回 `409 Conflict`，并保留原内容。
- 重复提交相同请求时，保存结果不变，后端不新增实体。

单个实体的索引和内容在同一事务中保存。保存失败时，后端回滚事务；已有内容保持不变，首次保存不留下索引。

ObservationSchema 的提交方判断是否需要新 ID，规则见[定义更新](../core/model/observations/schema.mdx#定义更新)。后端校验格式和类别，不比较定义的语义。

### 成功响应

| 条件 | 状态码 | 响应体 |
| --- | --- | --- |
| 首次创建实体 | `201 Created` | 无 |
| 替换已有实体或重复提交 | `204 No Content` | 无 |

### 错误响应

| 条件 | 状态码 |
| --- | --- |
| 请求不符合契约，例如标识无效、JSON 无效或缺少必填字段 | `400 Bad Request` |
| 内容超出 PostgreSQL JSON 或文本表示范围 | `400 Bad Request` |
| 保存路径声明的模型类别与已有实体不一致 | `409 Conflict` |
| 请求体超过 10 MiB | `413 Content Too Large` |
| 后端因未预期错误而保存失败 | `500 Internal Server Error` |

错误响应使用[错误格式](#错误格式)。

## 按标识读取

### 输入

[读取实体](/api/getEntity)使用 `GET /entities/{id}`。`id` 必须是实体的 UUIDv7。后端通过统一索引定位内容所在的表。

### 成功响应

读取成功时，后端返回 `200 OK` 和 JSON 响应体。

| 字段 | 内容 |
| --- | --- |
| `category` | 实体的模型类别 |
| `entity` | 实体除 `id` 外的全部属性 |

`category` 使用以下取值：

| 取值 | 模型 |
| --- | --- |
| `entity` | 通用领域实体，包含具体数据和具体关系实体 |
| `observation` | Observation |
| `observer` | Observer |
| `observation_schema` | ObservationSchema |

`entity` 的属性结构与保存请求一致。实体标识由请求路径提供。Observation 的已知时间边界返回 UTC 时间。

### 错误响应

| 条件 | 状态码 |
| --- | --- |
| `id` 不是有效的 UUIDv7 | `400 Bad Request` |
| 实体不存在 | `404 Not Found` |
| 后端因未预期错误而读取失败 | `500 Internal Server Error` |

错误响应使用[错误格式](#错误格式)。

## 字段表示

OpenAPI 的 `components/schemas` 定义属性类型和必填项。

| OpenAPI Schema | 内容 |
| --- | --- |
| `Entity` | 通用领域实体的 JSON 属性 |
| `Observation` | 观测主体、具体数据和观测定义的标识，以及事实时间和事实时区 |
| `Observer` | 观测主体名称 |
| `ObservationSchema` | 名称和 JSON 观测定义 |
| `EntityResponse` | 模型类别及实体属性 |

未知时间或时区必须写为 `null`。

API 字段使用 `camelCase`，C# 属性使用 `PascalCase`，数据库列名使用 `snake_case`。例如，`observerId`、`ObserverId` 和 `observer_id` 表示同一属性。

通用领域数据的字段名由领域定义。`ObservationSchema.schema` 保存 JSON 观测定义。通用实体内容和观测定义遵循 [jsonb 存储语义](../storage/index.mdx#内容存储)。

实体标识和实体引用使用 UUIDv7 字符串，定义见 [EntityId](../core/model/contracts/entity.mdx#entityid)。

## Observation 引用约束

后端校验 `observerId`、`dataId` 和 `schemaId` 的 UUIDv7 格式。后端允许引用尚未入库的实体。被引用实体入库后，后端即可按引用标识读取，Observation 无须修改。

## 时间表示与职责

`startAt` 和 `endAt` 的边界含义见 [ITimed](../core/model/contracts/timed.mdx)。UTC 是协调世界时（Coordinated Universal Time）。

| 组件 | 职责 |
| --- | --- |
| 采集程序 | 提供事实时间，提交以 `Z` 结尾或带明确 UTC 偏移的字符串 |
| 后端 | 转换为 UTC，以微秒精度保存和读取，读取时返回以 `Z` 结尾的字符串 |
| 前端 | 按浏览器或系统时区显示时间 |

例如，提交 `2026-10-06T09:00:00+08:00`，读取时返回 `2026-10-06T01:00:00Z`。两者表示同一时刻。

Observation 的 `timeZone` 保存事实所属的 IANA 时区 ID，例如 `Asia/Shanghai`。后端使用时间字符串中的 UTC 偏移转换时刻。

非空 `timeZone` 必须能被运行环境解析为 IANA 时区 ID。两个时间边界都已知时，`startAt` 必须早于或等于 `endAt`。校验失败返回 `400`。

## 错误格式

错误响应使用 `Content-Type: application/problem+json`，结构遵循 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)。

| 必填字段 | 内容 |
| --- | --- |
| `type` | 固定为 `about:blank` |
| `title` | HTTP 状态的简短名称 |
| `status` | 实际 HTTP 响应的状态码 |
| `detail` | 本次错误的具体说明 |

调用方按状态码处理错误。`detail` 供人阅读。

## 后端路由

保存新实体时，后端按路径声明的模型类别选择存储表。保存已有实体时，后端通过统一索引定位存储，并校验模型类别。

领域实体转入专用表后，保存路径仍为 `PUT /entities/{id}`。存储位置和类别映射见 [Heartbeat Storage](../storage/index.mdx)。协议决策见 [ADR 0003](../adr/0003-entity-submission-entry-points.mdx)。

## 实现与契约来源

Api 独立定义保存请求类型，Core 实体保留完整身份。

| 提交模型 | C# 请求类型 |
| --- | --- |
| Observation | `SaveObservationRequest` |
| Observer | `SaveObserverRequest` |
| ObservationSchema | `SaveObservationSchemaRequest` |

请求类型位于 `Heartbeat.Api/Entities/`，每个类型一个文件。类型使用 `sealed class`，属性使用 `required` 和 `init`。HTTP JSON 配置启用 `RespectNullableAnnotations = true`：`required` 检查字段是否出现，可空声明决定是否接受 `null`。

`Serialization/EntityIdJsonConverter.cs` 转换 HTTP JSON 中的实体标识。`Serialization/UtcDateTimeOffsetJsonConverter.cs` 校验时间字符串中的 UTC 偏移并输出 UTC 时间。两个转换器统一注册到 HTTP JSON 处理。

后端构建从端点、请求类型和契约声明生成 `content/docs/api/openapi.json`。不得直接编辑生成文件，权威来源见 [ADR 0001](../adr/0001-documentation-source-of-truth.mdx)。

Fumadocs 根据生成文件提供 `/api/<operationId>` 接口页。接口页的复制和导出提供 OpenAPI JSON，编辑链接指向后端端点代码。
