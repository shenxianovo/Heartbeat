description: "补全、删除与历史保留"
---

本页规定实体写入后如何变化，以及哪些历史会被保留。Observation 保存后只能补全或删除。Core 不定义纠正和撤回。

| 操作 | 用途 | 原记录 |
| --- | --- | --- |
| 补全 | 随证据积累延续同一个事实 | 被更新 |
| 删除 | 移除指定的数据 | 移除 |

## 补全 [#completion]

### HISTORY-1 连续事实可以随证据积累补全同一份 Observation [#history-1]

业务判断事实是否连续。业务不需要为每次确认新增 Observation。补全沿用原 EntityId，见 [IDENTITY-4](./identity.mdx#identity-4)。

### HISTORY-2 补全只增加证据，不推翻已知的值 [#history-2]

补全可以把为 `null` 的值填写为已知的值，也可以把时段的 `endAt` 延后到最近一次确认的时刻。除此之外，补全不改变 Observation 的任何已知值，包括 `startAt`、引用和 `timeZone`。

### HISTORY-3 已保存的 Observation 不得改写成另一个事实 [#history-3]

不满足 [HISTORY-2](#history-2) 的修改不是补全，不得写入原 Observation。状态发生变化时，业务形成新的 Observation。

## 保留范围 [#retention]

### HISTORY-4 替换不保留旧值，后端不保留历史 [#history-4]

替换实体时，旧的属性值不保留。补全后只留下补全后的结果。目标实体被替换后，引用方读到的是目标实体的新内容。后端不还原补全前的记录，也不还原过去任意时刻的状态。

### HISTORY-5 需要历史时，业务把历史保存为独立的实体 [#history-5]

业务决定保留原始材料、当前状态还是历史版本，并在 EntitySchema 中声明所需的字段。业务不默认保存完整的输入。

- 原始材料可以保存在内容字段中，也可以保存为独立的实体，由观测内容引用。
- 需要旧 Observation 保持原貌时，为不同时刻保存独立的内容，不覆盖旧 Observation 引用的内容。例如，本机应用保持同一个身份，不同时段读到的应用名称由各自的前台应用时段内容保存。
- 需要补全的过程时，把每次补全前的记录保存为独立的实体。

## 删除 [#deletion]

### HISTORY-6 删除只移除选中的实体，不沿引用扩展 [#history-6]

目标实体删除后，引用方保留原引用，但无法再通过这个引用读取目标。业务需要成组删除时，明确指定删除的范围。

### HISTORY-7 用户可以删除已保留的任何历史数据 [#history-7]

删除范围遵循 [HISTORY-6](#history-6)。
