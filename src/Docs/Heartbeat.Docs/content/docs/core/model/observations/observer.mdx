## 含义

`Observer` 是观测主体实体，标识实际形成观测的主体。

主体依据证据，按实体定义形成观测，并对判断负责。主体边界由形成观测的责任决定。API、数据源、输出类型和进程划分不直接决定主体身份。

## 定义

`+` 表示接口契约之外的属性。

```csharp
public sealed class Observer : IEntity
{
    public required EntityId Id { get; init; }
    public required string Name { get; init; } // [!code ++]

    public IEnumerable<EntityId> GetReferences() => [];
}
```

| 属性 | 含义 |
| --- | --- |
| `Id` | 观测主体的实体标识 |
| `Name` | 观测主体的名称 |

## 约定

同一个 Observer 可以使用多个 EntitySchema 形成不同类型的观测。各类观测分别记录自己的观测内容和事实时间。

如果内部读取或检测模块只提供证据，所属主体负责形成观测。该模块不需要独立的 Observer 身份。

如果模块独立形成观测，则观测引用该模块对应的主体身份。

如果程序仅传输已有观测，程序必须保留原 `ObserverId`。

如果另一观测主体重新解释证据并形成新观测，新观测的 `ObserverId` 引用该主体。

读取、解析或匹配失败属于采集诊断。

一个程序可以运行多个 Observer 实例。各实例保留自己的身份。

## 示例：读取本地会话记录

本地会话采集程序读取 Claude 会话记录，并形成观测。`ObserverId` 引用该采集程序对应的 `Observer`。

如果观测表达历史对话，采集程序从对话记录读取事实时间。来源未提供时间时，采集程序保留未知时间。
