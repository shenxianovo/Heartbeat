## 含义

具体数据保存观测引用的内容。各领域定义具体数据类型。每种具体数据类型只实现 [IEntity](../contracts/entity.mdx)。

被观测事实的时间由 [Observation](./observation.mdx) 记录。

## 存储表示

如果后端尚未识别具体数据的类型，则将实体自身的属性序列化为 JSON 保存，读取时返回保存的 JSON 属性。存储规则见 [entity_data](../../../storage/entity-data.mdx)。

采集程序可以使用领域定义的强类型实体。后端无需具有对应的领域类，也能保存和读取这些属性。

## 记录粒度与更新

领域定义数据的身份与记录粒度。采集时，根据这些定义判断更新已有记录还是创建新记录。

同一事物的新状态、保留的历史内容和新观测分别处理。

如果来源缺少稳定标识或时间，则根据已有证据创建记录。缺失信息保持未知。

## 历史保留

如果保留历史快照，旧 `Observation` 引用的数据必须保留当时的内容。

如果需要保留历史内容，领域可以定义内容版本记录。

## 示例

微信步数按“一个人一天”定义记录粒度。如果同一天的步数从 3000 增至 5000，则更新同一条每日记录。

如果消息内容从 A 编辑为 B，消息保留原标识。如果需要保留历史内容，领域保存 A 和 B 的内容版本记录。

如果对话尚未结束，可以更新对话的汇总记录，并保留各条消息。
