## 含义

具体数据实体保存观测引用的内容。各领域定义具体数据类型。每种具体数据类型只实现 [IEntity](../contracts/entity.mdx)。

被观测事实的时间由 [Observation](./observation.mdx) 记录。

## 存储表示

后端尚未识别具体数据类型时，按 JSON 属性保存和返回内容。采集程序仍可使用领域定义的强类型实体。存储规则见 [entity_data](../../../storage/entity-data.mdx)。

## 记录粒度与更新

领域定义具体数据实体的身份和记录粒度。采集程序按领域规则更新已有实体或创建新实体。

观测身份规则见 [Observation 观测身份](./observation.mdx#观测身份)。

如果来源缺少稳定标识或时间，采集程序按已有证据创建具体数据实体。缺失的信息保持未知。

## 历史保留

如果领域保留历史快照，旧 `Observation` 引用的数据必须保留当时内容。

领域可以使用内容版本记录保留历史。

## 具体实现

[前台应用时段](../../../observers/schemas/foreground-application-interval.mdx)给出跨平台应用信息草案。当前已实现的单次读数字段和独立快照规则见[前台状态 Observer](../../../observers/foreground-state.mdx#当前单次读数)。各采集来源的数据与观测规则维护在 Observers 栏目。

## 示例

微信步数按“一个人一天”定义记录粒度。如果同一天的步数从 3000 增至 5000，采集程序更新同一条每日记录。

如果消息内容从 A 编辑为 B，消息保留原标识。如果领域需要保留历史内容，领域保存 A 和 B 的内容版本记录。

如果对话尚未结束，可以更新对话的汇总记录，并保留各条消息。
