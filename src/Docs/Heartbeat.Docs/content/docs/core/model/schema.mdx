<ModelRelations node="EntitySchema" />

`EntitySchema` 声明一种业务实体类型的字段、字段约束和业务含义。EntitySchema 本身也是实体。EntitySchema 的 `EntityId` 称为 SchemaId。

Observer、Observation 和 EntitySchema 是 Core 类型，结构由 Core 定义，不使用 EntitySchema。本页的规则只约束业务实体类型。

| 项目 | 内容 |
| --- | --- |
| 实现的契约 | [IEntity](./entity.mdx) |
| 引用 | 无 |
| 定义的类型 | 每种业务实体 |
| 决策 | [ADR · 实体模型](../../adr/entity-model.mdx)、[ADR · 实体存储](../../adr/entity-storage.mdx) |

## 字段 [#fields]

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `displayName` | 非空字符串 | 供人阅读的类型名称 |
| `description` | 非空字符串 | 业务说明，见 [SCHEMA-3](#schema-3) |
| `resourceName` | 字符串 | 类型的资源名，见 [SCHEMA-4](#schema-4) |
| `fields` | 字段名到字段定义的映射 | 实体的属性和引用，见[字段定义](#field-definitions) |

## 字段定义 [#field-definitions]

每个字段定义描述一个字段的类型和约束。

| 配置 | 适用的字段 | 含义 |
| --- | --- | --- |
| `type` | 所有字段 | 值的类型 |
| `required` | 所有字段，数组元素除外 | 字段是否必须出现 |
| `nullable` | 所有字段 | 字段出现时，值能否为 `null` |
| `fields` | `object` | 对象的成员，结构与顶层 `fields` 相同 |
| `items` | `array` | 数组元素的字段定义 |

`type` 有以下取值：

| `type` | 值 |
| --- | --- |
| `string` | 字符串 |
| `boolean` | 布尔值 |
| `integer` | 整数 |
| `number` | 数值，可以包含小数 |
| `reference` | 目标实体的 `EntityId` |
| `object` | JSON 对象 |
| `array` | JSON 数组 |

## 示例 [#example]

以下 EntitySchema 定义一种业务记录。`title` 必须出现，值可以为 `null`。`relatedEntityId` 引用另一个实体。`identifiers` 是对象数组。

```json
{
	"displayName": "示例记录",
	"description": "保存一条带标题、实体引用和平台标识线索的业务记录。",
	"resourceName": "example-records",
	"fields": {
		"title": {
			"type": "string",
			"required": true,
			"nullable": true
		},
		"relatedEntityId": {
			"type": "reference",
			"required": true,
			"nullable": false
		},
		"identifiers": {
			"type": "array",
			"required": true,
			"nullable": false,
			"items": {
				"type": "object",
				"nullable": false,
				"fields": {
					"scheme": {
						"type": "string",
						"required": true,
						"nullable": false
					},
					"value": {
						"type": "string",
						"required": true,
						"nullable": false
					}
				}
			}
		}
	}
}
```

## 类型与实例 [#types]

### SCHEMA-1 一份 EntitySchema 定义一种业务实体类型 [#schema-1]

同一类型的所有实例共用一份 EntitySchema，每个实例有自己的 `EntityId`。Core 类型不使用 EntitySchema：EntitySchema 无法由另一份 EntitySchema 定义，Observer 和 Observation 也与它一样由 Core 定义。

### SCHEMA-2 后端只按已声明的 EntitySchema 校验实体 [#schema-2]

后端不从已收到的数据推测字段或类型。业务实体的 EntitySchema 必须先于业务实体保存。

### SCHEMA-3 description 必须说明业务事实、记录粒度和事实时间的取值 [#schema-3]

`description` 是给人和 Agent 阅读的说明。后端保存 `description`，但不执行其中的内容。

## 资源名与字段名 [#names]

### SCHEMA-4 resourceName 全局唯一，登记后不得修改 [#schema-4]

一个 `resourceName` 只属于一个 SchemaId。按 [SCHEMA-14](#schema-14) 使用新的 SchemaId 时，也必须使用新的 `resourceName`，例如在末尾加版本号：`foreground-application-periods-2`。API 和存储用 `resourceName` 定位实体类型，见 [API · 资源登记](../../api/index.mdx#资源登记)和 [Storage · Business Tables](../../storage/business-tables.mdx#表命名)。

`schemas`、`observers` 和 `observations` 是保留的资源名，分别属于 Core 类型 EntitySchema、Observer 和 Observation。

### SCHEMA-5 resourceName 只使用小写字母、数字和连字符，并以字母开头 [#schema-5]

例如 `local-applications` 和 `foreground-application-periods`。

### SCHEMA-6 顶层字段不得命名为 id [#schema-6]

实体的标识由 IEntity 的 `Id` 提供，见 [ENTITY-1](./entity.mdx#entity-1)。

## 字段约束 [#constraints]

### SCHEMA-7 reference 字段的非空值必须是 UUIDv7 [#schema-7]

`reference` 字段声明实体引用。哪些值算实体引用，见 [ENTITY-3](./entity.mdx#entity-3)。

### SCHEMA-8 reference 只能用于顶层字段 [#schema-8]

对象成员和数组元素不得使用 `reference`。

### SCHEMA-9 每个字段定义必须写明 type、required 和 nullable [#schema-9]

这三项配置没有默认值。数组元素是例外，只写 `type` 和 `nullable`，见 [SCHEMA-13](#schema-13)。

### SCHEMA-10 required 和 nullable 分别判断 [#schema-10]

`required` 决定字段能否省略。`nullable` 决定字段出现时值能否为 `null`。

| `required` | `nullable` | 省略字段 | 值为 `null` | 类型匹配的非空值 |
| --- | --- | --- | --- | --- |
| `true` | `false` | 不允许 | 不允许 | 允许 |
| `true` | `true` | 不允许 | 允许 | 允许 |
| `false` | `false` | 允许 | 不允许 | 允许 |
| `false` | `true` | 允许 | 允许 | 允许 |

### SCHEMA-11 实体只接受已声明的字段 [#schema-11]

这条规则也适用于对象成员。字段定义同样只接受上表列出的配置。

### SCHEMA-12 后端保留“省略”和“值为 null”的区别 [#schema-12]

省略的字段读回时仍然不出现。值为 `null` 的字段读回时仍然是 `null`。

### SCHEMA-13 对象用 fields 声明成员，数组用 items 声明元素 [#schema-13]

只有 `object` 可以有 `fields`，只有 `array` 可以有 `items`。每个对象成员都必须写明 `type`、`required` 和 `nullable`。`items` 写明 `type` 和 `nullable`，不写 `required`。

数组的三层约束分别生效：

| 配置 | 约束的对象 |
| --- | --- |
| 数组字段的 `required` | 数组字段能否省略 |
| 数组字段的 `nullable` | 数组本身能否为 `null` |
| `items.nullable` | 数组元素能否为 `null` |
| `items.fields` 中成员的配置 | 每个对象元素的成员 |

## 定义的变化 [#changes]

### SCHEMA-14 结构、约束或业务含义改变时，必须使用新的 SchemaId [#schema-14]

同一个 SchemaId 的字段结构、约束和业务含义固定不变。新的 SchemaId 定义一种新的实体类型。EntitySchema 没有有效期。

### SCHEMA-15 只改 displayName 或 description 的措辞时，沿用原 SchemaId [#schema-15]

这条规则只适用于业务含义不变的情况。业务含义改变时，适用 [SCHEMA-14](#schema-14)。
