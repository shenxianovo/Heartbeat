Heartbeat 使用 TUnit 执行测试。

## 测试分工

| 类型 | 验证内容 | 数据库 |
| --- | --- | --- |
| 单元测试 | 独立规则与转换逻辑 | 不启动数据库 |
| 集成测试 | Observer、后端组件与 PostgreSQL 的协作 | 使用独立测试数据库 |
| 端到端测试 | 完整用户操作流程 | 需要数据库的用例使用独立测试数据库 |

## 测试框架与公共工具

TUnit 通过 Microsoft.Testing.Platform 运行，版本 `1.72.16` 由 `Directory.Packages.props` 管理。

`tests/Heartbeat.Testing` 为集成测试和端到端测试提供数据库工具。类库使用 `Heartbeat.Testing` 命名空间，每个类型一个文件。依赖包含 Infrastructure、EF Core、Npgsql 和 Testcontainers.PostgreSql，版本由 `Directory.Packages.props` 管理。

| 类型 | 职责 |
| --- | --- |
| `PostgresTestInstance` | 启动和销毁 PostgreSQL 容器，创建用例数据库 |
| `TestDatabase` | 提供连接字符串，释放时删除用例数据库 |

集成测试与端到端测试各自创建独立实例，见 [Database](./database.mdx)。

## 无数据库的模型检查

`tests/Heartbeat.Model.Tests` 检查 Schema 边界、JSON 字段歧义与实体引用枚举，不启动数据库：

```sh
dotnet test --project tests/Heartbeat.Model.Tests/Heartbeat.Model.Tests.csproj
```

## 集成测试

`tests/Heartbeat.Integration.Tests` 使用真实 PostgreSQL 与 Infrastructure 迁移。HTTP 用例通过 `WebApplicationFactory` 启动 API 宿主，每个用例通过 `ConnectionStrings:Heartbeat` 使用独立数据库。

| 用例范围 | 验证内容 |
| --- | --- |
| 实体持久化 | Observation 直接写入数据库时，亚微秒部分向下截断 |
| 三个观测模型 HTTP 保存与统一实体读取 | 创建、重复提交、替换、类别冲突、无效请求、写入失败回滚和同 ID 并发保存 |
| 业务实体 | 动态列类型、具名引用、嵌套结构、缺失与空值、精确数值、Unicode、替换失败回滚与跨 Schema 冲突 |
| Observation | 未入库的引用、UTC、微秒精度、未知边界与时区 |
| EntitySchema | 资源登记、字段校验、定义不可变、显示名称修改、重复与并发登记、建表失败回滚 |
| 请求体 | 真实 Kestrel 接收 10 MiB 请求，超限返回 JSON `413`，支持分块传输；重复字段名（包括嵌套和转义后相同的名称）返回 `400`，原内容不变 |

前台状态 Observer 的用例：

- 身份文件：Observer 身份复用，以及本机应用识别、重启复用、不同路径、未知应用、并发登记和损坏文件保留。
- 时段：连续延长、切换、名称与时区变化、读取失败、休眠、停顿与时钟跳变。
- 提交：通过真实 API 和 PostgreSQL 检查本机应用、引用、微秒时间、重复提交、本地采集链路和历史保留。
- [Outbox 恢复](./observers/outbox-recovery.mdx)：当前时段只留本地，结束时原子入队，断网或发送结果不明时保留记录，后续读回一致后删除。
- 读回：使用模拟响应，检查类别或内容不一致时报告失败。

自动测试不调用 macOS 原生接口；原生读取的手动验证步骤见 `src/Observers/Heartbeat.Observer.ForegroundState/README.md`。程序集级 `Before`/`After` 钩子管理共享容器；需要数据库的测试类继承 `DatabaseTest`，由它的用例级钩子创建和删除独立数据库。

## Case

每个 Case 一页：为什么验证、前置条件、操作与预期结果。Case ID 稳定，不随测试方法名变化；测试用 `[Property("caseId", "…")]` 引用。页面末尾展示最新报告中匹配该 ID 的执行结果，一个 Case 可以对应多个参数化结果。职责见 [ADR · 开发验证与测试证据](../adr/verification.mdx)。

## 报告

[Integration Report](./reports/integration.mdx) 读取 `TestResults` 中最新的 TUnit 集成测试 JSON，每次刷新重新读取。JSON 是结果的权威来源，查看报告不运行测试。报告由 `fumadocs-test-reports` 展示，提供搜索、筛选、详情、输出与时间线。
