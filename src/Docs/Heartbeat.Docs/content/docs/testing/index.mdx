Heartbeat 的测试分三类，都用 TUnit 执行。本页说明每类测试验证什么、用到哪些公共工具，以及 Case 页和测试报告怎样对应。

## 测试分工 [#kinds]

| 类型 | 验证什么 | 数据库 |
| --- | --- | --- |
| 单元测试 | 独立的规则和转换逻辑 | 不启动 |
| 集成测试 | Observer、后端组件和 PostgreSQL 的协作 | 每个用例一个独立的测试数据库 |
| 端到端测试 | 完整的用户操作流程 | 需要数据库的用例使用独立的测试数据库 |

## 框架与公共工具 [#tools]

TUnit 通过 Microsoft.Testing.Platform 运行，版本 `1.72.16` 由 `Directory.Packages.props` 管理。

`tests/Heartbeat.Testing` 为集成测试和端到端测试提供数据库工具。它使用 `Heartbeat.Testing` 命名空间，每个类型一个文件，依赖 Infrastructure、EF Core、Npgsql 和 Testcontainers.PostgreSql，版本同样由 `Directory.Packages.props` 管理。

| 类型 | 职责 |
| --- | --- |
| `PostgresTestInstance` | 启动和销毁 PostgreSQL 容器，创建用例数据库 |
| `TestDatabase` | 提供连接字符串，释放时删除用例数据库 |

集成测试和端到端测试各自创建自己的容器，细节见 [Database](./database.mdx)。

## 模型测试 [#model]

`tests/Heartbeat.Model.Tests` 检查 EntitySchema 的边界、JSON 字段的歧义和实体引用的枚举，不需要数据库：

```sh
dotnet test --project tests/Heartbeat.Model.Tests/Heartbeat.Model.Tests.csproj
```

## 集成测试 [#integration]

`tests/Heartbeat.Integration.Tests` 使用真实的 PostgreSQL 和 Infrastructure 的迁移。HTTP 用例通过 `WebApplicationFactory` 启动 API，每个用例通过 `ConnectionStrings:Heartbeat` 连接自己的数据库。

| 范围 | 验证什么 |
| --- | --- |
| 实体持久化 | Observation 直接写入数据库时，不足一微秒的部分向下截断 |
| 三种 Core 类型的 HTTP 保存与统一读取 | 创建、重复提交、替换、类别冲突、无效请求、写入失败回滚，以及同一 ID 的并发保存 |
| 业务实体 | 动态列类型、具名引用、嵌套结构、缺失与空值、精确数值、Unicode、替换失败回滚，以及跨 EntitySchema 的冲突 |
| Observation | 未保存的引用目标、UTC、微秒精度、未知边界与时区 |
| EntitySchema | 资源登记、字段校验、定义不可变、显示名称修改、重复与并发登记、建表失败回滚 |
| 请求体 | 真实的 Kestrel 接收 10 MiB 的请求，超限返回 JSON 格式的 `413`，支持分块传输；重复的字段名（包括嵌套和转义后相同的名称）返回 `400`，原内容不变 |

前台状态 Observer 的用例按 Case 组织：[本机应用身份](./observers/local-application-identity.mdx)、[时段边界](./observers/application-period-boundaries.mdx)、[时段保存](./observers/period-submission.mdx)、[Outbox 恢复](./observers/outbox-recovery.mdx)。此外还有两组测试：身份文件的复用和损坏保留；用模拟响应检查读回时类别或内容不一致会报告失败。

自动测试不调用 macOS 原生接口，原生读取的手动验证步骤见 `src/Observers/Heartbeat.Observer.ForegroundState/README.md`。

共享容器由程序集级的 `Before`/`After` 钩子管理。需要数据库的测试类继承 `DatabaseTest`，由它的用例级钩子创建和删除独立的数据库。

## Case [#cases]

每个 Case 一页，写为什么验证、前置条件、操作和预期结果。Case ID 稳定，与测试方法名无关；测试用 `[Property("caseId", "…")]` 引用它。页面末尾显示最新报告中匹配这个 ID 的执行结果，参数化的测试会有多条结果。这样设计的理由见 [ADR · 开发验证与测试证据](../adr/verification.mdx)。

## 报告 [#reports]

[Integration Report](./reports/integration.mdx) 读取 `TestResults` 中最新的 TUnit 集成测试 JSON，每次刷新页面都重新读取。JSON 是测试结果的权威来源；查看报告不会运行测试。报告由 `fumadocs-test-reports` 展示，可以搜索、筛选，查看详情、输出和时间线。
