## 为什么验证 [#why]

调用方按状态码和 `rule` 判断错误的原因，所以每个错误响应都要有相同的结构。约定见 [API · 错误格式](../../api/index.mdx#errors)。

## 前置条件 [#setup]

通过 `WebApplicationFactory` 启动 API，连接一个独立的测试数据库，见 [Database](../database.mdx)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 提交一个带有 `recordedAt` 的版本，得到 `400` | `Content-Type` 为 `application/problem+json`；`type` 为 `about:blank`；`title`、`status` 和 `detail` 都存在，`status` 为 `400` |
| 读取从未出现过的 EntityId，得到 `404` | 同上，`status` 为 `404` |
| 用已保存的 VersionId 提交不同的内容，得到 `409` | 同上，`status` 为 `409`，另有 `rule`、`index` 和 `versionId` |
