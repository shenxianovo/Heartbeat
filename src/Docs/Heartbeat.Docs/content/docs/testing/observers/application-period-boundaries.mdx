export const caseId = 'foreground-application-period-boundaries';

## 为什么验证

[应用时段](../../observers/schemas/foreground-application-interval.mdx)用于统计前台时长。休眠、读取失败和采集停顿不能被计入应用持续使用时间。

## 前置条件

使用可控制时间和应用读数的采集时间线。采样间隔为 1 秒，最大连续间隔为 3 秒。

## 操作与预期结果

| 输入 | 预期结果 |
| --- | --- |
| 0 秒、1 秒连续确认应用 A | 同一条观测从 0 秒延长到 1 秒 |
| 2 秒确认应用 B | A 结束于 2 秒，B 从 2 秒开始 |
| 应用不变，名称变化或时区变化 | 新开时段，旧内容保持不变 |
| 1 秒后读取失败，2 秒恢复 | 原时段结束于 1 秒，恢复时新开一段 |
| 1 秒后直到 10 秒才恢复采样 | 不记录中间空白 |
| 包含休眠和不含休眠的计时出现超过 100 毫秒的差异 | 断开时段 |
| 两次定时确认之间收到 A → B → C 的事件 | 三个时段均保留 |
| 休眠通知、休眠中定时确认、唤醒通知 | 休眠时结束原时段，休眠中不采集，唤醒后新开时段 |
| 系统时间倒退或增量跳变超过 100 毫秒 | 断开时段，不延长原观测 |

## 测试实现

`ForegroundTimelineTests` 和 `ForegroundOutboxTests` 使用模拟读数与事件验证以上规则。模拟休眠只验证分段规则，不证明真实设备休眠事件的读取。
