## 为什么验证

[应用时段](../../observers/application-activity/foreground-application-period.mdx)记录已确认的前台事实，不判断用户活跃或根据其他维度裁剪时段。读取失败与采集停顿造成的未确认空白不能被计入连续前台时段。

## 前置条件

使用可控制时间和应用读数的采集时间线。采样间隔为 1 秒，最大连续间隔为 3 秒。

## 操作与预期结果

| 输入 | 预期结果 |
| --- | --- |
| 0 秒、1 秒连续确认应用 A | 同一条观测从 0 秒延长到 1 秒 |
| 2 秒确认应用 B | A 结束于 2 秒，B 从 2 秒开始 |
| 应用不变，名称变化或时区变化 | 新开时段，旧内容保持不变 |
| 1 秒后读取失败，2 秒恢复 | 原时段结束于 1 秒，恢复时新开一段 |
| 1 秒后直到 10 秒才恢复采样 | 不记录中间空白 |
| 应用与确认间隔不变，另一维度记录锁屏、休眠或无输入 | 不因其他维度的状态而切开前台时段 |
| 两次定时确认之间收到 A → B → C 的事件 | 三个时段均保留 |
| 采集未取得读数，直到超过连续确认阈值才恢复 | 原时段结束于最后一次确认，恢复后新建；不要求判断中断是否由休眠造成 |
| 系统时间倒退或增量跳变超过 100 毫秒 | 断开时段，不延长原观测 |
