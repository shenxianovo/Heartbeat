export const caseId = 'foreground-outbox-recovery';

## 为什么验证

网络中断或进程退出不应丢失已保存的时段。正在进行的时段会继续变化，不能凭服务器已有同一个 ID 就删除本地更新。

## 前置条件

使用独立 SQLite 文件。HTTP 测试服务可模拟断网，以及保存成功但响应丢失。

## 操作与预期结果

| 操作 | 预期结果 |
| --- | --- |
| 保存并延长当前时段 | Outbox 为空，当前时段只在本地更新 |
| 重新打开状态文件，结束遗留时段 | 以最后确认时间入队，ID 和完整提交内容保持不变 |
| 再次执行恢复 | 不重复入队 |
| 另一 Observer 打开同一状态文件 | 报错，原数据保留 |
| 切换时，在写入新时段前模拟本地失败 | 已结束时段的入队也回滚，原当前时段仍可恢复 |
| 后端不可达 | Outbox 保留记录与错误原因，本地仍可保存新读数 |
| 后端已保存实体，但发送响应丢失 | 后续查询发现内容一致，该实体不再重复提交 |
| 六个实体全部读回一致 | 删除该时段的 Outbox 记录 |

## 测试实现

`ForegroundOutboxTests` 验证本地恢复、事务回滚和不确定的发送结果。`MacObserverReadBackTests` 验证相同 ID 的内容或类别不一致时保留记录。
