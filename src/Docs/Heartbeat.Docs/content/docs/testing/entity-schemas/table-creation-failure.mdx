export const caseId = 'entity-schema-registration-table-conflict';

## 为什么验证 [#why]

登记一个 EntitySchema 要做四件事：保存 EntitySchema、写入统一索引、绑定业务资源、创建业务表，见 [Storage](../../storage/index.mdx)。建表失败时，四件事必须一起回滚，否则会留下一个无法使用的业务资源。

## 前置条件 [#setup]

使用独立的测试数据库。数据库中已经有一张物理表 `entity_test_records`，业务资源 `test-records` 还没有登记。

## 操作 [#steps]

1. 用一个新的实体标识提交 EntitySchema：资源名为 `test-records`，字段 `title` 是可以省略、可以为空的字符串。
2. 用同一个标识读取这个 EntitySchema。
3. 向业务资源 `test-records` 提交一条数据。

第一步向 `PUT /api/entities/schemas/{新实体标识}` 提交：

```json
{
  "references": {},
  "properties": {
    "displayName": "Test",
    "description": "验证业务表重名时，定义、索引与资源登记整体回滚。",
    "resourceName": "test-records",
    "fields": {
      "title": { "type": "string", "required": false, "nullable": true }
    }
  }
}
```

第二步请求 `GET /api/entities/{同一实体标识}`。第三步向 `PUT /api/entities/test-records/{另一个新实体标识}` 提交：

```json
{ "references": {}, "properties": {} }
```

## 预期结果 [#expected]

- 登记返回 `409 Conflict`：同名的物理表让建表失败。
- 读取返回 `404 Not Found`：失败的登记没有留下统一索引。
- 提交数据返回 `404 Not Found`：业务资源没有登记。
