## 版本与启动

- PostgreSQL 镜像 `postgres:18.6-alpine`，服务与测试使用同一版本。
- 数据库运行在容器中，API 运行在本机。数据库健康后，Aspire 运行 EF Core 迁移，迁移成功后启动 API，见 [ADR · 后端运行与本地环境](../adr/backend-runtime.mdx#local-environment)。
- 测试数据库见 [Database](../testing/database.mdx)。

## 数据访问

| 项目 | 配置 |
| --- | --- |
| .NET SDK | `global.json` 固定 `10.0.401`，允许同功能版本的维护更新 |
| 运行时、EF Core | `10.0.12`，见后端 Dockerfile 与 `Directory.Packages.props` |
| 固定表与迁移 | EF Core；Initial migration 与模型快照位于 Infrastructure 的 `Database/Migrations/` |
| 业务表 | Npgsql 参数化 SQL；表名与列名按标识符规则引用 |
| 连接字符串 | `ConnectionStrings:Heartbeat`（环境变量 `ConnectionStrings__Heartbeat`）；缺失时 API 启动失败 |

- 重写期间直接修改 Initial migration 与模型快照。EF 工具以 Api 为启动项目，Api 引用 `Microsoft.EntityFrameworkCore.Design`（`PrivateAssets="all"`）。
- `AddHeartbeatInfrastructure(connectionString)` 注册 Npgsql 与 `HeartbeatDbContext`。上下文为 `Scoped`；`NpgsqlDataSource` 为单例，由服务容器创建和释放，请求共用连接池。

## 时间

已知时间边界先转换为 UTC，再向下截断到整微秒，以 `timestamptz` 保存；未知边界保存为 `NULL`。IANA 时区由 `observations.time_zone` 单独保存。

- EF 实体读写使用 `Database/Converters/UtcDateTimeOffsetValueConverter.cs`，应用于所有 `DateTimeOffset` 与可空属性。
- 参数化 SQL 写入 Observation 前复用同一投影。
- 投影不依赖数据库的时间纪元：`1999-12-31T23:59:59.9999999Z` 保存为 `1999-12-31T23:59:59.999999Z`。见 [ADR · 实体存储](../adr/entity-storage.mdx#rationale)。
- `2026-10-06T09:00:00+08:00` 保存为 `2026-10-06T01:00:00Z`。

## 统计与诊断

| 项目 | 配置 | 用途 |
| --- | --- | --- |
| `pg_stat_statements` | 启用，`track=top` | 按查询结构汇总调用次数、耗时与块读写 |
| `track_io_timing` | `on` | 数据文件 I/O 等待耗时 |
| `track_wal_io_timing` | `on` | WAL I/O 等待耗时 |
| `track_activities`、`track_counts` | 默认 `on` | 会话活动与累计统计 |
| `log_min_duration_statement` | `500ms` | 慢 SQL 日志 |
| `log_lock_waits` | `on` | 超过 `deadlock_timeout`（默认 `1s`）的锁等待 |
| `pg_stat_statements.track_planning` | 默认 `off` | 规划统计 |
| `auto_explain` | 关闭 | 需要执行计划时启用 |

`pg_stat_statements` 需要预加载：AppHost 已配置 `shared_preload_libraries`，初始化 SQL 创建扩展。在其他数据库启用：

1. 将 `pg_stat_statements` 加入 `shared_preload_libraries`。
2. 重启 PostgreSQL（现有连接会中断）。
3. 执行 `CREATE EXTENSION pg_stat_statements;`。
4. 确认 `pg_extension` 中存在 `extname = 'pg_stat_statements'`。

常用视图：

| 视图 | 用途 |
| --- | --- |
| `pg_stat_activity` | 当前 SQL、会话状态与等待事件 |
| `pg_stat_io` | 实例 I/O |
| `pg_stat_user_tables` | 表扫描、行更新、死元组与 vacuum |
| `pg_stat_user_indexes` | 索引使用 |
| `pg_stat_database` | 事务、缓存命中与临时文件 |

I/O 计时会增加读取时钟的开销；判断 CPU 瓶颈还需结合锁等待与执行计划。`auto_explain` 开启 `log_analyze` 后会影响所有语句。参考：[pg_stat_statements](https://www.postgresql.org/docs/current/pgstatstatements.html)、[统计配置](https://www.postgresql.org/docs/current/runtime-config-statistics.html)、[日志配置](https://www.postgresql.org/docs/current/runtime-config-logging.html)、[锁配置](https://www.postgresql.org/docs/current/runtime-config-locks.html)、[auto_explain](https://www.postgresql.org/docs/current/auto-explain.html)。
