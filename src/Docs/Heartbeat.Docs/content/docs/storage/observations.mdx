---
title: "observations"
description: "观测实体的专用存储"
---

`observations` 保存 [Observation](../core/model/observations/observation.mdx) 的内容。后端将本表映射为模型类别 `observation`。

## 保存内容

| 列名 | 数据库类型 | 允许 SQL `NULL` | C# 属性 | 保存的信息 |
| --- | --- | --- | --- | --- |
| `id` | `uuid` | 否 | `Id` | 观测的实体标识 |
| `observer_id` | `uuid` | 否 | `ObserverId` | 形成观测的观测主体标识 |
| `data_id` | `uuid` | 否 | `DataId` | 具体数据的实体标识 |
| `schema_id` | `uuid` | 否 | `SchemaId` | 解释观测的观测定义标识 |
| `start_at` | `timestamptz` | 是 | `StartAt` | 被观测事实的开始时间 |
| `end_at` | `timestamptz` | 是 | `EndAt` | 被观测事实的结束时间 |
| `time_zone` | `text` | 是 | `TimeZone` | 事实所属的 IANA 时区 ID；未知时为 `null` |

后端将已知时间边界转换为 UTC，以微秒精度保存。未知边界保存为 SQL `NULL`。`time_zone` 保留事实所属时区的信息。

引用的实体可以晚于观测到达。引用约束见 [Heartbeat API](../api/index.mdx#observation-引用约束)。

## 约束

`id` 为主键，并通过外键引用 `entities.id`。实体内容必须有对应的统一索引。

主键约束名为 `pk_observations`，外键约束名为 `fk_observations_entities_id`。

外键使用 `ON DELETE CASCADE`。统一索引行被删除时，本表中同 ID 的内容行自动删除。

`observer_id`、`data_id`、`schema_id` 是实体标识引用，不建立数据库外键。被引用实体可以稍后入库。

时间边界使用 `ck_observations_time_order` 检查约束：

```sql
CHECK (start_at <= end_at)
```

两个边界均已知时，开始时间必须早于或等于结束时间。任一边界未知时允许保存。

## 读写

保存路径为 `PUT /entities/observations/{id}`。读取路径为 `GET /entities/{id}`。

统一索引中的 `table_name` 为 `observations`。后端在同一事务中写入索引和本表内容，遵循[写入一致性](./index.mdx#写入一致性)。
