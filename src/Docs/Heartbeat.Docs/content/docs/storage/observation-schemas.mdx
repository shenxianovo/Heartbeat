---
title: "observation_schemas"
description: "观测定义的专用存储"
---

`observation_schemas` 保存 [ObservationSchema](../core/model/observations/schema.mdx) 的内容。后端将本表映射为模型类别 `observation_schema`。

## 保存内容

| 列名 | 数据库类型 | 允许 SQL `NULL` | C# 属性 | 保存的信息 |
| --- | --- | --- | --- | --- |
| `id` | `uuid` | 否 | `Id` | 观测定义的实体标识 |
| `name` | `text` | 否 | `Name` | 观测定义的名称 |
| `schema` | `jsonb` | 否 | `Schema` | 具体数据的结构、约束和观测含义，以 JSON 保存 |
| `start_at` | `timestamptz` | 是 | `StartAt` | 观测定义有效期的开始时间 |
| `end_at` | `timestamptz` | 是 | `EndAt` | 观测定义有效期的结束时间 |

`schema` 遵循 [jsonb 存储语义](./index.mdx#内容存储)。

后端将已知时间边界转换为 UTC，以微秒精度保存。未知边界保存为 SQL `NULL`。

如果语义或约束变化，创建方必须使用新的实体标识。如果仅修改名称或说明，且语义与约束不变，可以保留原标识。规则见[定义更新](../core/model/observations/schema.mdx#定义更新)。

## 约束

`id` 为主键，并通过外键引用 `entities.id`。实体内容必须有对应的统一索引。

主键约束名为 `pk_observation_schemas`，外键约束名为 `fk_observation_schemas_entities_id`。

外键使用 `ON DELETE CASCADE`。统一索引行被删除时，本表中同 ID 的内容行自动删除。

时间边界使用 `ck_observation_schemas_time_order` 检查约束：

```sql
CHECK (start_at <= end_at)
```

两个边界均已知时，开始时间必须早于或等于结束时间。任一边界未知时允许保存。

## 读写

保存路径为 `PUT /entities/observation-schemas/{id}`。读取路径为 `GET /entities/{id}`。

统一索引中的 `table_name` 为 `observation_schemas`。后端在同一事务中写入索引和本表内容，遵循[写入一致性](./index.mdx#写入一致性)。
