---
title: "0001 文档与 API 契约的权威来源"
---

长期文档的唯一权威位置是 `src/Docs/Heartbeat.Docs/content/docs/`。模型、术语和设计决策直接在站内源文件中维护。人和 Agent 使用同一份正文。模型正文只记录用户已确认的结构与语义。

API 请求与响应结构以 `Heartbeat.Api` 的端点、请求类型和契约声明为准。后端构建生成 `content/docs/api/openapi.json`，Fumadocs 从该文件生成接口页。修改接口结构时更新后端代码，生成文件不直接编辑。

`openapi.json` 随后端代码提交，用于审查契约变化。文档站启动和构建直接读取该文件，生成流程由后端构建负责。文档站可以独立运行，展示最近一次后端构建生成的契约。

文档站保留 Heartbeat Core、Heartbeat API、Heartbeat Storage、Heartbeat Testing 和 Heartbeat ADR 五个分区。Core 记录模型定义，API 记录读写协议，Storage 记录存储与数据库约定，Testing 记录测试约定与公共工具，ADR 记录设计决策。

文档站按根路径运行。NGINX 通过独立端口提供文档入口并转发实体 API 请求，见 [ADR 0007](./0007-unified-http-entry.mdx)。

文档站的路径和操作说明见模块 README。Agent 的维护规则见仓库根目录的 `AGENTS.md`。
