---
title: "0004 按模型保存，按标识统一读取"
---

保存接口通过路径区分通用领域实体、Observation、Observer 和 ObservationSchema。请求体直接提交实体除 `id` 外的属性。读取接口 `GET /entities/{id}` 返回 `category` 和 `entity`。这样调用方可以按模型提交，也可以仅凭标识读取任意实体。

API 字段使用 `camelCase`，C# 属性使用 `PascalCase`，数据库表名和列名使用 `snake_case`。通用领域数据的字段名遵循领域定义。通用实体内容和观测定义使用 `jsonb` 保存和返回，空白和对象键顺序不保留，重复键只保留最后一个值。

采集程序可以直接提交以 `Z` 结尾或带明确 UTC 偏移的时间。后端统一转换为 UTC，以微秒精度保存和读取时间，读取时返回以 `Z` 结尾的时间。前端按浏览器或系统时区显示。Observation 的 `timeZone` 独立保存事实所属时区的信息。未知时间或时区必须写为 `null`。

后端允许 Observation 引用尚未入库的实体，并检查三个引用的 UUIDv7 格式。各实体可以独立提交，交付顺序不影响观测的保存。

实体首次保存后，模型类别固定。如果保存路径声明的模型类别与已有实体不一致，后端必须拒绝请求并返回 `409 Conflict`。后端保留已保存的内容，保证已有标识的模型类别稳定。

ObservationSchema 的提交方负责判断定义的语义或约束是否变化，并据此决定是否使用新的实体标识。后端检查请求格式、时间顺序和模型类别，不自动判断任意 JSON 定义的语义变化。同 ID 且类别一致的合法请求替换已有内容；JSON 内容变化本身不触发 `409`。

保存接口共用创建、替换和重试语义。通过校验后，首次保存创建实体，后续保存替换内容。相同请求重复提交后保存结果不变。接口路径、字段结构、状态码和错误格式见 [Heartbeat API](../api/index.mdx)。
