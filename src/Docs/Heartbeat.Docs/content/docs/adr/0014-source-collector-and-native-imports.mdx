## 背景与范围

100 个模型场景证明了字段表达与保存/读回边界，没有自动产生对应来源适配器。本轮在 Observers 实现真实本机读取和有界原生格式导入，沿用既有 Core、EntitySchema 与 API。入口、协议和领域限制见[来源采集](../observers/sources/index.mdx)及[100 场景接入目录](../observers/sources/coverage.mdx)。

## 决定

1. **主体按责任实例识别。** 一个持久采集状态文件拥有一个稳定 ObserverId。来源解析器、进程启动或输出 Schema 不单独决定主体身份；重启复用同一状态文件。多个来源适配器可以服务同一采集实例。
2. **来源解析留在 Observers。** `IRecordSource` 读取显式来源，输出原生身份、证据、固定 Schema、属性、具名引用及事实边界。解析器不能调用 Core 把所有原始材料包装为通用核心内容。
3. **本实例使用来源身份节点与历史快照。** SQLite 持久保存 scope/kind/native-key 到 UUIDv7 的映射；业务内容引用该身份。身份节点仅说明标识已知。此运行时复用相同内容并为来源证据维护 Observation，历史内容不可被下一次编辑覆盖；这不是所有业务实体必须采用的核心保留模式。
4. **本地恢复与远端数据分别负责。** SQLite 是此采集实例身份映射、证据重放和待发送队列的权威位置；后端仍按既有 EntitySchema 存储约定保存实体。解析批次在本地事务中登记，不在 HTTP 层增加多实体事务。
5. **远端确认必须读回。** 发送器用既有 API 按稳定 ID 检查/提交，再用 GET 核对类别、Schema 身份、属性与引用。PUT 成功不能直接删除 Outbox。合法的 Schema 显示名称更改不视为结构冲突；其他内容冲突保留本地证据，不覆盖既有数据。
6. **事实未知就保留未知。** 来源 event time、内部时钟、本地日期与捕获时间分别按具体定义使用。导入时间不替代来源历史事件时间；更高精度原生时间按来源字段保留。共同 API 时间投影使用微秒。
7. **覆盖目录区分层次。** 实际本机读取、离线原生导入、部分替代格式、仅相关解析器与模型测试分别标记。13 个 CLI 选项不是 13 个 Observer，也不是 100 个完整连接器。

## 不在本决定中

不增加核心 Relation、通用 Revision 或 Schema 有效期，不改变现有实体接口。不建立 OAuth 管理、自动分页、外部 cursor 恢复、持续监控、分布式 exactly-once、通用保留策略或生产性能承诺。导入某份文件不会自动证明远端来源真实性与材料完整性。

公共 API 仍缺少列表、逆向引用和图遍历；底层 Schema 表可以另行设计 SQL 查询与索引。接入更多来源不等于已经决定或实现通用查询接口。

## 验证

来源单元测试检查真实读取或原生 fixture；运行时测试检查重启、身份、冲突、队列与失败恢复；`SourcePipelineTests` 用实际 HTTP/PostgreSQL 比对每个已提交实体。具体运行范围与未验证项见[本轮来源验证](../observers/sources/verification.mdx)。核心模型压力证据仍独立保留在 Testing。
