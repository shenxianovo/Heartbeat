---
title: "0004 统一索引定位实体的权威存储"
---

实体索引和内容保存在 PostgreSQL。每个实体只能有一份权威内容。统一索引保存实体标识和内容所在的表名；后端先查询索引，再读取内容。

后端未识别的领域类型使用通用 JSON 存储。结构稳定且有明确查询需求的类型可以使用专用表。实体转入专用表时，后端必须保留原标识并更新索引，已有引用继续有效。

保存单个实体时，后端在同一事务中登记索引、检查模型类别并写入内容。索引和内容必须同时成功或同时回滚，避免留下无内容的索引或错误的存储位置。同一 ID 的并发写入通过索引行锁依次执行。

内容表通过外键引用统一索引，删除索引行时级联删除同 ID 的内容。Observation 的三个实体引用不建立外键，允许先保存观测、再保存被引用实体。

后端使用 .NET 10、EF Core 和 Npgsql。EF Core 管理映射和迁移，Npgsql 访问 PostgreSQL。重写期间直接修改 Initial migration 和模型快照。

表结构、数据库类型、版本和约束见 [Heartbeat Storage](../storage/index.mdx)。
