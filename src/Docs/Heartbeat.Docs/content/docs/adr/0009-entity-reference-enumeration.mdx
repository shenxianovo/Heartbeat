## 引用枚举

`IEntity` 定义统一的实体引用枚举契约。调用方取得任意 `IEntity` 后，按该契约枚举实体引用。没有引用的实体返回空集合。

引用枚举只列出实体已有引用，不读取目标实体。业务定义引用名称和含义。通用遍历使用目标标识。

实体是关系图中的节点，实体引用连接节点。普通实体引用参与统一遍历。

## 业务关系

业务定义关系的含义、方向、字段和约束。普通引用可以保留在具体实体的字段中。

如果关系需要独立保存身份、时间或其他信息，业务定义普通实体。关系实体通过同一契约提供引用。需要时间边界的业务实体实现 `ITimed`。

Core 不提供通用关系基类。统一遍历依赖引用枚举契约，不依赖独立的关系实体。业务关系也不统一要求两个端点或时间边界。

## HTTP 引用表示

所有保存入口使用相同的外层格式：`references` 与 `properties` 并列。`references` 是 JSON 对象，键是业务定义的引用名称，非空值是目标实体的 UUIDv7。字段定义允许空值时，值可以为 `null`。`properties` 保存其他业务属性。引用字段不得在 `properties` 中重复。没有引用字段时，`references` 使用 `{}`。

Observation 将 `observerId`、`contentId` 和 `schemaId` 放在 `references` 中，将时间边界和事实时区放在 `properties` 中。Observer 与 EntitySchema 没有实体引用，使用 `references: {}`。

EntitySchema 将实体引用限制在顶层字段。对象成员和数组元素不允许使用 `reference`，这一规则适用于任意嵌套层级。

业务在实体字段中定义引用。提交层根据业务声明，将引用字段放入 `references`，将其他业务字段放入 `properties`。读取层按引用名称还原业务对象。业务不另行维护一份引用集合，也不扫描 JSON 标识字符串推断引用。

所有类别使用同一读取响应结构：`category`、`references` 与 `properties`。通用读取方遍历 `references` 的非空值即可取得目标标识，无须了解每一种业务实体的字段。

字段和示例见[读取实体](/api/getEntity)。

模型规则见[实体引用约定](../core/model/contracts/entity.mdx#约定)。
