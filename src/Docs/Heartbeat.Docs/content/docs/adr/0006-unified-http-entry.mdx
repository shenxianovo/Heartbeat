---
title: "0006 HTTP 入口与应用分流"
---

业务前端与文档站分别运行。NGINX 提供业务/API 入口和文档入口，文档入口同时转发实体 API 请求，使 Playground 与 API 同源。

| 本地端口与路径 | 接收组件 | 转发规则 |
| --- | --- | --- |
| `8080/api/…` | API | 去掉 `/api` 前缀 |
| `3000/api/entities/…` | API | 去掉 `/api` 前缀 |
| `3000` 的其他路径 | 文档站 | 保留完整路径 |

文档站按根路径运行，不配置 Next.js `basePath`。API 在 OpenAPI 中声明相对服务地址 `/api`。Playground 将服务地址与接口路径组合。文档入口仅代理实体请求，接口文档和搜索仍由文档站处理。

8080 的其他路径目前返回 `404`。业务前端实现后，由业务前端接收根路径。

两个 HTTP 入口仅绑定本机地址，API 与文档站仅在容器网络内监听。NGINX 和 API 都检查 10 MiB 的请求体上限，超限时返回 `413` 和 `application/problem+json`。这样直连 API 与经过代理的请求使用同一上限和错误格式。

代理配置见 `docker/nginx/default.conf`，版本、超时和运行说明见后端模块 README。
