---
title: "0005 核心模型与后端项目分工"
---

核心模型和后端按职责划分为以下项目：

| 项目 | 位置 | 职责 |
| --- | --- | --- |
| `Heartbeat.Core` | `src/Core/Heartbeat.Core/` | 实体、基础能力接口和模型自身的规则 |
| `Heartbeat.Application` | `src/Backend/Heartbeat.Application/` | 保存、读取等应用操作与规则 |
| `Heartbeat.Infrastructure` | `src/Backend/Heartbeat.Infrastructure/` | 数据库等具体实现，包括 EF Core、事务、表映射和迁移 |
| `Heartbeat.Api` | `src/Backend/Heartbeat.Api/` | HTTP 请求、响应与启动组装 |

原 `Heartbeat.Contracts` 改名为 `Heartbeat.Core`，目录、项目名、命名空间和引用统一更新。

## 依赖方向

- `Core` 不依赖另外三个项目，也不依赖 ASP.NET Core 或 EF Core。
- `Application` 依赖 `Core`。
- `Infrastructure` 依赖 `Application` 和 `Core`。
- `Api` 依赖 `Application`，启动组装时引用 `Infrastructure` 注册具体实现。

项目引用约束依赖方向。应用规则独立于 HTTP 和数据库实现。项目内部按业务能力组织代码，数据库映射与迁移集中管理。

后端各项目共同组成一个运行进程，打包为一个后端容器。各层承担实际职责，避免增加仅转发调用的层。

## 数据库映射

Infrastructure 直接将 Core 的 `Observation`、`Observer`、`ObservationSchema` 映射到对应专用表。统一索引 `entities` 和通用 JSON 存储 `entity_data` 使用 Infrastructure 中独立定义的存储类型。

表名、列名、数据库类型和约束统一在 Infrastructure 中配置，Core 保持独立。

Api 从配置键 `ConnectionStrings:Heartbeat` 读取数据库连接字符串。配置缺失或为空时，启动失败。Infrastructure 的 `DependencyInjection.cs` 提供 `AddHeartbeatInfrastructure(connectionString)`，通过 `AddDbContext` 注册 `HeartbeatDbContext`，使用 Npgsql，生命周期为 `Scoped`。

Api 负责提供配置，Infrastructure 负责数据库注册。

## 测试数据库

测试负责数据库实例的创建与销毁。数据库辅助代码集中在 `tests/Heartbeat.Testing` 类库，负责容器生命周期、用例数据库的创建与迁移、连接字符串和数据库清理。集成测试和端到端测试各自创建独立实例。

测试框架使用 TUnit，通过仓库已配置的 Microsoft.Testing.Platform 运行，负责调用公共工具的生命周期方法。调用方负责先释放被测后端与连接，再由公共工具删除用例数据库。

测试通过 `ConnectionStrings:Heartbeat` 向被测后端提供连接字符串，后端沿用正常数据库注册方式。测试建表与正常服务共用 Infrastructure 中的 EF Core 迁移。

测试分工、实例隔离与工具接口见 [Heartbeat Testing](../testing/index.mdx)。

## HTTP 入口

`Heartbeat.Api` 使用 ASP.NET Core Minimal APIs。当前 HTTP 层负责接收实体、调用应用操作和返回结果，使用直接的路由定义组织入口。

`Program.cs` 负责启动、依赖注册和路由组装。路由处理代码放在对应业务目录中，使用 `MapGroup` 表达 `/entities` 及其下级路由。应用操作与规则由 `Application` 承担。

API 请求类型与 Core 实体分开定义，放在 `Api` 的对应业务目录中。保存实体的请求类型只包含请求体属性，实体自身的 `Id` 由路径提供。后端组合路径中的标识与请求体属性，得到完整实体。

`EntityId` 的 HTTP JSON 转换由 `Api` 的 `Serialization/EntityIdJsonConverter.cs` 负责，统一注册到 HTTP JSON 处理。读取时接受 UUIDv7 字符串，输出时写成 UUID 字符串。

时间的 HTTP JSON 转换由 `Api` 的 `Serialization/UtcDateTimeOffsetJsonConverter.cs` 负责，统一注册到 HTTP JSON 处理。输入接受带 `Z` 或明确 UTC 偏移的时间，输出转换为 UTC 并以 `Z` 结尾。可空时间的 `null` 保持不变。
