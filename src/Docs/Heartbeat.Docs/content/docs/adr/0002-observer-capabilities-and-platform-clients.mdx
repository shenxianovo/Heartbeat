## 主体与客户端

Observer 按形成观测的责任划分。EntitySchema 定义事实含义。Observer 依据证据形成观测，并对判断负责。API、数据源、输出类型和进程划分不直接决定主体身份。

一个 Observer 可以使用多份 EntitySchema。各类观测分别保存观测内容和事实时间。跨平台实现的数据结构、约束、事实含义和时间规则一致时，可以共用同一份定义。

前台应用时段使用平台无关的实体定义。平台名称和系统读取方式写在实现说明中；遵循相同字段、约束和时间含义的平台共用 SchemaId。

内部模块只提供证据时，由所属 Observer 形成观测。模块独立形成观测时，观测引用该模块对应的主体身份。

平台客户端组合并运行 Observer。多个 Observer 可以运行在同一进程中。客户端只组合或传输已有观测时，必须保留原 `ObserverId`。如果主体形成新的聚合观测，聚合观测使用该主体的身份。聚合数据保存被聚合的实例引用。EntitySchema 定义引用字段。

## 桌面观测职责

桌面观测由三个 Observer 分别负责，可以运行在同一程序中：

| Observer | 负责的事实 |
| --- | --- |
| 前台状态 | 前台应用时段和窗口标题时段，分别使用自己的定义与时间线 |
| 输入事件 | 键盘和鼠标事件发生的时间点 |
| 设备状态 | 设备休眠和唤醒状态的时间段 |

“应用使用”表示前台时长。设备清醒、会话未锁定和近期存在输入是三种事实。“用户活跃”的判断规则与锁屏责任归属尚未确定。

当前应用和标题可以保留在采集器内存中，无需保存每次采样。历史观测引用的内容必须保持为观测发生时的内容，不得引用被反复覆盖的当前数据。结束时间未知不证明状态仍在持续。

## 应用身份

应用身份分为本机应用实体和跨平台应用实体。观测内容保存当时读到的事实，观测时间由 Observation 保存。

| 对象 | 身份范围 |
| --- | --- |
| 本机应用实体 | 某台设备上的一个应用安装 |
| 跨平台应用实体 | 多台设备或多个平台上的同一个软件 |

两台 Mac 上的 VS Code 分别拥有本机应用实体。确认两个安装属于同一个软件后，可以将两个实体关联到同一个跨平台应用实体。即使平台相同，设备上的安装也分别保留身份。

Observer 维护本机应用身份，不负责判断其他平台的软件身份。跨平台关联可以在采集后建立。没有跨平台关联时，本机应用实体与观测仍可保存。

`identifiers` 属于本机应用实体，保存本平台取得的应用标识线索。观测内容与本机应用实体分别保存。应用观测使用 `localApplicationId` 引用本机应用实体，`name` 保留当时读到的名称，未取得名称时为 `null`。本机身份识别规则见[本机应用](../observers/entities/local-application.mdx)。

本机应用实体的身份独立于 Observer 实例身份。本机应用实体表示应用安装，Observer 实体表示形成观测的主体。

## 前台状态实例

前台状态 Observer 形成前台应用和窗口标题两类观测。同一实例共用 `ObserverId`，两类观测分别使用自己的定义和时间线。标题变化不改变应用的前台状态，标题读取失败时仍可形成应用观测。

本地身份文件是前台状态实例身份映射的权威来源。文件只保存 `ObserverId`。同一实例多次采集、重启或升级时，程序沿用原 ID。独立实例使用自己的身份文件。如果文件损坏，程序报告错误并保留原文件。实体内容以[后端存储](./0004-entity-storage-authority.mdx)为权威。

当前实现是独立的 .NET macOS 命令行程序。程序读取前台应用、识别本机应用身份、形成时段、提交实体并核对读回结果。相同内容的连续读数延长原时段；中断后重新开始。

本机应用登记文件是应用身份映射的权威来源。多个采集器实例可以共享登记文件。后台保存实体内容，本地文件保存下次采集所需的身份映射。识别规则、提交边界与中断处理见 [ADR 0012](./0012-foreground-application-periods.mdx)。

标题、输入事件、独立设备状态时间线和锁屏规则逐项确定。多个 Observer 的共用需求明确后，再设计运行时宿主和插件机制。

观测规则见[前台状态](../observers/foreground-state.mdx)、[输入事件](../observers/input-events.mdx)与[设备状态](../observers/device-state.mdx)。启动参数、文件路径和退出码见采集程序 README。
