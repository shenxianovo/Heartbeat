## 主体与客户端

Observer 按形成观测的责任划分。ObservationSchema 定义事实含义；Observer 依据证据形成观测，并对判断负责。API、数据源、输出类型和进程划分不直接决定主体身份。

一个 Observer 可以使用多份 ObservationSchema。各类观测分别保存具体数据和事实时间。跨平台实现的数据结构、约束、事实含义和时间规则一致时，可以共用同一份定义。

前台应用单次读数共用一份平台无关的定义，表达“在时刻 t 读到应用 A 位于前台”。平台名称和系统读取方式属于具体实现说明；新增平台本身不要求新的 SchemaId。各平台保留字段原义，没有字段值时保存为 `null`。去掉定义名称和说明中的 macOS 与系统 API 信息不改变字段、约束或时间点含义，继续沿用已有定义 ID。

内部模块只提供证据时，由所属 Observer 形成观测。模块独立形成观测时，观测引用该模块对应的主体身份。

平台客户端组合并运行 Observer，多个 Observer 可以共处同一进程。客户端只组合或传输已有观测时，必须保留原 `ObserverId`。主体形成新的聚合观测时，使用自己的身份；聚合数据保存具体实例引用，ObservationSchema 定义引用字段。

## 桌面观测职责

桌面观测由三个 Observer 分别负责，可以运行在同一程序中：

| Observer | 负责的事实 |
| --- | --- |
| 前台状态 | 前台应用时段和窗口标题时段，分别使用自己的定义与时间线 |
| 输入事件 | 键盘和鼠标事件发生的时间点 |
| 设备状态 | 设备休眠和唤醒状态的时间段 |

应用使用先表示前台时长。设备清醒、会话未锁定和近期存在输入分别表达不同事实，“用户活跃”的判断规则与锁屏归属尚未确定。

当前应用和标题可以保留在采集器内存中，无需保存每次采样。历史观测引用的数据保留当时内容，不能引用被反复覆盖的当前数据；结束时间未知不证明状态仍在持续。

## 前台状态实例

前台状态 Observer 形成前台应用和窗口标题两类观测。同一实例共用 `ObserverId`，两类观测分别使用自己的定义和时间线。标题变化不改变应用的前台状态，标题读取失败时仍可形成应用观测。

本地身份文件是前台状态实例身份映射的权威来源，只保存 `ObserverId`。同一实例多次采集、重启或升级时沿用原 ID；独立实例使用自己的身份文件。文件损坏时报告错误并保留原文件，避免静默更换主体身份。实体内容以[后端存储](./0004-entity-storage-authority.mdx)为权威。

当前实现是独立的 .NET macOS 命令行程序，只采集一次前台应用读数。程序负责系统读取、实体创建、HTTP 提交和读回核对，完成后退出。每次读取创建独立快照，所有实例共用程序内置的观测定义。

一次采集分别保存四个实体，失败时保留已成功保存的实体，不跨实体回滚。程序不自动重试，也不使用离线队列。重试已有读数时必须沿用原实体 ID、内容和事实时间。

应用时段从第一次确认应用在前台时开始，确认切换时结束。休眠、停止采集或读取失败时，在最后一次确认的位置断开；恢复后新开一段，中间空白不计入前台时长。是否排除锁屏或无输入时段留给后续分析规则。具体规则见[前台应用时段](../observers/foreground-state.mdx#前台应用时段)。当前单次读数定义保持时间点含义；后续应用时段使用自己的定义和 ID。

应用时段的 Data 保存应用原始信息，起止时间只放在 Observation 中，跨平台数据结构草案见[前台应用时段](../observers/schemas/foreground-application-interval.mdx)。连续采集未中断且完整数据相同时，延长同一段；数据变化则新开一段，每段引用的数据保持一致。把不同名称或安装路径归为同一软件，由后续查询规则处理。

跨平台草案的字段约束与列表相等规则、采样间隔、采集停顿处理与固定 SchemaId 尚需确认。标题、输入事件、设备状态和锁屏的具体规则随后确认。运行时宿主和插件机制留待多个 Observer 的共用需求确认后设计。

观测规则见[前台状态](../observers/foreground-state.mdx)、[输入事件](../observers/input-events.mdx)与[设备状态](../observers/device-state.mdx)。四份目标 Schema 的草案见 [Observers 概览](../observers/index.mdx#目标与职责)，当前应用读数契约见[当前单次读数](../observers/foreground-state.mdx#当前单次读数)。身份文件路径、参数和失败处理见采集程序 README。
