## 本地环境

Aspire AppHost 是本地服务配置、依赖关系和启动顺序的唯一来源。Aspire CLI 与看板管理环境生命周期。`Heartbeat.Dev` 负责验证和保存证据。职责见 [ADR 0008](./0008-aspire-local-development.mdx)。

## 验证与证据

开发工具组织构建、测试、质量扫描和证据保存。构建失败、测试失败或扫描未完成时，验证失败。复杂度、重复代码、疑似未使用代码和依赖的扫描结果供审查，不直接使验证失败。

扫描覆盖业务实现、文档站和开发工具。测试重复与代码行数单独统计。每次运行都在独立目录保存清单、结果和日志，包括成功、失败和取消的运行。维护者通过这些文件核对实际执行范围。

## 测试 Case

文档站 `testing/` 中的独立 Case 文档是验证目的、前置条件、操作和预期结果的权威位置。Case 定义稳定 ID；测试以 TUnit 自定义属性 `caseId` 引用该 ID，关联不依赖方法名。一个 Case 可以对应多个参数化执行结果。

文档站负责 Case 路由与原生报告的关联，只展示最新报告中属性精确匹配的结果。Case 结果统计仅涵盖匹配的执行结果，不沿用全报告统计。无报告和最新报告没有匹配结果均不能表示通过；正文始终可阅读。报告提供时间或代码版本时如实展示，不补造代码版本。

## 测试报告

测试执行项目生成的 `TestResults/*.tunit-report.json` 是测试结果的权威来源，报告不写入实体数据库。文档站读取文件并展示结果，查看报告不运行测试。

`fumadocs-test-reports` 校验 TUnit 原始结构并提供报告交互。文档站负责文件读取、页面路由和语言选择。Docker 只读挂载报告目录，更新报告无需重建文档站镜像。

开发命令和证据保留规则见 `tools/Heartbeat.Dev/README.md`。报告页面与文件读取规则见 [Heartbeat Testing](../testing/index.mdx#报告)和文档站 README。
