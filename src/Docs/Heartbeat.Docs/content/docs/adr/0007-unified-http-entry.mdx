---
title: "0007 HTTP 入口与应用分流"
---

业务前端和文档站分别运行。NGINX 按端口提供业务/API 入口和文档入口。文档入口同时转发实体 API 请求，使 Playground 与 API 使用同一来源。

| 本地端口与路径 | 接收组件 | 转发规则 |
| --- | --- | --- |
| `8080/api/…` | API | 去掉 `/api` 前缀 |
| `3000/api/entities/…` | API | 去掉 `/api` 前缀 |
| `3000` 的其他路径 | 文档站 | 保留完整路径，文档站按根路径运行 |

8080 的其他路径暂时返回 `404`。业务前端实现后，由前端接收该入口的根路径。

文档站不配置 Next.js `basePath`。接口文档 `/api/…`、搜索 `/api/search`、页面、资源和导出均使用根路径。文档端口仅将 `/api/entities/…` 转给后端，使接口文档与请求入口各自得到正确处理。

API 负责在生成的 OpenAPI 中声明相对服务地址 `/api`。文档站读取该声明，Playground 将服务地址与接口路径组合，向当前站点发送请求。

NGINX 使用 `nginx:1.30.5-alpine`，配置位于 `docker/nginx/default.conf`。运行模式和开发模式共用配置，代理支持开发服务器的 WebSocket 连接。两个 HTTP 端口均绑定 `127.0.0.1`；API 和文档站只在容器网络内访问，PostgreSQL 保留本地 `127.0.0.1:54329` 入口。

NGINX 通过 Docker DNS 动态解析 API 和文档站地址，解析结果缓存 30 秒。服务重建后，NGINX 重新解析地址。两个上游各保留最多 16 条空闲连接供每个工作进程复用；代理连接超时为 5 秒，读写间隔超时为 60 秒。

NGINX 与 API 的请求体上限均为 10 MiB（10,485,760 字节）。网关或 API 拒绝超限请求时，返回 `413` 和 `application/problem+json` 错误。NGINX 在转发前检查请求体，API 同样检查直连请求。
