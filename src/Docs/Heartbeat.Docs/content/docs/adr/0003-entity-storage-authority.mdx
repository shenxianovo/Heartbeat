---
title: "0003 统一索引定位实体的权威存储"
---

实体索引和内容使用 PostgreSQL 存储。实体存储使用统一索引、通用 JSON 存储和专用表。每个实体必须只有一份权威内容。后端根据标识查询统一索引，再从索引指向的位置读取内容。

PostgreSQL 版本选用最新稳定发布。整个服务使用 Docker 打包运行。

后端使用 .NET 10 的最新稳定维护版本，数据访问采用 EF Core 和 Npgsql PostgreSQL Provider。EF Core 管理表映射、Initial migration 和常规读写，Npgsql 负责连接 PostgreSQL。重写期间直接修改 Initial migration 和模型快照。

实体标识和引用使用 `uuid`，文本使用 `text`，通用实体内容和观测定义使用 `jsonb`，时间边界使用 `timestamptz`。系统使用微秒精度存储和读取时间。

后端未识别的领域数据使用通用 JSON 存储。结构稳定且有明确查询需求的类型可以直接使用专用表，也可以从通用存储转入专用表。

如果实体转入专用表，后端必须保留原实体标识，并更新索引中的 `table_name`。专用表成为该实体的权威存储，已有引用继续有效。存储变化不改变实体身份。

数据库表名和列名使用 `snake_case`。统一索引保存 `id` 和 `table_name`。后端根据存储表映射模型类别，用于读取响应和已有实体的模型类别校验。

后端保存一个实体时，必须在同一事务中写入统一索引和实体内容。两者必须同时成功或同时失败，避免索引与内容不一致。写入失败时，事务回滚。

五张表都以 `id` 为主键。内容表的 `id` 通过外键引用 `entities.id`。后端事务逻辑负责表名匹配和跨表只有一份权威内容。

四张内容表到统一索引的外键使用 `ON DELETE CASCADE`。索引和内容共同表示一个实体，删除统一索引行时自动删除同 ID 的内容行。

观测的三个实体引用不建立数据库外键，以允许被引用实体稍后入库。两张带时间边界的表使用 `CHECK (start_at <= end_at)`，禁止已知的开始时间晚于结束时间。

表名、索引字段和类别映射见 [Heartbeat Storage](../storage/index.mdx)。
