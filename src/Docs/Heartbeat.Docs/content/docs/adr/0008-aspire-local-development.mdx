title: "0008 Aspire 本地开发编排"
---

Aspire AppHost 是本地资源配置、依赖关系和启动顺序的唯一来源，替代手写 Compose。API 与文档站使用本机进程，数据库与 NGINX 使用容器，以便直接调试和热更新，同时保留 [ADR 0006](./0006-unified-http-entry.mdx) 的 HTTP 入口。

数据库就绪后，AppHost 启动独立迁移资源。迁移成功后，AppHost 启动 API。API 本身不应用迁移。NGINX 的上游地址由 AppHost 注入，入口仍为 API 的 8080 和文档站的 3000。看板独立运行，显示资源状态、控制台日志，以及 API 导出的结构化日志、调用链和指标。

环境启动、停止、日志和资源操作由 Aspire CLI 与看板负责。Heartbeat.Dev 负责构建、测试、质量观察和验证证据，不提供 env 命令及本地 --release 运行模式。数据库使用命名卷，停止开发环境保留数据。

Dockerfile、代理模板和数据库初始化脚本继续保留。Aspire 仅用于开发。将来部署使用 Docker 镜像与 Docker Compose，不运行 Aspire AppHost。当前不建设 Compose 部署配置、服务器发布流程或生产监控栈。

本地看板允许匿名访问，无需登录令牌。看板使用 HTTPS，仅监听本机并接受 `localhost` 主机名。此配置用于本地开发。

## 应用遥测

API 启动层负责组装 OpenTelemetry，应用日志沿用标准 `ILogger`。追踪覆盖入站 HTTP 与现有 Npgsql 调用，指标覆盖 HTTP 与 .NET 运行时；不扩展浏览器、NGINX 或 PostgreSQL 服务自身的遥测。

AppHost 负责在开发环境提供 OTLP 接收地址和连接配置。API 只有在 `OTEL_EXPORTER_OTLP_ENDPOINT` 是包含主机名的有效 HTTP/HTTPS 绝对地址时才注册遥测提供者并导出三类数据；未配置或地址无效时保留原有控制台日志，不尝试默认本机 OTLP 接收端。因此 API 可脱离 Aspire 独立运行。

遥测不采集请求体，不启用数据库参数值或 EF Core 敏感数据日志。数据库追踪使用现有 Npgsql 活动源，保留参数化 SQL 与 HTTP 请求的父子关系。

运行方式见仓库中的 `tools/Heartbeat.AppHost/README.md`。
