# Orisumi Feature Map

本页用于选择验证入口。行为以链接的长期文档为准。表中的 `orisumi` 是 Orisumi.Dev 的命令，安装见 [Orisumi.Dev README · 安装](../../../../../tools/Orisumi.Dev/README.md#安装)。

| 能力 | 用户入口 | 验证入口 | 权威文档 | 证据限制 |
| --- | --- | --- | --- | --- |
| 模型规则 | `dotnet test --project tests/Orisumi.Model.Tests/Orisumi.Model.Tests.csproj` | `orisumi verify checks --scope all`、变更选择的 `model-tests` | [测试分工](../../../../../src/Docs/Orisumi.Docs/content/docs/testing/index.mdx) | Core 与 Application 的规则，存储为内存实现；不覆盖 HTTP、数据库和 Observer 运行 |
| 实体 API 与存储 | `orisumi env up api` 后 <http://localhost:8080/api>；文档站接口页的 Playground | `orisumi verify checks` 中的集成测试（独立 PostgreSQL）；`orisumi verify scenarios api` | [API](../../../../../src/Docs/Orisumi.Docs/content/docs/api/index.mdx)、[Storage](../../../../../src/Docs/Orisumi.Docs/content/docs/storage/index.mdx)、[API README](../../../../../src/Backend/Orisumi.Api/README.md) | `verify scenarios api` 只覆盖提交、读取和拒绝；吞吐只在本机测过 |
| Runtime、.NET SDK 与前台状态 Observer（macOS） | Runtime：`Orisumi.Observer.Runtime --data-dir <目录> --backend <API>/api/ --bundled <安装包目录> [--catalog <URL>]`，标准输入输出是客户端管道；开发时加 `--run foreground-state` 在命令行运行一个已安装的 Observer，Ctrl+C 退出 | `orisumi verify checks` 中的集成测试；另在 macOS 按[运行说明 · 验证](../../../../../src/Observers/Orisumi.Observer.ForegroundState/README.md#验证)对临时环境实际运行 | [Submission](../../../../../src/Docs/Orisumi.Docs/content/docs/observers/submission/index.mdx)、[Clients · Runtime](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/runtime.mdx)、[Packages](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/packages.mdx)、[Foreground State](../../../../../src/Docs/Orisumi.Docs/content/docs/observers/foreground-state/index.mdx)、[SDK README](../../../../../src/Observers/Orisumi.Observer.Sdk/README.md)、[运行说明](../../../../../src/Observers/Orisumi.Observer.ForegroundState/README.md) | 自动测试不调用 macOS 原生接口；真实休眠和长时间断网需另测；未覆盖的预期列在各 Case 页 |
| 应用识别 Observer | 随 API 运行，`orisumi env up` 启动 `api` 即包含它；Key、型号和间隔见[程序 README · 运行](../../../../../src/Observers/Orisumi.Observer.ApplicationIdentity/README.md#运行)；`orisumi env logs api` 读诊断 | `orisumi verify checks` 中的集成测试：`ApplicationIdentityTests`（模型替身、独立 PostgreSQL；保存中断用故障注入模拟；轮次调度运行真实的服务端托管）和 `ApplicationModelTests`（HTTP 替身）；`orisumi verify scenarios api` 检查 API 启动；真实的 OpenAI 调用在临时环境中单独运行并保存结果 | [Application Identity](../../../../../src/Docs/Orisumi.Docs/content/docs/observers/application-identity/index.mdx)、[ADR · 应用识别](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/application-identity.mdx)、[ADR · 服务端托管](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/server-observer-hosting.mdx)、[程序 README](../../../../../src/Observers/Orisumi.Observer.ApplicationIdentity/README.md) | 自动测试不调用 OpenAI，模型判断的质量要看真实调用的结果；没有杀掉操作系统进程；只覆盖一个 API 副本 |
| macOS 客户端 | `orisumi mac build [--configuration debug\|release]`、`orisumi mac run [--configuration debug\|release] [--build] [--window]`、`orisumi mac stop`；连接本检出目录的环境，每个数据卷一个 Runtime 数据目录（`.artifacts/mac/instances/<卷名>`）；窗口侧栏管理 Observer，“添加 Observer”安装 | `orisumi verify checks`（macOS 上包括 `swift test` 和 Debug 构建）；另按[客户端 README · 验证](../../../../../src/Clients/Orisumi.Mac/README.md#验证)实际运行，浅色和深色都看 | [ADR · 设备端客户端](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/device-client.mdx)、[Clients · macOS](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/macos.mdx)、[Clients · Runtime](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/runtime.mdx)、[客户端 README](../../../../../src/Clients/Orisumi.Mac/README.md)、[Orisumi.Dev README · macOS 客户端](../../../../../tools/Orisumi.Dev/README.md#macos-客户端) | 单元测试不启动真实 Runtime；`RuntimeIntegrationTests` 不经过界面；菜单、窗口和悬停需要实际运行 |
| 文档站 | `orisumi env up docs`，或者文档目录 `pnpm dev`；文档端口的 `/core`、`/observers`、`/clients`、`/api`、`/storage`、`/testing`、`/adr`；公开站点 <https://docs.orisumi.dev> | 文档目录 `pnpm docs:check`、`pnpm test`、`pnpm types:check`、`pnpm build`（含静态导出检查）；实际页面、搜索、导出与资源链接；发布由 `.github/workflows/docs.yml` 完成，发布后按[文档站 README · 发布](../../../../../src/Docs/Orisumi.Docs/README.md#发布)检查公开站点 | [文档站 README](../../../../../src/Docs/Orisumi.Docs/README.md)、[ADR · 设计层与变更流程](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/documentation-authority.mdx)、[ADR · 文档站的发布](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/documentation-publishing.mdx)、仓库根目录的 [AGENTS.md](../../../../../AGENTS.md) | 导出问题以 `pnpm build` 为准；公开站点对应最近一次成功发布的提交 |
| 文档引用图 | 文档站 Start 分区的 `/start/graph` | 文档站检查与 `build-graph.test.ts`；实际检查节点跳转、缩放、适应画布、页面列表及 Markdown 导出中的引用清单 | [Graph](../../../../../src/Docs/Orisumi.Docs/content/docs/start/graph.mdx)、[文档站 README · Graph](../../../../../src/Docs/Orisumi.Docs/README.md#graph) | 图只包含 `graphSections` 选定分区的页面链接，章节归到页面 |
| Web 控制台（独立 SPA） | `orisumi env up web` 后的统一入口 <http://localhost:8081>；或者 `src/Clients/Orisumi.Web` 目录 `npm run dev`（5173，`/api` 代理到 8080）；路由 `/?date=`、`/entities?type=`、`/entities/$entityId`、`/observers?view=bubble\|strip\|ring&observer=`、`/applications`、`/versions/$versionId`，任何页面可带 `stack=` | `orisumi verify checks --scope all` 或变更选择的 `frontend-verify`，即目录内 `npm run verify`（typecheck + eslint --max-warnings=0 + prettier --check + vitest + vite build）；`npm run test:e2e` 跑 Playwright（首次 `npx playwright install chromium`），用路由拦截代替后端，检查外壳和日页面、Observer 页面的空状态；`orisumi env up web` 后另跑 `npm run test:e2e:edge`，检查边缘转发、同源 /api、HMR，并用真实数据检查 Observer 页面的三种视图、日页面的排行、两层面板、Esc 和类型图；页面或交互变更另实际检查页面，浅色和深色、两种基调都看 | [Web](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/web.mdx)、[API](../../../../../src/Docs/Orisumi.Docs/content/docs/api/index.mdx)、[前端 README](../../../../../src/Clients/Orisumi.Web/README.md) | 视图、面板和实体页只在 edge 用例中用真实数据检查，edge 用例会写入并删除测试实体；角色和类型之间的引用都来自样本，同一类型的实体结构不一致时，类型图只反映样本 |
| 测试 Case 与报告 | `/testing/observers/foreground-submission`、`/testing/reports/integration` | 文档目录 `pnpm test`、类型检查与构建；实际 Case 正文、结果关联、多参数结果、无匹配结果、报告搜索、筛选、详情和无报告状态 | [ADR · 开发验证与测试证据](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/verification.mdx)、[文档站 README](../../../../../src/Docs/Orisumi.Docs/README.md) | 展示真实 TUnit JSON；页面不执行测试；公开站点的报告是发布时运行集成测试生成的 |
| 本地环境 | `orisumi env up/down/status/logs/otel/restart/volumes` 和看板；表结构与迁移不一致时 `orisumi env up --reset` 重建默认卷 | 工具测试；`orisumi verify scenarios environment` 验证转发、部分启动、迁移失败、停止与数据保留；临时卷环境中检查 Playground、热更新和页面 | [Orisumi.Dev README · 环境](../../../../../tools/Orisumi.Dev/README.md#环境)、[AppHost README](../../../../../tools/Orisumi.AppHost/README.md)、[ADR · 开发环境的启动与隔离](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/development-environment.mdx)、[ADR · 后端运行与本地环境 · 本地环境](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/backend-runtime.mdx#local-environment)、[ADR · 后端运行与本地环境 · HTTP 入口](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/backend-runtime.mdx#http-entry) | 本地验证不证明部署环境 |
| API 遥测 | API 启动时的 `OTEL_EXPORTER_OTLP_ENDPOINT` 与开发看板 `api` | `TelemetryTests`；`orisumi env up api --temp` 后用 `orisumi env telemetry` 和看板读取结构化日志、HTTP/数据库追踪和 HTTP/.NET 指标；无 OTLP 配置的独立运行 | [ADR · 后端运行与本地环境 · 遥测](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/backend-runtime.mdx#telemetry)、[API README](../../../../../src/Backend/Orisumi.Api/README.md#遥测)、[AppHost 验证](../../../../../tools/Orisumi.AppHost/README.md#api-遥测验证) | 只覆盖 API 遥测，不覆盖生产监控、浏览器或容器自身遥测 |
