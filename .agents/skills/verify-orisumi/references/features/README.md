# Orisumi Feature Map

本页用于选择验证入口。行为以链接的长期文档为准。表中的 `orisumi` 是 Orisumi.Dev 的命令，安装见 [Orisumi.Dev README · 安装](../../../../../tools/Orisumi.Dev/README.md#安装)。

| 能力 | 用户入口 | 验证入口 | 权威文档 | 证据限制 |
| --- | --- | --- | --- | --- |
| 模型规则 | `dotnet test --project tests/Orisumi.Model.Tests/Orisumi.Model.Tests.csproj` | `orisumi verify checks --scope all`、变更选择的 `model-tests` | [测试分工](../../../../../src/Docs/Orisumi.Docs/content/docs/testing/index.mdx) | Core 与 Application 的规则，存储为内存实现；不覆盖 HTTP、数据库和 Observer 运行 |
| 实体 API 与存储 | `orisumi env up api` 后 <http://localhost:8080/api>；文档站接口页的 Playground | `orisumi verify checks --scope all` 或变更选择的 `integration-tests`（`EntityApiTests`、`ReferrerApiTests`，独立 PostgreSQL）；`orisumi verify scenarios api` | [API](../../../../../src/Docs/Orisumi.Docs/content/docs/api/index.mdx)、[Storage](../../../../../src/Docs/Orisumi.Docs/content/docs/storage/index.mdx)、[API README](../../../../../src/Backend/Orisumi.Api/README.md) | 集成测试覆盖全部接口，包括列出引用方、部分拒绝、时间查询与多实例冲突；`orisumi verify scenarios api` 只覆盖提交、读取和拒绝；吞吐只在本机测过 |
| Runtime、.NET SDK 与前台状态 Observer（macOS） | Runtime：`Orisumi.Observer.Runtime --data-dir <目录> --backend <API>/api/ --bundled <安装包目录> [--catalog <URL>]`，标准输入输出是客户端管道；开发时加 `--run foreground-state` 在命令行运行一个已安装的 Observer，Ctrl+C 退出 | `orisumi verify checks --scope all` 或变更验证（`ObserverSdkTests` 等，及 Runtime 的协议、安装、生命周期测试）；另在 macOS 对 `orisumi env up api --temp` 的环境用临时数据目录实际运行，用 API 读回已结束的时段；Observer 场景加入后用 `orisumi verify scenarios` | [Submission](../../../../../src/Docs/Orisumi.Docs/content/docs/observers/submission/index.mdx)、[Clients · Runtime](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/runtime.mdx)、[Packages](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/packages.mdx)、[Foreground State](../../../../../src/Docs/Orisumi.Docs/content/docs/observers/foreground-state/index.mdx)、[SDK README](../../../../../src/Observers/Orisumi.Observer.Sdk/README.md)、[运行说明](../../../../../src/Observers/Orisumi.Observer.ForegroundState/README.md) | 自动测试覆盖草稿与恢复、重试与拆批、部分拒绝、Schema 登记、上传和本机应用被删除后的恢复，不调用 macOS 原生接口；Runtime 的 Case 见 Testing 的 Clients 分组，未实现的预期标为未覆盖；真实休眠、长时间断网需另测 |
| macOS 客户端 | `orisumi mac build [--configuration debug\|release]`、`orisumi mac run [--configuration debug\|release] [--build] [--window]`、`orisumi mac stop`；连接本检出目录的环境，每个数据卷一个 Runtime 数据目录（`.artifacts/mac/instances/<卷名>`）；窗口侧栏管理 Observer，“添加 Observer”安装 | `orisumi verify checks --scope all`（macOS）或变更选择的 `mac-test`（`swift test`）和 `mac-build`（`xcodebuild` Debug）；另用 `orisumi env up api web --temp` 和 `orisumi mac run --window` 实际运行：切换应用、停用再启用、卸载再重装、让 Observer 崩溃看重启、退出后重启、断开 API 后恢复，再在窗口和 Web 控制台读回时段；菜单、侧栏、详情、悬停和设置实际检查，浅色和深色都看 | [ADR · 设备端客户端](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/device-client.mdx)、[Clients · macOS](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/macos.mdx)、[Clients · Runtime](../../../../../src/Docs/Orisumi.Docs/content/docs/clients/runtime.mdx)、[客户端 README](../../../../../src/Clients/Orisumi.Mac/README.md)、[Orisumi.Dev README · macOS 客户端](../../../../../tools/Orisumi.Dev/README.md#macos-客户端) | 单元测试用 shell 脚本代替 Runtime、用替身代替管道响应；`RuntimeIntegrationTests` 在设置 `ORISUMI_APP` 时驱动真实 Runtime 和 API，不经过界面；菜单和窗口的点击需要实际运行；悬停效果无法用合成事件触发，需人工检查 |
| 文档站 | `orisumi env up docs`，或者文档目录 `pnpm dev`；文档端口的 `/core`、`/observers`、`/clients`、`/api`、`/storage`、`/testing`、`/adr`；公开站点 <https://docs.orisumi.dev> | 文档目录 `pnpm docs:check`、`pnpm test`、`pnpm types:check`、`pnpm build`（含静态导出检查）；实际页面、搜索、导出与资源链接；发布由 `.github/workflows/docs.yml` 完成，发布后按[文档站 README · 发布](../../../../../src/Docs/Orisumi.Docs/README.md#发布)检查公开站点 | [文档站 README](../../../../../src/Docs/Orisumi.Docs/README.md)、[ADR · 设计层与变更流程](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/documentation-authority.mdx)、[ADR · 文档站的发布](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/documentation-publishing.mdx)、仓库根目录的 [AGENTS.md](../../../../../AGENTS.md) | 页面检查只证明所检查的页面和交互；开发服务器不按静态导出检查，导出问题以 `pnpm build` 为准；公开站点对应最近一次成功发布的提交 |
| 文档引用图 | 文档站 Start 分区的 `/start/graph` | 文档站检查与 `build-graph.test.ts`；实际检查节点跳转、缩放、适应画布、页面列表及 Markdown 导出中的引用清单 | [Graph](../../../../../src/Docs/Orisumi.Docs/content/docs/start/graph.mdx)、[文档站 README · Graph](../../../../../src/Docs/Orisumi.Docs/README.md#graph) | 图只包含 `graphSections` 选定分区的页面链接，章节归到页面 |
| Web 控制台（独立 SPA） | `src/Clients/Orisumi.Web` 目录 `npm run dev`（5173，`/api` 代理到 8080，`?source=demo` 用演示数据）；`orisumi env up web` 后的统一入口 <http://localhost:8081>；路由 `/?view=ecg\|bubble\|strip\|ring&observer=`、`/entities/$entityId`、`/versions/$versionId`、`/schemas` | `orisumi verify checks --scope all` 或变更选择的 `frontend-verify`，即目录内 `npm run verify`（typecheck + eslint --max-warnings=0 + prettier --check + vitest + vite build）；`npm run test:e2e` 用演示数据源跑 Playwright（首次 `npx playwright install chromium`）；`orisumi env up web` 后另跑 `npm run test:e2e:edge`，检查边缘转发、同源 /api、HMR，并提交真实数据检查四种视图和实体页；页面或交互变更另实际检查页面，浅色和深色都看 | [API](../../../../../src/Docs/Orisumi.Docs/content/docs/api/index.mdx)、[前端 README](../../../../../src/Clients/Orisumi.Web/README.md) | 默认 e2e 不连后端，演示数据每次加载重新生成；edge 用例依赖运行中的 Web 控制台和 API，会写入并删除测试实体；写入靠 2 秒轮询发现，事实时间远离今天的补发不在“现在”出现 |
| 测试 Case 与报告 | `/testing/observers/foreground-submission`、`/testing/reports/integration` | 文档目录 `pnpm test`、类型检查与构建；实际 Case 正文、结果关联、多参数结果、无匹配结果、报告搜索、筛选、详情和无报告状态 | [ADR · 开发验证与测试证据](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/verification.mdx)、[文档站 README](../../../../../src/Docs/Orisumi.Docs/README.md) | 展示真实 TUnit JSON；页面不执行测试；公开站点的报告是发布时运行集成测试生成的 |
| 本地环境 | `orisumi env up/down/status/logs/otel/restart/volumes` 和看板；表结构与迁移不一致时 `orisumi env up --reset` 重建默认卷 | 工具测试；`orisumi verify scenarios environment` 验证转发、部分启动、迁移失败、停止与数据保留；临时卷环境中检查 Playground、热更新和页面 | [Orisumi.Dev README · 环境](../../../../../tools/Orisumi.Dev/README.md#环境)、[AppHost README](../../../../../tools/Orisumi.AppHost/README.md)、[ADR · 开发环境的启动与隔离](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/development-environment.mdx)、[ADR · 后端运行与本地环境 · 本地环境](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/backend-runtime.mdx#local-environment)、[ADR · 后端运行与本地环境 · HTTP 入口](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/backend-runtime.mdx#http-entry) | 本地验证不证明部署环境；停止保留数据库卷；API 三类 OTLP 遥测需实际读取看板或遥测 API |
| API 遥测 | API 启动时的 `OTEL_EXPORTER_OTLP_ENDPOINT` 与开发看板 `api` | `TelemetryTests`；`orisumi env up api --temp` 后用 `orisumi env telemetry` 和看板读取结构化日志、HTTP/数据库追踪和 HTTP/.NET 指标；无 OTLP 配置的独立运行 | [ADR · 后端运行与本地环境 · 遥测](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/backend-runtime.mdx#telemetry)、[API README](../../../../../src/Backend/Orisumi.Api/README.md#遥测)、[AppHost 验证](../../../../../tools/Orisumi.AppHost/README.md#api-遥测验证) | 只覆盖 API 遥测，不覆盖生产监控、浏览器或容器自身遥测 |
| 开发验证 | `orisumi verify checks [--scope changed\|all] [--quality]`、`orisumi verify scenarios` | `--plan` 核对选择和场景前提；执行后检查清单、结果和日志；失败、取消和场景跳过的边界测试 | [工具 README](../../../../../tools/Orisumi.Dev/README.md)、[ADR · 开发验证与测试证据](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/verification.mdx) | 运行时行为由场景检查；热更新与页面检查另行选择 |
| 质量与规模 | `orisumi analyze quality --base REF`、`orisumi analyze loc` | 分类与发现解析测试；真实扫描；可编译隔离基线验证变化比较 | [工具 README](../../../../../tools/Orisumi.Dev/README.md)、[ADR · 开发验证与测试证据](../../../../../src/Docs/Orisumi.Docs/content/docs/adr/verification.mdx) | 发现供审查；扫描失败仍失败；历史编译失败不能称为比较通过 |
