## 当前决定汇总

- 新活动页面在独立路由，与现有 Dashboard 并存，以当天经历为目标。
- 按 Subject 分组，独立活动并列可见，隐藏选中时间范围内无活动的组。
- System 为机器前台主线，Browser 是可展开的相关观察，VRChat Account 有独立展示。
- 不合并原始 Segment，不用候选 Browser 页面替代确定的前台事实。
- 开发者提供前端 Fact View，随 Dashboard 发布；同一事实允许多种视图。
- 当前默认布局同时显示泳道和记录列表，保留内容展开/隐藏；不设两者切换开关，无拖拽编辑器或动态展示代码加载。
- 未支持的来源显示记录提示与少量默认收起的 Payload JSON 样例。
- 已有日历窗口、Owner 可见性与事实身份语义沿用；不把展示需求变成全量历史加载。
- Q6 已确认：Subject 泳道搭配逐条详情；顶部全天总览控制所选范围，支持框选、平移、调整两侧边界与时间轴缩放。
  首版反馈后删除“全局／聚焦”和加减按钮，不做固定时长切换按钮。

## 访谈开始时的实现事实

- 活动投影要求 Payload 中有非空 activityKey；任意 Fact 的保管不等于已有可视化。
- 主时间线与日/周使用排行仍围绕 system 机器活动；Browser 已有 App 详情中的展示。
- 非 system 活动 API 已返回 Subject 与完整 Payload；VRChat 的真实 Account 事实没有
  AppIdentity 关联，而 App 详情请求按 appId 过滤，因此不能靠现有入口自然访问。
- Event 当前主要投影为键鼠统计，不等于所有 Event 都应采用同一种 UI。
- Browser 当前保存每窗口 active tab 的标题、URL、domain/site、windowId，没有网页图片或
  favicon；记录不证明该窗口在操作系统前台。
- VRChat 当前保存可观测的世界名/ID、实例 ID 与区间，没有世界图片、好友或人数。
  private/offline/缺实例均可能导致无段，缺段不能标成确定离线；长停留会轮换 Fact，
  Fact 条数不能冒充访问次数。
