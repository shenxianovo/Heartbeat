# VRChat 服务器事件与本地日志的去重、互补和权威来源

Status: needs-triage

## 背景

2026-09-27 用户确认先实现服务器 Hub 可提供的 VRChat 事件采集，同时明确要求记录本地日志接入之前必须认真设计的问题。本轮不接入日志，不提前添加兼容层或合并机制。

## 待决问题

- 同一账号、同一次世界访问同时被服务器 API 与 PC/Quest 日志观测时，如何关联来源，避免时长和访问次数重复累加？
- 本地日志补足非好友、隐藏位置与更精确进出时间时，如何补充服务器观测而保留原始依据？
- 多设备、账号切换、不同时间精度和时钟偏差、同名玩家、不同实例如何匹配？
- 断线、崩溃、缺失边界或互相矛盾时，采用哪个来源，如何展示不确定性？
- 原始 Track 保持独立，还是形成派生 Track/视图？合并规则更新如何重算，不覆盖原始记录？
- 重复导入、文件轮换/截断和重新采集如何幂等？

## 验收方向

以后用真实服务器记录与 Windows/Quest 日志对照：完整重复、部分重叠、互补、冲突、断线和重复导入。设计确认后留 ADR，再实施；不能仅靠 world ID 或时间相近自动去重。
